# `src/**` を触るときの実装規律

正本の 10 型は `CLAUDE.md` §6。ここは `src/**` を変更するときの具体的な設計・実装チェックポイント。

## 1. 同じ問いに答える場所を複数作らない

- **判定の 1 か所化**:
  - 「編集中か」「どの領域か」「どのトークンを残すか」などの判定を複数箇所に書かない。1 つの関数に寄せて export し、複数経路から同じ関数を呼ぶ。
- **複数の描画経路への伝播**:
  - 1 つの設定やコンテキストが複数の描画経路（通常の Markdown 本文 / CSV フェンス内のセル / 添付の説明文 / プレビュー / 印刷準備など）に効く場合、`grep` で読む場所をすべて洗い出し、全経路に確実に渡す。
- **ピン留め枠・別ペインでの操作対象（`lid`）**:
  - 選択中ノート（`selectedLid`）とは無関係に表示される枠（ピン留め枠・比較枠など）のボタンが、誤って `selectedLid` を書き換えないようにする（その枠自身の `lid` を対象にするか、操作を出さない）。

## 2. 読む側と書く側の対称性・直列化

- **書込と読込の追い越し防止**:
  - ストアへの非同期書込（`upsertEntry` 等）の直後に書き出しや別ウィンドウ読込が走るときは、`settled()` 等で書込完了を待ってから読む。
- **入力検証・URL ハッシュの対称性**:
  - URL ハッシュやディープリンクを読む側が `containerId` と `lid` の 2 段で検証するなら、書く側も同じ条件を満たすときだけ書き込む。
- **楽観更新と非同期 ack の世代管理**:
  - 画面を先に動かしてから非同期で保存・再読込する操作（並べ替え等）では、世代（generation）を進め、古い世代の非同期応答が後から返ってきても画面を巻き戻さないようにする。
- **読む面の最適化を編集中に被せない**:
  - スクロール中のポインタ抑止などの描画最適化は、`isEditing` 中には無効化して「保存」ボタン等の押下を妨げない。
- **外部ファイル取り込み時のサニタイズ**:
  - `.pptx` 等の外部ファイルから抽出した文字列を Markdown 記法（テーブルや見出し等）へ埋め込むときは、改行やパイプ文字を適切に畳んで記法崩れを防ぐ。

## 3. 配線とフォールバックの罠

- **通信封筒（エンベロープ）の共通化**:
  - Worker や別ウィンドウと `postMessage` で通信するときは、メッセージの組み立てと検証を共通の型・ヘルパーに寄せ、両端を実物同士で繋ぐテストを 1 本置く。
- **`?.` と `try / catch` の罠**:
  - `this.storage?.getItem(KEY)` は `storage === null` のとき例外を投げずに `undefined` を返すため、`catch` ブロックのメモリ fallback に入らない。`if (!this.storage) return this.fallback;` を明示的に先に書く。
- **不要な全量読込による競合を避ける**:
  - 題名変更など本文を必要としない操作で `getBody` → 全文書き戻しをしない。必要な列だけを触る口（`renameEntry` 等）を使って競合自体を起こらなくする。

## 4. 置き換えの作法（native → 自前 UI / 要素の変更）

- **native 機能（`confirm` / `prompt` / D&D 等）を自前 `<dialog>` 等に替えるとき**:
  - native が暗黙に保証していた **①背面のショートカット・操作の抑止 ②複数要求の直列化 ③閉じた後のフォーカス復帰 ④`Escape` キーの伝播停止（`stopImmediatePropagation` で背後のノート選択解除等を巻き込まない）** を必ず揃える。
- **DOM 要素の構造を変えるとき**:
  - ボタン内にアイコン文字を直接足すと `button.textContent` が変わり、既存のラベル参照やテストに影響する。アイコンは CSS の `::before` や `aria-hidden` 要素で扱い、読み取られるテキスト値を壊さない。
