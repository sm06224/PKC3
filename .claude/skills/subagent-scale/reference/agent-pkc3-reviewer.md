# pkc3-reviewer の詳細

本体 `pkc3-reviewer.md` から退避した経緯・実測・手順(2026-11-22 のスリム化。知見は削らずにここへ移した)。

### ④b `render()` の外で変わる値は、状態変化に乗らないので画面が古いまま残る

`binder.ts` が store を**直に**書き換える action(`appCopyHistory.clear()` のような)を
`grep` で数え上げ、その値を出している描画側が**何で更新されるか**を言えるか問う。
実例(2026-09-21):「コピーの履歴を消す」は binder が store を直に呼ぶだけで、
`showStatus` は画面下の 1 行を塗るだけなので、件数の字「いま 1 件あります。」が
消した後も画面に残った。⚠ **dispatch/state を経由しない書込みは、描画側が
購読していない限り届かない** ── store に `onChange` を足して描画側が購読する形か、
そもそも dispatch 経由にするかのどちらかを要求する。

### ⑤ tripwire は両側にあるか

上限だけの検査は**縮む方向**の事故を通す(entry chunk を 0 バイトにしても
「配る量が減った」で緑になった実績がある)。

### ⑥ コメントの嘘 / 壊れた導線

この repo は**古くなったコメントを欠陥として扱う**。数字(件数・サイズ)は実際に
数え直して突合する。⚠ `.claude/` を指す記述は、**指す先が実在するか**を確かめる。

## PKC3 固有の地雷(毎回見る)

- **層**: `core ← features ← adapter`。`core` に browser API を入れない
- **不可侵指示**(user 由来。設計の是非を論じる前に**引く**):
  - 重い処理はワーカーへ / **使い捨て**(遅延起動・ジョブのバッファ・アイドルで kill)。
    ⚠ 飛んでいるジョブがある間は kill しない / terminate 時は待ち手を必ず reject
  - 図は「描いたら焼く」── 画面は PNG の `<img>`、SVG は書き出しのときだけ。
    鍵は **原文 + テーマ + 幅 + devicePixelRatio**、bytes は IDB Blob、
    ObjectURL は**寿命終端で revoke**
  - ゼロコピー / 生成物のライフサイクル終端で即破棄
  - **配る量は気にしない。効くのは定常** ── 🔴 **「重いから入れない」を
    レビューの指摘理由にしてはならない**。size cap は手違いの検出であって
    守らせる規律ではない(引き上げ可・撤廃不可)
  - 目指す姿は「業務画面」── 色は意味にだけ(アクセント 1 色 + 状態 4 色)、区切りは背景の段差と余白、ボタンは 4 型(#1982)
- **flags は最大 15 個**、各 flag に畳む条件の宣言が要る。設定(settings)とは分離
- **CI を長くしない** ── PR gate に重い検証を足す変更は、それだけで指摘対象
- **ブラウザが 2 つある**: 手元は `/opt/pw-browsers/chromium`(フル)、CI は
  `chromium_headless_shell`。`window.print()` の `afterprint` など**実挙動が違う**。
  実ブラウザ依存の spec は両方で通した形跡があるかを見る
- **smoke は `dist/` を配信する** ── source を変えただけでは届かない
- 🔴 **折り返す帯で「塊の切れ目」を作るなら、間は**器**に持たせる**(2026-09-21、#1029 段 B)。
  ⚠ `margin-top` を**要素 1 個ずつ**に付けると、`margin` は**行の境目ではなく
  その要素**を押し下げるので、**境目が行の途中に来る幅でだけ 1 個が浮く** ──
  実測で **1440px 以上**(ふつうのノート PC の幅)で「集計」が 8px ぶら下がり、
  段数を数える既存の検査が **3 段**と読んで落ちた。
  🔑 見るのは「間が在るか」ではなく「**塊を包む器 1 つ**が間を持っているか」
  (いまは器の `border-inline-start` + `padding-inline-start`。⚠ #1054 段②-2 で
  器を行いっぱい(`flex: 1 0 100%`)にして**必ず次の行へ落とす**のはやめた ──
  絵だけのタイル 7 つは 1 行に入る)。⚠ 狭い幅でだけ試すと**通ってしまう**
  (1024〜1366px は境目がちょうど行頭に来るので正しく見える)── **幅を変えて測った形跡**を見る
- 🔴 **開いて閉じる物(メニュー・一覧)を足したら、`Escape` の行き先を全部たどる**(2026-09-25、#1054)。
  鍵は **root の聞き手が先、`document` の聞き手が後**で、`document` の中は**登録順**に回る。
  ⚠ 閉じる聞き手が `stopImmediatePropagation` しないと、**同じ 1 回の `Escape` が後ろの
  `onShortcut`(ノートを閉じる `deselect-entry`)まで届く**。⚠ 焦点が一覧の**外**
  (マウスで ▼ を押した直後は ▼ の上)に在るときだけ閉じない、という形も同じ実害になる
  (#1054 で両方あった ── 一覧は開いたまま、読んでいたノートの選択だけ外れた)
- 🔴 **長押しで何かを開くなら、指を離したときの `click` の着地点を見る**(同日)。
  長押しの直後の合成 `click` は**押し始めた要素ではなく、離した瞬間の座標**に落ちる ──
  開いたばかりの一覧がそこに重なると、**選ぶ前に先頭の項目が押される**。
  happy-dom の手撃ちの test では再現しない(実ブラウザの smoke で初めて見つかった)
