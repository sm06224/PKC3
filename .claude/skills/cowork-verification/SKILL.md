# 実ブラウザ検証を外部へ依頼する

**依頼するときは、必ず「指示プロンプト」を書く**(user 指示 2026-08-12)。
「見てほしい」だけ投げると、**こちらが必要としない情報が返り、必要な情報が返らない**。

## いつ使うか ── 手元で届かないときだけ

| 手元(`tests/smoke`)で足りる | 外部へ依頼する |
|---|---|
| DOM 契約 / CSS / キー処理 / 生成物の検品 | **実 IME**(合成 event では届かない) |
| 偽物を仕込んで通せる経路 | **実 DPR / 実 OS の修飾キー**(mac の Cmd と Ctrl) |
| 決定的に再現するもの | **人の手でしか出ない再現**(数十回の操作の果てに落ちる) |
| | **こちらの箱から到達できない配信先**(egress で塞がれている) |

⚠ 手元で書ける検査を外へ投げない ── 往復が 1 回で数時間になる。

## 🔴 骨組み(この順で書く)

### ⓪ 依頼の前に ── **配布が何段あるか数え、最後の段まで届いたか確かめる**

🔴 **「焼いた」は「届く」ではない**(2026-08-14 に踏んだ)。Office 一式は **2 段**ある:

| 段 | 何が起きるか | ⚠ 注意 |
|---|---|---|
| ① `office-wasm-build` が **PKC3 の prerelease** `lo-wasm-dev` に zip を添付 | ここまでで CI は緑になる | ⚠ **アプリからは CORS で原理的に取れない**(ACAO 0 件 / OPTIONS 405 を実測) |
| ② 展開して `build/office-wasm/make-pages-bundle.mjs` で組み、**別 repo `sm06224/office-pack` の Pages** へ deploy | ⚠ **ここを踏まないと user には 1 バイトも届かない** | ⚠ PKC3 の CI は**この段を 1 度も自動では踏まない** |

⚠ 焼いただけで「届きます」と書いて依頼し、**相手の報告で初めて古い版を見ていた**と分かった
── 往復 1 回を丸ごと捨てた。⚠ **こちらの計器は 1 つも鳴らない** ── この箱から
`sm06224.github.io` は読めない(proxy が `CONNECT tunnel failed, response 403`。2026-08-14 実測)。

🔑 **だから依頼の 1 問目を「目録の版を貼ってください」にする。** 版は
`lo-<sha12>-run<id>` なので、焼いた run の id と**字面で突き合わせられる**
(⚠ 順序は無い ── 言えるのは「同じか、違うか」だけ)。user の画面でも見える
(設定 → Office 表示)。

### ① 手順 0 ── **どのビルドを見ているかを先に確定させる**

**これが無い依頼は、返ってきた報告が使えない。** キャッシュ・IndexedDB・Service Worker の
どれかが古いと、**直したはずの症状がそのまま再現する**。

- 何を消して何を入れ直すか、**画面の言葉で**書く(「設定 → Office 表示 → 削除 → 取得」)
- 新旧を**機械的に見分ける 1 行**を渡す。⚠ 版文字列が無いなら、**新ビルドにしか無い
  シンボルの有無**で代用する(`typeof window.__lo?.HEAPU8`)
- 「旧しか取れなかった」も**報告してよい結果**だと明記する

### ② 姿勢 ── **こちらの申告を裏取りさせる**

> 「直したと書いてあるものが直っていない」可能性を優先して疑ってください。

これを書くと、**こちらの見落としが返ってくる**(実績: 2026-08-12 の #3 で、
自分が「ぴったり」と報告した窓の寸法が**外寸ではみ出していた**ことと、
自分が入れたキー処理が**別のショートカットを殺していた**ことの 2 件が出た)。

### ③ 確認点 ── **観測点をこちらが書く**

「見てください」ではなく、**コピペで走る 1 行**を渡す。今回いちばん効いた部分である。

- 何を測るか / **どの単位で**(CSS px か device px か)/ **DPR も一緒に**
- 数値は**両方**出させる(`css` と `attr`)── 片方だと DPR の取り違えが判定できない
- 🔴 **外寸と内寸を区別して書かせる**。「中身が器と同じ」と「窓が器に収まる」は別
- 頻度が要るものは「出た / 出ない」ではなく **「N 分・M 操作で K 回」**と指定する

#### 🔴 ネイティブのダイアログに答える手順を渡す(2026-08-21 に踏んだ)

⚠ **書いていなかったせいで、存在しない P0 を 1 件追わせた。**

症状の報告は「**`Delete` を押すと画面全体が固まる(2/2、2 分以上)**」だった。実際は
`window.confirm()` が開いていただけである ── JS ダイアログが開くと Chrome のレンダラは
**ネストしたメッセージループ**に入るので、CDP の `Input.dispatchKeyEvent` /
`Page.captureScreenshot` / `Runtime.evaluate` が**どれも返らない**。
🔑 **相手から見ると「無言のフリーズ」と区別が付かない**(headless なら画面にも何も出ない)。

だから依頼文に**必ず**書く:

- **破壊的な操作(削除 / 上書き / 掃除 / 強制解放)には確認ダイアログが出る。**
  どの操作にどの文言が出るかを**こちらが列挙して渡す**
- CDP を使うなら **`Page.javascriptDialogOpening` を購読し、
  `Page.handleJavaScriptDialog{accept:true}` を返す**ハンドラを**押す前に**張る
  (Playwright なら `page.once('dialog', (d) => d.accept())`)
- ⚠ **「固まった」を報告するときは、`Page.javascriptDialogOpening` が出ていたかを
  必ず併記してもらう** ── 出ていれば原因はモーダル、出ていなければ本物の停止。
  **この 1 行があるかないかで、P0 と P2 が入れ替わる**

🔑 そして**こちら側の反省**を先に済ませる:この症状は
**手元の smoke で拾えるものだった**(`dialog` を張って Delete を押す spec が 1 本も
無かった)。CLAUDE.md「自前の headless で拾える不具合を cowork に拾わせたら、
それはこちらのテスト不足」── **依頼の前に、その操作の smoke が在るか数える**。

### ④ 🚫 やらなくてよいことを名指しする

範囲を切らないと空振りする(`subagent-scale` と同じ)。

- 既に確定していること(「クリックの座標は正確」)
- 別課題として起票済みのもの(「IME は #120。確認だけ、深追い不要」)
- こちらのソースを読む作業(**実挙動だけ**見てほしいとき)

### ⑤ 報告様式を**指定する**

🔴 **1 問ごとに 8W3H を埋めてから投げる**(2026-08-14 に「質問が不明すぎる」と指摘された)。
**埋まらない欄がある問いは、こちらがまだ調べていないという合図**である ── 投げる前に調べる。

| 欄 | 書くこと | 空欄のまま投げると |
|---|---|---|
| **What** | 何を見るか(**1 つ**) | 「全体を見て」になり、返るのは感想 |
| **Where** | どの画面 / URL / 面 | 別の面を見た報告が返る |
| **When** | どの操作の直後・何分後 | 「出ませんでした」が信用できない |
| **Which** | どのビルド・端末・ブラウザ | ⓪と①の答え。無いと全判定が宙に浮く |
| **Why** | 何を疑っているか | 相手が裏取りの角度を選べない |
| **How** | 手順(**コピペで走る 1 行**まで) | 再現の失敗がこちらの落ち度になる |
| **How many / long** | 回数・時間(「N 分・M 操作で K 回」) | 「たまに出る」しか返らない |
| **How much** | 数値の単位(CSS px / device px / DPR) | 取り違えが判定できない |
| 🔴 **これで何が決まるか** | この答えで**こちらが何を決めるか** | 決まらない情報が返ってくる |

⚠ **最後の欄がいちばん効く** ── 何も決まらない問いは、そもそも投げない。

| 要素 | なぜ要るか |
|---|---|
| 冒頭に「見たビルド」欄 | ①の結果。無いと全部の判定が宙に浮く |
| **自信度表**(主張ごとに % と根拠の質) | こちらで**検算する順番**を決められる |
| 判定は **4 値**: ✅直った / ❌残っている / ⚠部分的 / — 試せなかった | 「⚠」と「—」を潰すと嘘になる |
| 🔴 **再現しなかったものも書く** | 「20 分触って 0 回」は情報である |
| 🔴 **「触っていない」を「出なかった」と書かせない** | いちばん困る混同。末尾に「未検証で残した項目」欄を要求する |
| 修正案には **層 / 確かめたこと・推測したこと / 壊れうるもの** | 下記 |
| 優先度表は**最後に 1 つだけ** | 各節に散ると読めない |

### ⑥ 🔴 過去に覆った助言を**実例として渡す**

相手を責めるためではなく、**様式を改善するため**だと書いたうえで載せる。
これを入れると、次から「確かめた / 推測した」の線が最初から引かれて返ってくる。

> 実例(2026-08-12):
> - 「ObjectURL は読み込み後に revoke できる」→ **否定**。emscripten は pthread を
>   その URL から起こす
> - 「`-sPROXY_TO_PTHREAD` で切り分ける」→ **使えない**。LO の Qt6 経路が
>   無効前提で gate されている
> - 「窓状態を仕込む」→ **正しかったが理由が違った**。効いたのは状態ビットではなく
>   明示の幾何

🔑 **3 つ目の型がいちばん大事** ── 「結論は合っているが理由が違う」は、
そのまま信じると**次に別の場所で外す**。
