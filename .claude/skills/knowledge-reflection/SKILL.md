# 教訓を `.claude` へ反映する

> **user 指示 2026-07-26(PKC2 で確立)**: 「**着地後に知見を .claude に反映してくれ。
> コレは今度からスキルやコマンド、ルール、エージェントの更新に使用する言葉です**」/
> 「**キーワードは .claude更新です**」/「**コレ自体もスキル化しておいてください**」
>
> **user 指示 2026-08-07(PKC3)**: 「**ここまでの教訓をすべてスキル、サブエージェント、
> コマンド、ルールに適切に分割細分化して残してください / この活動自体も教訓コマンドと
> して残してください**」── 本スキルと `/claude-update` がそれ。
>
> ⚠ 出典タグ付き = **不可侵**。削除・希釈・言い換えによる骨抜きを禁ずる。

## 0. いつ走るか

- **着地後**(PR が merge され main に入ってから)が既定 ── 着地前は「結局どう直したか」
  が確定しておらず、書いた内容が嘘になる
- **例外**: 実態との乖離(廃止済みの記述 / 壊れた導線 / 古い数字)は**見つけた瞬間**に直す
- **セッションを切り替える前**は必ず走らせる(引き継ぎの前段。`session-handoff` の手順 1)

## 1. 何を拾うか ── 4 種類だけ

セッションの出来事を全部書くのではない。**次に使う人の判断を変えるもの**だけ。

| 種類 | 2026-08-07 の実例 |
|---|---|
| **踏んだ罠** | 検品が「需要側の数」を見ていた / 並びの検査が行頭しか拾わなかった / `;` で畳む分岐が属性値の中でも畳んだ |
| **覆った前提** | 「紙のリンクが緑になるのは退行」→ 実測するとアプリも緑で**面が揃った**が正解 |
| **user 裁定** | 紙のリンク色は A(このまま)/ `.claude/` は GO 済み |
| **実態との乖離** | CLAUDE.md の「⏸ 裁定待ち」が嘘だった / コメントの規則数 294 が実は 301 |

## 2. 🔴 どこへ書くか ── 分割の基準

**これを間違えると、書いたのに誰も読まない。**

| 置き場 | 何を置くか | 判定 |
|---|---|---|
| **`CLAUDE.md`** | **原則**と**user 由来の指示・裁定** | 「毎回読まれる必要があるか」 |
| **`.claude/skills/*/SKILL.md`** | **手順**(その作業をするときだけ読む) | 「作業に入ってから読めば足りるか」 |
| **`.claude/agents/*.md`** | **エージェントの観点**(何を探すか) | 「投げる相手に覚えていてほしいか」 |
| **`.claude/commands/*.md`** | **導線とガードレール**(呼ぶときの注意) | 「呼ぶ瞬間に効く注意か」 |
| **コードのコメント** | **その file 固有の罠**(位置・順序・詳細度) | 「そこを触る人だけが要るか」 |

🚫 **user 由来の金言的プロンプト(不可侵指示・裁定記録・プロセス指示)は
`.claude/` へ移さない。** `CLAUDE.md` に在ることに意味がある ── 毎回読まれるのはそこ。
スキルへ移してよいのは**手順**だけ。

🔑 **同じ教訓を 2 か所に書かない。** 原則は CLAUDE.md、手順はスキル。
CLAUDE.md 側は**スキルへのポインタ**を 1 行持つ(指す先が実在するときだけ)。

## 3. 手順

1. **拾う** ── セッションを振り返り、上の 4 種類に当てはまるものを列挙する。
   ⚠ 「うまくいったこと」は拾わない。**判断を変えるもの**だけ
2. **分ける** ── 各項目を上の表で振り分ける。迷ったら「**次にこれが要るのは、
   どの作業に入った人か**」を問う
3. **書く** ── 実例つきで書く。⚠ **抽象論を書かない** ── 「注意する」ではなく
   「**何が起きて、どう見分け、どうするか**」
4. **裁定は Issue にも起票する** ── 🔑 **会話に流すと消える**(2026-08-07 に
   GO 済みの件を聞き直す事故になった。#91)
5. **導線を検算する** ── 書いたパスが実在するか機械的に確かめる:
   ```bash
   # ⚠ `PKC2:.claude/…` は PKC2 側(read-only 参照)を指す規約なので除く ──
   #    除かないと検算が偽陽性を出し、次から無視される
   grep -rhoE '(PKC2:)?\.claude/[A-Za-z0-9./_-]*' CLAUDE.md .claude docs \
     | grep -v '^PKC2:' | sed 's/[.,)。]*$//' | sort -u \
     | while read p; do [ -e "$p" ] || echo "無い $p"; done
   ```
6. **古い記述を消す** ── 足すだけでなく**削る**。実態と食い違う記述は、在ることが害
7. **commit する**。⚠ **実体と導線を同じ commit に入れる** ── 導線だけ先に入れると
   壊れたポインタが残る(#69 で 1 度やった)

## 4. 書き方の作法

- **実例を必ず添える。** 「変異が当たったか確かめる」ではなく「`  armDpr();` が
  4 字下げの別行に部分一致して先にヒットした」まで書く ── 抽象論は再発を止めない
- **数字を書いたら、それが古くなることを前提にする。** 「116 本」のような実測値は
  **test が pin しているものだけ**書く。pin が無い数字は「約」で書く
- **⚠ / 🔴 / 🔑 を使い分ける** ── 🔴 は「これを外すと壊れる」、⚠ は「踏みやすい」、
  🔑 は「考え方の要点」
- **否定形で書く。** 「〜する」より「**〜しない**」のほうが守られる

## 5. この活動そのものの教訓(2026-08-07)

- 🔴 **裁定を受け取ったら、その場で起票するか資産に書く。** 会話に流すと消える。
  GO が出ていたのに起票せず、CLAUDE.md に「⏸ 裁定待ち」を残したまま **user に
  聞き直す**事故になった。「あとで書く」は書かないのと同じである
- 🔴 **実体を作ってから導線を書く。** 逆順は壊れたポインタになる
- ⚠ **`.claude/` を作ったら、それが読み込まれたことを確かめる**(スキル一覧・
  エージェント一覧に出る)。frontmatter の書式ミスは静かに無視される
