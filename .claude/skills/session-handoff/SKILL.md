# セッション引き継ぎ(PKC3)

> **user 指示 2026-07-26(PKC2 で確立、PKC3 に継承)**:
> 「**セッション引き継ぎはセッション引き継ぎ用の PR を作成して、その PR を渡すことで
> セッション引き継ぎを完成させます。PR には引き継ぎ事項のほかに最初の仕事の有無を
> 含めてください**」
>
> ⚠ 出典タグ付き = **不可侵**。削除・希釈・言い換えによる骨抜きを禁ずる。

## 0. 何をもって「完成」とするか

**PR を作り、その URL を user に渡した時点で完成。** doc を書いただけ・会話に要約を
書いただけでは完成していない ── 次のセッションは**会話履歴を持たない**。
**1 個の PR URL に集約されている**ことが、引き継ぎが機能する条件である。

## 1. 🔴 最初の仕事の有無 ── PR 本文の冒頭に必ず書く

| 区分 | 書き方 |
|---|---|
| **あり** | 「**最初の仕事: あり**」+ 何を・どこから・完了条件。次セッションは確認せず着手してよい |
| **なし(指示待ち)** | 「**最初の仕事: なし。user の指示を待つ**」 |
| **裁定待ち** | 「**最初の仕事: なし。user の裁定待ちが N 件**」+ 何を裁定してほしいか。**催促はしない** |

⚠ **曖昧にしない。**「あとは適当に続けて」は最悪で、次のセッションが**勝手に仕事を作る**。
「なし」と書くのは手抜きではなく、**それ自体が指示**である。

## 2. PR に入れるもの

### (a) 現在の状態 ── 次セッションが最初に確認する事実
- main の HEAD(sha と 1 行要約)/ open PR の一覧と状態 / 作業 branch
- ⚠ **実際に `git`・GitHub を見てから書く。** 2026-08-04 の引き継ぎ doc は
  「open PR: 無し / 作業 branch: 無し」と書きながら、当の PR と branch が実在した

### (b) 着地したもの ── 何が main に入ったか(PR 番号 + 1 行)
### (c) 残件 ── 「やる」と決まっているもの。**着手の順と、なぜその順か**
### (d) 🔴 裁定待ち ── user が決めないと進めないもの。**選択肢まで書く**
### (e) 踏んだ罠と覆った前提 ── ⚠ **書く先は原則 `.claude/` か `CLAUDE.md`**。
引き継ぎ doc には**要約とポインタ**だけ置く(下記「導線の作法」)

### (f) 測って「問題なし」と分かったこと ── 再調査させないために結論だけ書く
### (g) やらないと決めたこと ── **理由つき**。書かないと次が蒸し返す

## 3. 🔴 導線の作法 ── 指す先が実在するときだけ指す

2026-08-04 の引き継ぎ doc が 3 か所で**存在しない `.claude/`** を指し、
「罠の正本は `.claude` 側」と書いたせいで**罠がどこにも残らないところだった**(#69)。

```bash
# 引き継ぎ doc / PR 本文が指すパスを機械的に確かめる
# ⚠ `PKC2:.claude/…`(PKC2 側の read-only 参照)は除く ── 除かないと偽陽性が出る
grep -hoE '(PKC2:)?\.claude/[A-Za-z0-9./_-]*' <file> | grep -v '^PKC2:' \
  | sed 's/[.,)。]*$//' | sort -u \
  | while read p; do [ -e "$p" ] && echo "ok   $p" || echo "無い $p"; done
```

⚠ **実体を作ってから導線を書く。** 逆順で 1 度失敗している。

## 4. 手順

1. **`/claude-update`** を先に回す(知見を `.claude` と `CLAUDE.md` へ反映)──
   引き継ぎ doc に罠を書き溜めるのではなく、**資産に入れてからポインタを書く**
2. **状態を実測する** ── `git log --oneline -5` / open PR / CI の結論 / 未 push の有無
3. **doc を書く**(`docs/development/session-handoff-YYYY-MM-DD.md`)。
   ⚠ **PKC3 には `docs/development/INDEX.md` も `check:doc-orphans` も無い**
   (2026-08-07 に確認)── PKC2 の「新 doc は同 commit で INDEX 登録」は**ここでは
   適用されない**。代わりに**引き継ぎ PR 本文から doc を必ずリンクする**
   (孤児 doc を作らないのが目的で、手段は INDEX ではない)
4. **裁定待ちを Issue に起票する** ── 🔑 **会話に流すと消える**。
   2026-08-07 に、GO が出ていた案件を起票しなかったせいで**裁定済みの件を
   user に聞き直す事故**になった(#91)
5. **commit → push → PR** を作り、**URL を user に渡す**
6. 作業ツリーが clean であることを確かめる(コンテナは揮発する ── 未 push は失われる)

## 5. PKC3 固有の注意

- **ブランチは 1 本に固定されている**(`claude/…`)。主題ごとに PR を分けたくても
  分けられないことがある ── そのときは **commit を分け、PR 本文に「別主題が同居して
  いる」と明記**する。剥がすには user の許可が要る
- **merge は Claude に委任済み**(user 指示 2026-08-04「チェックリスト以外はあなたに
  すべて委任します」/ 「main に入れてくれ、Pages で見たいから」)。CI green +
  scope 自己監査クリアで squash merge してよい。⚠ scope drift / 後方互換の破壊 /
  不可逆操作 / 不可侵指示への抵触があるときは**会話で**裁定を仰ぐ
- 引き継ぎ PR が merge 済みなら、**branch を main から作り直す**
  (`git fetch origin main && git checkout -B <branch> origin/main`)── merge 済みの
  PR に新しい commit を積まない
