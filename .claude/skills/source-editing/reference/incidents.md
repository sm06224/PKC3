## 書き換えで、検査・内容が静かに消える

- 型: 自分の書き換え script や 1 回で書いた長い本文が、途中で切れる・範囲を食う。切れたことを誰も言わない。
- 見分け方: `npm test` は緑のまま(検査が消えれば落ちない)。気づく計器は**件数**と `git diff --stat` だけ。
- 直し方: 書き換えの前後で件数を見る。消す範囲は開始と終了の両方を文字列で名指しする(index で切って繋がない)。書いたら読み返し、本文は短くする。
- 手順の在り処: 正規表現で「まとめて消す」/ `Write` の前に path の実在を確かめる は `../SKILL.md`。

- 🔴 **test file を切り落としても、suite は緑になる**(2026-08-23。今日いちばん危なかった)。
  自分の書き換え script(index で切って繋ぐ形)が `tests/repo-hygiene.test.ts` を
  **527 行**削り落とした ── ⚠ そして **`npm test` は全部緑**だった。
  **検査が消えれば、当然その検査は落ちない。**
  🔑 気づけたのは **test の件数**だけである(**4364 → 4349**)。
  ⚠ 「Test Files 251 passed」も緑のままだった ── file は残り、中身だけ消えたので。
  - 🔑 **書き換えの前後で件数を見る。** 減っていたら**その場で止まる**
    (増減の理由を 1 行で言えないなら、それは事故である)
  - 🔑 **index で切って繋ぐ書き換えをしない。** 消したい範囲は
    **開始と終了の両方を文字列で名指し**して、`s[:i] + s[j:]` の `j` を
    必ず計算する ── `s[:i] + "…"` は**後ろを全部捨てる**
  - ⚠ **`git diff --stat` を commit の前に読む。** 527 行の削除は 1 行で見える
  - ⚠ これは CLAUDE.md『test は使い所を選ぶ』の**裏面**である ── あちらは「回さないと
    確かめていない」、こちらは「**回しても、消えた検査は何も言わない**」

- 🔴 **長い本文を 1 回で書くと、途中で切れることがある ── 切れても誰も言わない**
  (2026-08-30、#281 で **2 度**踏んだ)。⚠ 上は自分の script が file を切った話だが、
  こちらは **issue の本文**である。束ね台帳 #281 は表の 4 行目の途中
  (閉じていないバッククォート)で終わっており、**6 行が丸ごと消えていた**。
  🔴 **2 度目は「切れていたので書き直しました」と書いた更新自体が、同じ所で切れた** ──
  つまり**訂正の記録だけが残り、訂正されていない**。
  ⚠ 台帳は「まだ在る仕事」の顔をしているので、**切れた表を読んだ人はそこまでで数え直す**
  (題名の「残りは 3 本」と食い違うのに、誰も検算しない)。
  🔑 **書いたら読み返す** ── 末尾が意図した行で終わっているかを 1 回見るだけで分かる。
  🔑 **本文は短くする** ── 数えられることだけを置き、長い根拠はコメントへ回す
  (本文と根拠が同じ長さになった時点で、切れる側へ寄っている)。
  ⚠ **読み側を疑う前に、書き側で往復を確かめる** ── 今回は同じ口で書き直したら
  末尾まで戻ってきたので、切っていたのは**読み手ではなく自分**だと確定した。

## 作業ツリーの未 commit の編集を失う

- 型: 「後片付け」の道具(`git reset --hard` / `git checkout --`)や、書き込み権のあるエージェントの並行走行が、手元の編集を消す・変異させる。
- 見分け方: 追跡されていない新 file は残るので、消えた物と残る物が混ざって気づきにくい。自分の変更と混ざるので diff でも見えない。
- 直し方: 空 commit を戻すなら `git reset --soft`。確かめる操作の前に編集を `git add` しておく。書き込み権のあるエージェントは worktree を分ける。整形ツールを既存 file に掛けない(diff が読めなくなる)。

- 🔴 **書き込み権のあるサブエージェントを、自分の作業ツリーで並行に走らせない**(2026-08-04)。
  レビュー用に投げたエージェントが**私の編集中の file を変異させ、戻さずに終わった**
  (`// MUT-A: revoke removed` が `rasterize` の `URL.revokeObjectURL` を消していた)。自分の
  変更と混ざるので diff でも気づきにくい。読み取りだけならよい。書くなら**待ってから**か、
  worktree を分ける

- 🔴 **`git reset --hard` / `git checkout --` を「後片付け」に使わない**(2026-09-12。
  ⚠ CLAUDE.md が既に戒めている「変異試験の後始末に `git checkout` を使って未 commit の
  変更を失った」の**3 度目**である)。
  実例:hook が本当に効くかを **`git commit --allow-empty` で試し**、戻すのに
  `git reset --hard HEAD~1` / `git reset --hard origin/main` を打った ──
  🔴 **作業ツリーの未 commit の編集が、それで消えた**(`package.json` の 1 行。
  ⚠ 追跡されていない新 file は残るので、**消えた物と残る物が混ざって**気づきにくい)。
  🔑 **空 commit を戻すなら `git reset --soft`** ── 空なので staged も増えず、
  **作業ツリーを 1 byte も触らない**。⚠ `--hard` は「commit を戻す」道具ではなく
  **「作業ツリーを捨てる」道具**である(名前からは読めない)。
  🔑 手順:**確かめる操作(probe)の前に、手元の編集を `git add` しておく** ──
  stage してあれば `--hard` でも残る。⚠ 気づけたのは**別の test が落ちたから**で、
  落ちなければ**消えたことに気づかないまま push していた**

- 🔴 **整形ツールを既存 file に掛けない**。`npx prettier` を掛けて `main.ts` を全面リフォーマット
  (302 行差分)し、リポジトリで唯一 double quote の file にした。diff が読めなくなり、
  次に触る PR が全部 conflict する

## 見えない字・制御文字が生バイトで入る

- 型: 編集ツールが escape を書いたつもりで生バイト(制御文字・U+FEFF など)を埋める。
- 見分け方: `od -c` で見るまで気づけない。制御文字の走査は分類の外(U+FEFF・全角空白)を素通りする。
- 直し方: 書き換えたらバイト走査する(手順は `../SKILL.md` の §1)。「見えないもの」を止める検査は、範囲を字の種類で決める。

- 🔴 **制御文字をソースに生バイトで埋めない**(``'\u007f'`` と書く)。「正規表現に書かない」と
  注意書きしている当の file で 3 度踏んだので、`npm test` の `tests/repo-hygiene.test.ts` が
  機械的に止める
  - 🔴 **同じことが「見えない字」でも起きる**(2026-09-05、#708 段①の実装で踏んだ)。
    編集ツールが `'\uFEFF'` と書いたつもりで**生バイト(EF BB BF)を埋めた** ──
    ⚠ **U+FEFF は制御文字の範囲外**なので、上の走査は**素通りした**
    (`od -c` で見るまで気づけない)。🔑 走査に**見えない字**を足した
    (`U+FEFF` / `U+200B`〜`U+200D` / `U+2060` / `U+00A0`)。
    ⚠ 足した日に **2 件見つかった**(`xml-lite.ts` の `nbsp` の値と、BOM を使う test の
    fixture)── どちらも**正しい中身**だが**生で書かれていた**ので、escape に直した。
    🔑 一般形:**「見えないもの」を止める検査は、範囲を字の種類で決める** ──
    「制御文字」という**分類**で切ると、分類の外に同じ害の字が残る

## 名前が id として扱われる

- 型: id を機械的に潰す処理が在る repo で、「id らしく見える名前」が id として書き換えられる。
- 見分け方: diff が別物に見えるが原因が読めない。
- 直し方: 内部の名前(postMessage の種別など)を、既存の id の前置きで始めない。

- 🔴 **内部の名前を、既存の id の前置きで始めない**(2026-08-06)。postMessage の種別を
  `pkc-html-blocked-images` ではなく `pkc-html-render-blocked` と名付けたところ、箱の id が
  `pkc-html-render-<hash>` なので **goldens の正規化(id を連番へ潰す処理)が message 種別も
  一緒に書き換え**、diff が別物に見えて原因を 1 往復探した。⚠ id を機械的に潰す処理が在る
  リポジトリでは、**「id らしく見える名前」は id として扱われる**
