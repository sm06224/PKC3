# 変異試験(PKC3)

> **通っている test は、何も保証していないかもしれない。**(CLAUDE.md)

実装を意図的に壊し、**test が落ちることを確かめる**。落ちなければ、その test は
その機構を守っていない。実績: **1 PR あたり 1〜3 件が生き残り、その多くが
「既に壊れているのに鳴っていない」**だった。

> この file は**手順と判断の表**。事故の記録(日付・issue つき)は `reference/` の 2 本に在る ──
> [`incidents.md`](reference/incidents.md)(SURVIVED の型 = 生き延びた変異の実例)/
> [`harness-notes.md`](reference/harness-notes.md)(ハーネスの事故 = 印・戻し・判定)。

## 1. ハーネスを file に出す(その場の shell に書かない)

```bash
cp .claude/skills/mutation-testing/templates/mutate.py scratchpad/<issue 番号>/mut-<主題>.py
# MUTATIONS を編集してから
python3 scratchpad/<issue 番号>/mut-<主題>.py            # 全件
python3 scratchpad/<issue 番号>/mut-<主題>.py M1 M3      # id を指定
```

🔴 外すと壊れる規則(理由と実例は [harness-notes.md](reference/harness-notes.md)):

- **その場の shell に書かない。** shell の引用で python が SyntaxError になり、変異が当たらないまま
  「生存」と読むことがある。雛形は置換前に「元の文字列がちょうど 1 件」を assert し、置換後に
  「変異後の字面が在る」を確かめる。「挿入」型は `before` が `after` に含まれるので「元の字面が消えたこと」は
  要求できない(雛形は済み。手書きすると踏む)
- **変異表は file に書き、agent には「この file を回せ」と渡す。** 字を依頼文に通すと、渡った先で字が変わる。
  `NOT-APPLIED` が多く返ったら、まず**その字が実装に在るかを自分で数える**
- **自分だけの置き場に書く。** ハーネスも作業 file も `scratchpad/<issue 番号>/`(同名 file が別の agent に上書きされる)。
  backup は target の隣(`<file>.mutbak`)か `mktemp -d`。出力の先頭に `harness=<主題> muts=<件数>` を出し、
  **渡した件数と返った行数が合わない回は読まない**
- **`ROOT` は自分の作業ツリーから取る**(`git rev-parse --show-toplevel`。雛形は済み)。先頭に印字される ROOT が
  自分の worktree の path と一致することを 1 行見る(worktree の agent が本体の tree を変異させかけた)
- **アンカーは前後を含めて一意に。** `  armDpr();` のような断片は別の行に当たる。全角の括弧を含む
  コメント行は使わず**コードの行**を掴む。`$` を含む字面は perl でなく python を file に出して置換する
- **当てた後に、書き換わった行番号と、その行が入っている関数の名前**を出す(同じ行が 2 か所に在る)
- **smoke の絞り(`SMOKE_GREP`)は spec の path で書く**(題名は部分一致に化ける)。結果行に**走った test の件数**を出し、狙った数と合わせる
- **戻しは `finally` + signal**(雛形は済み)。`git checkout` で戻さない(未 commit の変更ごと消える)。
  バックアップは**当てる直前に取り直す**(使い回さない)。**スイープの後は `git status` / `git diff --stat` と字面を見て**、
  typecheck / lint / test を回してから commit する ── 変異試験は作業ツリーを触る操作である
- **固まる変異に備える。** `timeout -k` で確実に殺す / 出力は file へ(`$( )` で受けない)/ 変異の直後に必ず戻す /
  `124` / `137` は `TIMEOUT` として出す(`SURVIVED` と混ぜない)

## 2. 結果は 5 値で読む

| 値 | 意味 | やること |
|---|---|---|
| `KILLED` | test が、**変異を当てた assert の文言で**落ちた = 守られている | 次へ。build が落ちた(検品 tripwire)も `KILLED` |
| `SURVIVED` | test が通った = **守られていない** | 下の §3 で型を引いてから、test を足す / 書き直す |
| `NOT-APPLIED` | **変異が当たっていない** | アンカーを直して**やり直す**。🔴 **合格と読まない**(当たっていない変異は生存と見分けがつかない)。直したあとの再走でも生える(アンカーの字面が変わる) |
| `TIMEOUT`(判定不能) | 無限ループ等で時間切れ。外から殺すと終了コード非 0 で **`KILLED` に見える** | 3 値の外へ出す(雛形は出す)。`SURVIVED` より重い ── **製品が固まる形をしている**ので門の置き方を直す。node で書くなら `maxBuffer` 超過も `SIGTERM` なので `maxBuffer` を明示し、大きな生成物は `cat` せず `grep -c` に数えさせる |
| `INFRA`(計器が立たなかった) | playwright の `webServer` が立たず test が全部落ちた(`EADDRINUSE` 等) | 出力に `webServer` / `EADDRINUSE` / `Error: Process from config.webServer` が在れば `INFRA` として出し、**結果を読まない**(雛形は出さない。smoke を回すハーネスは書き足す)。`KILLED` と言えるのは**狙った assert の文言で落ちたとき**だけ(`first_reason` を結果行に出す) |

## 3. 生き延びたら ── test を足す前に型を引く

🔴 **`SURVIVED` には 2 つの意味がある。** 順に潰す ── 逆順だと、届いてもいない test に assert を足し続ける。

| 見かけ | 実態 | 直し方 |
|---|---|---|
| `SURVIVED` | test は**壊した行を実行している**が、assert が弱い | assert を足す / 観測点を変える |
| `SURVIVED` | test が**壊した行に一度も入っていない** | **入力を変えて経路に入れる** |

見分け方: 壊す代わりに **`throw new Error('reached')` を置いて test を回す**。落ちなければ、その行は**誰も通っていない**。
そのうえで「assert を足す」より先に「**この assert は何に救われているか**」を問う。

型の一覧(詳細は [incidents.md](reference/incidents.md) の「SURVIVED の型: …」。**型の見出しで引く**):

| 型 | 見分け方 | 直し方 |
|---|---|---|
| 通っていない | `throw` を置いても落ちない | 入力を変えて経路に入れる(指紋が同じなら早期 return する描画など) |
| user から見た差が無い | 実装は違うが結果が同じ | 差が出る入力を探す(居ない lid など)。本当に差が無いなら**冗長なコード**なので消す |
| 入力で差が出ない | 同じ結果になる 2 つの実装は区別できない。`null` 同士の `toBe` は緑 | fixture が「その変異で差の出る形か」を回す前に 1 行で言う。比べる前に片側 `not.toBeNull()` |
| 別の処理が結果を戻していた | 通り、差も出るのに、後続の処理が元へ戻す | 変異を当てたまま最終状態を印字。救い手が走らない前提を **fixture 側**で作る(製品は変えない) |
| 観測点が「開始」と「完了」を取り違えている | 直列でも真になる assert(`started` を見ている) | 並行・順序・排他は「相手を止めたまま自分が進めるか」で書く。変異前後で値が違うか印字 |
| 守る網が 2 枚あって互いに救う | 1 枚ずつ壊しても落ちない | 網の数だけ「その網だけが鳴る場面」を作る。殺せない網は殺せないと注記し、報告で「振る舞いを変えない後始末」と分けて数える |
| 実装の穴 | 変異が出した物が test の弱さではない | test を足す前に**実装はこれで正しいか**を読む(穴を埋めたまま緑にしない) |
| 当てた変異が欠陥を再現していない | 別の経路(例外・既定値)が拾って結果が変わらない | 「この変異を当てた版は、直す前の版と同じ振る舞いか」。**直す前の綴りをそのまま復元する変異**を 1 本(`git show`) |
| 手順が肝心の場面を作っていない | assert も変異も正しいのに落ちない | **初めての値**を作っているか。元へ戻す / 往復は新しい場面を作らない |
| 正しい値を残したまま偽物を足しただけ | `toContain` の門に「足す」変異 | **変異の向きを門の向きに合わせる**(下の表) |
| 「file に字が在るか」を見る門 | 字は別の所にも在って満たされる | 正本を 1 つ `export` し、**配列そのものを等値で pin**する。寄せる前に「同じ問いに答えているか」を 1 行で言う |
| 普段の経路を 1 度も通っていない | 入れ子 / 例外の場面しか無い | 1 本が何度も往復する形を、再予約・idle の tick を回したうえで N 周。状態 flag は何もしない tick の後に次の操作が通るか。レビュー依頼に「生き延びる変異を 2 つ以上、`from → to` で」 |
| 定数と符号を pin していない | 閾値・周期・数え直し・`<` / `!==` | 閾値の**両隣**(249 / 250)と符号の**裏側**を場面に。reset は短い episode を 3 回並べて「鳴らない」。模型が門なしでも落ちるなら**模型を疑う** |
| 1 回しか呼ばない台 | 「初回だけ動いて以後は固まる」変異が生き延びる | 台で 2 回以上呼び、2 回目の結果まで assert。`grep -c '<台の呼び口>('` で数える |
| 置き忘れた門 | 「N 件 KILLED」は置いた門の範囲でしか言えない | 変異を並べる前に、実装が受ける / 受けない**軸を数え上げ**、端を総当たり(§4) |
| 印の数では見えない門 | 読み手が描かない形は 0 個を返す | 判定関数を**直に**当てる test を別に置く。空振り防止を添える |
| 自分の直しの副作用 | 主張の向きを変えた反対側が壊れる | 向きを変えたら反対側で何が壊れるかを 1 度は見る。1 巡目の修正は 2 巡目の対象 |
| 経路が別 | 層をまたぐ配線を誰も通らない | どの test がその層を通るかを先に数える。無ければ **smoke が唯一の門** |

### 門の向きと変異の向き

| 門が見ているもの | 当てる変異 |
|---|---|
| **在ること**(`toContain` / `>0` / `toBeDefined`) | 🔑 **消す・置き換える**(⚠ 足す変異は当たらない) |
| **無いこと**(`not.toContain` / `toBe(0)`) | 🔑 **足す**(⚠ 消す変異は当たらない) |
| **等値**(`toBe` / `toEqual`) | どちらでもよい |

## 4. 変異の選び方

**壊れる当の振る舞い**を狙う。下流の結果だけ見る test は別経路に救われる。

| 型 | 例 |
|---|---|
| 値の取り違え | `find('dark')` → `find('light')`(名前しか見ない検査を素通りする) |
| 順序 | 生成物の一部を前後へ移す(詳細度・cascade・listener 登録順) |
| 落とす | 集合の最後の 1 件を落とす / 文脈(`@media`)を落とす |
| 緩める | `every` → `some` / 境界チェックを外す / 判定を常に真にする |
| 検品を骨抜き | 検査関数が常に合格を返す / `this.error` を消す |
| 渡し忘れ | 複数経路のうち 1 つだけ引数を落とす(**経路ごと**に 1 件ずつ) |

⚠ **検品する側・test する側も変異の対象**にする(CLAUDE.md)。検品が壊れると
「通った」という事実だけが残る。

🔑 **置いた門ではなく、置き忘れた門を狙う。** 変異を並べる前に「受ける / 受けない」を分ける**軸**を数え上げ、受ける側の端を総当たりする:

| 軸の例 | 端を並べる |
|---|---|
| 直前の 1 字 | 数字 / ASCII の語 / 日本語 / 記号 / 空白 / 行頭 |
| 打ち方 | 半角 / **全角** / 混在 / 変換中 |
| 位置 | 行頭 / 行末 / **行の途中** / 選択あり |
| 入れ子 | 素 / 引用の中 / 囲みの中 / **引用の中の囲み** |

## 5. 当てる相手ごとの作法

- **unit**: そのまま `vitest` に当てる。
- **probe**(`tests/probe/run-*.mjs`): vite dev(`--port 45731`)に向くので **build は要らない**。`src/**` を書き換えたら
  watcher が拾うまで**1.5 秒待つ**。判定は **exit code だけに頼らない**(`ok: false` でも `process.exitCode` を立て忘れる /
  bench は落ちない作り)── 出力の中身も見る
- **smoke**: `tests/smoke` は `vite preview` で **`dist/` を配信**するので、source を書き換えただけでは届かない。
  テンプレートの `kind="smoke"` は `npm run build` を挟み、`dist/assets/` の生成物に**変異後の字面が在り、変異前の字面が消えたこと**を確かめてから回す。
  - 🔴 **スイープの後に `npm run build` をもう 1 度回す**(ハーネスは source を戻すが `dist` は変異入りのまま残る)。
    最後の検証の前に必ず build する
  - 変異ごとに smoke を回すなら **port を agent ごとに固有**に(`PKC3_SMOKE_PORT` / `PKC3_PLAIN_PORT` / `PKC3_SUBPATH_PORT`、
    10 刻み。[smoke-testing](../smoke-testing/SKILL.md) §3)。**落ちた log に `EADDRINUSE` が無い**ことを見てから 3 値を書く
  - smoke の変異は、その変異が殺されるはずの **1 spec に絞る**(`build` + smoke の対で回る)

印の置き方(`dist` に何の字で落ちるかで書く。偽の `NOT-APPLIED` は「当たらなかった」の顔で出るので、そのまま読むと殺せた変異を捨てる):

| 壊す物 | 印 | 探す字 |
|---|---|---|
| CSS の宣言 | `--mut-a: 1` を**宣言として足す**(コメントの印は minify が消す) | **名前まで**(`--mut-a`。値と空白を入れない)。`*.js` だけでなく css も読む(雛形は両方) |
| CSS の選択子を差し替える | 印を選択子に埋めず、同じ規則に `--mut-x: 1;` を**1 行足す**。規則ごと消す変異にも代わりに `--mut-x: 1` を置く | 同上 |
| TypeScript | **実行時の副作用** `(globalThis as unknown as Record<string, unknown>)['__mutS1'] = 1;`(型注釈の印は `tsc` が消し、`.slice` する文字列リテラルは minifier が畳む) | `__mutS1` |
| 製品に焼き込まれた文書と字が被る | **コードにしか出ない字**にする(マニュアル・お知らせ・CHANGELOG は bundle に入る) | 変異を当てる**前に基準を数え**、「0 か」ではなく「基準から減ったか」で判定する。`grep -c` は行数なので `grep -o … \| wc -l` |

⚠ 印が出ないと言われたら、`grep` を**自分の手で**打って `dist/assets/*` の実際の字を見る(1 回で分かる)。

### R1 ── 直す前に、新しい test を「直す前の dist」で回して赤を見る(2026-09-02)

変異試験の最初の 1 件は **「直す前の実装そのもの」**である(CLAUDE.md §1「直す前の実装に
戻して、その test が落ちるか」)。順番を固定すると手間が要らない:

1. 新しい test(unit / smoke)を**先に**書く
2. **source を直す前に** `npm run build` した dist(= 直す前)へ、その test を当てる →
   **赤**を見る(落ちた行が「直したい症状」の assert であること。前提の assert で落ちたら
   台が崩れている)
3. source を直す → build → 同じ test が**緑**

⚠ **build の順番を間違えると偽の赤が出ない** ── 直してから build すると、直す前の dist は
もう無い。**dist を焼き直す前に回す**。実測 3 件 →
[incidents.md](reference/incidents.md)「R1 の実測」。

## 6. 報告の形

```
○ KILLED       M1 焼いた CSS を style から外す
    Error: 配った HTML の見た目がアプリと違う
🔴 SURVIVED    M2 …
⚠ NOT-APPLIED  M3 元の文字列が 0 件(1 件でない)

KILLED 10 / 10
```

PR 本文には **KILLED した件数と、何を壊したか**を書く。⚠ 「変異試験を回した」
だけでは意味がない ── **何が生き延びて、どう直したか**が中身である。
