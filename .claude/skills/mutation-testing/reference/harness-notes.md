## ハーネスは自分だけの置き場に書く(2026-09-04、#685 で 2 度読み違えた)

⚠ 共有の scratchpad(`/tmp/claude-*/…/scratchpad/`)に `mutate.mjs` のような
**ありふれた名前**で置くと、**並行して走っているサブエージェントに上書きされる**。
実例:着地前レビュアーが同名の file に**自分の変異一覧をハードコードした版**を書き、
以後こちらが渡した引数は**丸ごと無視された** ── 🔴 **相手の結果が返ってくるのに、
返り値は「変異試験の結果」の顔をしている**ので、そのまま自分の成果として読みかけた。

🔑 **気づけた手掛かりは 1 つだけ** ── **出力の書式が自分のものと違った**こと。
⚠ 中身(KILLED / SURVIVED の並び)は自然に見えるので、書式を見ていなければ
**やっていない変異試験を「全部 KILLED」と報告していた**。

だから 3 つ:

1. **置き場を分ける**(`…/scratchpad/mine/mutate-<主題>.mjs`)── 名前だけでなく**階層**を分ける
2. **自分のハーネスだと分かる印を出力に出す**(先頭に `harness=<主題> muts=<件数>` など)
3. ⚠ **件数を数える** ── 渡した変異の数と、返ってきた行の数が合わない回は**読まない**
4. 🔴 **backup の置き場も自分専用にする**(2026-10-01、#274 と #1102 の implementer が
   **同時に**踏んだ)。両方が自前のハーネスで backup を `…/scratchpad/bk/` に
   **同じ file 名**(`src__adapter__state__app-state.ts` など)で書いたため、
   片方の復元が**もう片方の版を書き戻し**、`app-state.ts` の編集が丸ごと消えた
   (気づけたのは `git diff --stat` の行数が想定の桁より小さかったから)。
   🔑 backup は **target の隣(`<file>.mutbak`。雛形 `templates/mutate.py` の作法)か
   `mktemp -d`** に置く。共有 dir に置くなら名前に主題を前置する ──
   ⚠ そして**変異試験の後に `git diff --stat` を読む**(行数が想定の桁か)
5. 🔴 **`ROOT` は自分の作業ツリーから取り、作業 file は `scratchpad/<issue 番号>/` に置く**
   (2026-10-01、worktree の implementer **2 本**が踏んだ)。雛形 `templates/mutate.py` の
   `ROOT` は昔 `/home/user/PKC3` 固定で、worktree の agent がそのまま写すと
   **自分の tree ではなく本体の tree を変異させかけた**。また scratchpad は**全 agent で共用**なので、
   `mutate.mjs` / `edit1.py` のような同名 file が**別の agent に上書きされた**。
   目的:**他人の tree を壊さない / 他人の道具を消さない**。
   🔑 手順:①`ROOT` は **`git rev-parse --show-toplevel`** から取る(雛形は直してある)。
   ハーネスの先頭で **`ROOT` を印字**し、自分の worktree の path と一致することを 1 行見る
   ②ハーネスも作業 file も **`scratchpad/<issue 番号>/`** の下に置く(`mkdir -p` してから。
   上の 1 と同じ「階層で分ける」)。

⚠ サブエージェントが `read-only` の型でも `Bash` は持つ。**規律を守るのは tools の
一覧であって、相手の善意ではない**(CLAUDE.md「規律を守るのは tools の一覧」)。
⚠ ただし**作業ツリーを触られたわけではなかった** ── 相手は `/tmp` のコピーで
検証していた。🔑 **事故の範囲は実測してから書く**(こちらは 1 度
「作業ツリーで回されている」と誤報した)。

## smoke の絞り(`SMOKE_GREP`)は spec の path で書く(2026-08-27、#444)

🔴 **smoke の絞り(`SMOKE_GREP`)は spec の path で書く。**
⚠ あれは playwright の**位置引数**なので、**空白で割られて file 名の部分一致**に
なる ── 2026-08-27(#444)に test の**題名**(`"添付から読んだ mermaid"`)を書いたら
`mermaid.smoke.spec.ts` に当たり、**狙っていない spec が緑で通って SURVIVED** と出た
(手で当て直したら KILLED だった)。
🔑 ハーネスは**走った test の件数を結果行に出す** ── 0 件は `NOT-APPLIED` で止まるが、
「**別の spec が走った**」は**数を見るしかない**。狙った数と合っているか毎回見る。

## その場の shell に書かない / 挿入型の変異 / アンカーは一意に(2026-08-04、2026-08-08)

🔴 **その場の shell に書かない。** shell の引用で python が SyntaxError になり、
**変異が当たらないまま「生存」と読んだ**ことがある(2026-08-04)。
テンプレートは置換前に「元の文字列がちょうど 1 件あること」を assert し、
置換後に「変異後の字面が在ること」を確かめる。

⚠ **「挿入」型の変異では「元の字面が消えたこと」を要求できない**(2026-08-08 に
ハーネスが 2 回止まった)。`before` を残したまま前後に足す変異
(`import X;` の前に 1 行挿す等)では `after` が `before` を**含む**ので、
`assert before not in now` が必ず落ちる。判定はこう書く:

```python
assert after in now, f'{mid}: 置換後の字面が入っていない'
if before not in after:                       # ⚠ 置換型のときだけ
    assert before not in now, f'{mid}: 元の字面が残っている'
```

🔑 **同梱テンプレートは既にこの形**(「置換後の字面が在るか」だけを見る)──
**手書きすると踏む**。`templates/mutate.py` をコピーして `MUTATIONS` だけ書き換える。

⚠ **アンカーは前後を含めて一意にする。** `?pkc-flag=editor.live` は同じ file に
3 回出て `NOT-APPLIED` になった ── `ARM === 'live' ? '?pkc-flag=editor.live' : ''`
のように**式ごと**掴む。

## `NOT-APPLIED` を合格と読まない(2026-08-04 / 2026-08-20)

🔴 **`NOT-APPLIED` を合格と読まない。** 当たっていない変異は「生存」と見分けが
つかない ── これを 1 セッションで 2 度踏んだ(2026-08-04)。

⚠ **直したあとの再走で `NOT-APPLIED` が生える**(2026-08-20)。実装を直すと
アンカーの字面も変わるので、**同じ変異表を回すと当たらなくなる** ── 「前は
KILLED だったから大丈夫」と読まず、**アンカーを直して回し直す**。

## 変異の字を依頼文に埋めて渡さない ── 渡った先で字が変わる(2026-09-27、#1081)

🔴 **変異の字を依頼文に埋めて渡さない ── 渡った先で字が変わる**(2026-09-27、#1081)。
Workflow のテンプレート文字列に変異表を書いて verifier へ渡したら、**14 件中 9 件が
`NOT-APPLIED`、1 件が `SURVIVED`** で返った。⚠ 当てる字は実装に**ちょうど 1 回ずつ
在った**(`grep -c -F` で数えて 1)── 逃がし(`` \` `` / `\${…}`)と改行の書き方で、
agent の手元に届いた字が実装と一致しなかったのが実体である。同じ 14 件を
**python の配列に字をそのまま書いた file** で当て直したら、11 KILLED / 3 SURVIVED
(3 件は本当に検査の穴だった)。
🔑 **変異表は file に書き、agent には「この file を回せ」と渡す**(字を会話や依頼文に
通さない)。⚠ `NOT-APPLIED` が多く返ったら、まず**その字が実装に在るかを自分で数える** ──
在るなら、それは「当たらない変異」ではなく**当て方の失敗**である。

## `TIMEOUT`(判定不能)── 2026-08-20 に誤読した

**変異が無限ループを作ることがある。** そのとき test は止まったまま返らないが、
外から殺すと**終了コードは非 0** なので、素直に読むと **`KILLED`** に見える ──
**「守られている」という嘘の合格**が残る。

実例: 埋め戻しの `for(;;)` は「UPDATE が条件を外すから必ず尽きる」に賭けていた。
代入を落とす変異で同じ 200 行が永久に返り続け、**test が 15 分止まった**。
外から殺した結果を KILLED と読みかけた(製品側にも天井を足して直した)。

🔑 **時間で切れたものは 3 値の外へ出す。** 同梱テンプレートは
`subprocess.TimeoutExpired` を `TIMEOUT` として出す(⏱)。

### ⚠ node で書くなら:`SIGTERM` は時間切れとは限らない(2026-08-20)

`execSync` は **`maxBuffer`(既定 1MB)超過**でも子を **SIGTERM で殺す**。
`e.signal === 'SIGTERM'` だけで判定すると、**落ちてもいないのに「判定不能」**と出る。
実例: 診断用の `cat dist/assets/*.js` が 1MB を超えて SIGTERM → `TIMEOUT` と表示。
手で回したら **9.5 秒で落ちて KILLED** だった。

```js
// ⚠ maxBuffer は明示して上げる。そのうえで時間切れと区別する
execSync(cmd, { stdio: 'pipe', timeout: 300_000, maxBuffer: 64 * 1024 * 1024 });
// …
const overflow = /maxBuffer/i.test(String(e && e.message));
status = e && e.signal === 'SIGTERM' && !overflow ? 'TIMEOUT(判定不能)' : 'KILLED';
```

🔑 **大きな生成物は `cat` しない** ── `grep -c` に数えさせて数字だけ受け取る。

## `INFRA`(計器が立たなかった)── 2026-10-02、#1231 段①の CSS 変異で踏んだ

smoke に変異を当てるハーネスは `build` + `playwright` の対で回る。**playwright の `webServer` が立たなければ
test は全部落ちる**ので、7 件の変異が**全部 KILLED に見えた**(偽の KILLED)。原因は port の衝突
(`EADDRINUSE`。playwright は `PKC3_SMOKE_PORT` から **3 つ**握る ── `subagent-scale` の注意書き)。
🔑 ハーネスは**落ちた理由の字**を見る:出力に `webServer` / `EADDRINUSE` / `Error: Process from config.webServer`
が在れば **`INFRA`** として出し、**結果を読まない**。KILLED は「変異を当てた test が、その assert の文言で落ちた」
ときだけ ── ⚠ 「落ちた」だけでは KILLED と言えない(§4 の「対照群が届かない回は判定不能」の、ハーネス版)。

## smoke の変異ハーネスは dist を戻さない(2026-10-02、#529 / #275 の直しで 2 本が別々に踏んだ)

source は `cp` の控えで戻るが、`npm run build` で焼いた **`dist/` は変異入りのまま残る**。そのまま最終の
smoke を回すと**全部緑でも検査対象が変異版**である(2 本とも気づいて build し直した ── 気づかなければ
「緑」を報告していた)。🔑 **最後の検証の前に必ず `npm run build`**(手順にする。ハーネスの `finally` に
build を入れる手もあるが重いので、依頼文の「最後に build し直す」の 1 行で足りる)。

## probe に変異を当てる(2026-08-17 に確立、#223)

**`tests/probe/run-*.mjs` は vite dev(`--port 45731`)に向く**ので、smoke と違って
**build は要らない** ── `src/**` を書き換えたら、次の page 読み込みでそのまま届く。
⚠ ただし watcher が拾うまで一拍あるので、当てた直後に **1.5 秒待つ**。

```python
if kind.startswith("probe:"):
    time.sleep(1.5)                      # vite の watcher が拾うのを待つ
    r = run(kind[len("probe:"):], timeout=900)
```

🔴 **判定は「exit code」だけに頼らない。** probe は `ok: false` を出しても
`process.exitCode` を立て忘れることがあるし、**bench は落ちない作り**である
(数字を出すのが仕事なので)。実例(#223):「live の行確定を外す」変異は
bench の**出力の中身**(`observed.diagram` が 0 件)でしか捕まらなかった。

```python
killed = r.returncode != 0 or '"diagram": 0' in out    # 中身も見る
```

## 置換文字列は前後を含めて一意にする

`  armDpr();` のような短い断片は、狙った行ではなく**4 字下げの別行に部分一致**する。
テンプレートは出現回数が 1 でなければ `NOT-APPLIED` を返す。

## smoke に当てるなら build が要る

`tests/smoke` は `vite preview` で **`dist/` を配信**する ── source を書き換えた
だけでは検査対象に**一切届かない**。印刷 CSS の変異 6 件が全部「SURVIVED」に
見えて「誰も守っていない」と読み違えかけた(真相は 6 件とも NOT-APPLIED)。

テンプレートの `kind="smoke"` は `npm run build` を挟み、**`dist/assets/` の生成物に
変異後の字面が在り、変異前の字面が消えたこと**を確かめてから test を回す。

## CSS を壊す変異は、印を custom property で置く(2026-08-14)

CSS の変異に**コメントで印を書くと minify が消す** ── dist に 1 つも残らないので、
**当たっているのに `NOT-APPLIED`** になる(実測: 出荷 css のコメントは **0 件**、
custom property は残る)。`--mut-a: 1` を足して、それを探す。

⚠ **`*.js` だけを見ない。** `app.css` は `dist/assets/` へ**別 file** で出る
(実測 js **105 件** / css **1 件**)── テンプレートの `dist_assets()` は両方読む。

```bash
# 変異を当てて build したあと。印が無ければ NOT-APPLIED(SURVIVED と読まない)
grep -rq -- "--mut-a" dist/assets/
```

⚠ **規則ごと消す変異にも印を残す** ── 消すだけだと「当たったこと」を dist から
確かめられない。消した規則の代わりに `--mut-x: 1` を置くと、当たりが見える。

## 印は「dist に何の字で落ちるか」で書く(2026-08-27、#474 で 2 件)

⚠ 上の 2 つは「印の**置き方**」の話だが、この日は**置き方は正しいのに探す字が違って**
2 件とも**偽の `NOT-APPLIED`** になった。⚠ どちらも「当たらなかった」の顔で出るので、
そのまま読めば**殺せた変異を捨てる**。

| 書いた印 | dist に落ちる字 | 探した字 | 結果 |
|---|---|---|---|
| `--mut-x: 1;`(宣言) | `--mut-x:1`(**空白が落ちる**) | `--mut-x: 1` | ❌ 当たらない |
| `[data-pkc-field='mut-x-none']`(**選択子**) | `[data-pkc-field=mut-x-none]` | `--mut-x` | ❌ 当たらない(**選択子に `--` は付かない**) |

🔑 **宣言なら「名前まで」で探す**(`--mut-x`。値と空白を入れない)。
🔑 **選択子を書き換える変異では、印を選択子に埋めない** ── 同じ規則に
`--mut-x: 1;` を**宣言として 1 行足す**(選択子の変更と印を分ける)。

```python
# 選択子を差し替える変異。印は「宣言として」足す
old = "[data-pkc-field='entry-pick-row'] {\n  /* 器いっぱいの行にする"
new = "[data-pkc-field='mut-x-none'] {\n  --mut-x: 1;\n  /* 器いっぱいの行にする"
```

⚠ **検算は 1 つ** ── 印が出ないと言われたら、`grep` を**自分の手で**打って
`dist/assets/*.css` の**実際の字**を見る(1 回で分かる)。
⚠ ここを飛ばして「当たらない変異だ」と結論すると、**その変異は二度と回されない**。

## TypeScript を壊す変異の印は、実行時の副作用にする(2026-08-18、#253)

CSS のコメントと同じ罠を、TS で **2 通り**踏んだ ── どちらも
「dist に届いていない」= **偽の NOT-APPLIED**(変異自体は効いている)になる:

| 印の置き方 | どうなるか |
|---|---|
| **型注釈に混ぜる**(`'idle' as T & { __mutS1?: true }`) | ❌ `tsc` が**型を消す**ので 1 バイトも出ない |
| **文字列リテラル + `.slice`**(`'idle__mutS1'.slice(0, 4)`) | ❌ minifier が**畳んで** `'idle'` にする |
| **実行時の代入** | ✅ 残る |

```ts
// 変異の中に 1 行足す ── 畳めない・消せない
(globalThis as unknown as Record<string, unknown>)['__mutS1'] = 1;
```

⚠ 印が出ないときに**「当たらなかった」と読んで先へ進まない** ── まず
**印の置き方**を疑う(1 度目は本当に届いていない、2 度目はたいてい印の側である)。

**マニュアル・お知らせ・CHANGELOG が bundle に入る**ので、user に見せる文言や、
文書に載せた実例のコードは**印に使えない**。
🔑 迷ったら、印を `__mut<Id>` のような**その場で作った字**にする
(上の「実行時の副作用」と同じ理由 ── **他の誰も書かない字**であることが要点)。
⚠ そして **`grep -c` は「行数」であって「出現数」ではない**
(minify された dist は数行しか無いので、10 件あっても `1` と出る)──
数えるなら `grep -o … | wc -l`。

🔴 **判定は「0 か」ではなく「基準の数から減ったか」で書く。** この件の実測:

| | dist の `capture-ready` |
|---|---|
| 変異前(基準) | **2 件**(コード 1 + マニュアルに載せた実例 1) |
| 変異後 | **1 件**(マニュアルだけ残る) |

⚠ 「0 なら当たった」と決めつけていたので、**1 件残ったのを NOT-APPLIED と読みかけた**。
🔑 **変異を当てる前に基準を数える** ── 差が出れば当たっている。

バックアップと復元は `finally` の中だけに置き、外から `git` を触らせない。

## `finally` だけでは足りない ── 殺されたときにも戻す(2026-08-22、#178)

⚠ ハーネスを **timeout で殺されると `finally` は走らない**。実際に踏んだ:
2 分の timeout でスイープごと落ち、**変異が作業ツリーに残った**。

🔴 **本当に怖いのは次の走りである。** 残った変異入りの版を `orig` として読むので:

1. その変異は「元の文字列が 0 件」= **NOT-APPLIED** と出る(**合格に見える**)
2. **以後のどの復元も「変異入りの版」を書き戻す** ── スイープ全体が無意味になる
3. 変異が **1 つ製品コードに残ったまま** commit されうる(この日は
   **無限ループ**のコードが残った ── 字面を目視して気づいた)

🔑 **シグナルでも戻す。** node のハーネスなら:

```js
const RESTORE = [];
const restoreAll = () => { for (const [p, t] of RESTORE) { try { writeFileSync(p, t); } catch {} } };
for (const sig of ['SIGINT', 'SIGTERM', 'SIGHUP'])
  process.on(sig, () => { restoreAll(); process.exit(1); });
process.on('exit', restoreAll);
// 変異を当てる直前に積む
RESTORE.push([path, orig]);
```

⚠ **背景実行にすれば安全、ではない** ── 背景でも timeout はかかる。
🔑 **スイープの後は `git status` と字面を見る**(緑だけ見て commit しない)。
⚠ そして **`NOT-APPLIED` を合格と読まない** ── この日それを守ったから助かった。

## `HUNG`(= テンプレートの出力名では `TIMEOUT`)を `SURVIVED` と混ぜない(2026-09-11、#215 / 2026-10-02、#1266)

⚠ 上は「殺されたときに戻す」話だが、**そもそも殺せないことがある**。
実際に踏んだ形:門を 1 つ外した変異で配線が**無限に回り**、同期のループなので
**test の timeout すら発火しない**(JS は 1 本なので、回っている間は誰も割り込めない)。

🔴 **`$(timeout 120 …)` は効かない。** `timeout` が `npx` を殺しても、
**子が stdout を握っている限り `$( )` は返らない** ── ハーネスはぶら下がったままになり、
外から殺すと(上の節と同じく)**変異が作業ツリーに残る**。

```bash
run() {                      # 🔑 出力は file へ。$( ) で受けない
  local log=/tmp/…/mut_$1.log
  timeout -k 5 150 npx vitest run "${@:2}" > "$log" 2>&1
  local code=$?
  restore                    # 🔑 変異の直後に必ず戻す(trap だけに頼らない)
  if [ $code -eq 124 ] || [ $code -eq 137 ]; then echo "$1: HUNG(固まった)"; return; fi
  if grep -qE "Tests .*failed" "$log"; then echo "$1: KILLED"; else echo "$1: SURVIVED"; fi
}
```

🔴 **`HUNG` は `SURVIVED` より重い。** 生き延びたのは「**検査が弱い**」だが、
固まるのは「**製品が壊れうる形をしている**」である ── 門が 1 つ消えただけで
固まるなら、**門の置き方のほうを直す**。

⚠ そのとき「再入を弾く」形の門で済ませない ── この repo の `Dispatcher` は
**drain 中の dispatch を待ち行列に積む**ので、輪は入れ子ではなく**順番に**回る
(再入の門は 1 度も効かなかった)。🔑 効いたのは**送る条件**のほう:
回り続ける理由が「押すたびに時刻が動く」ことなので、**時刻だけの違いでは送らない**
形にしたら輪が構造から消え、同じ変異が 1 秒で `KILLED` になった。

🔑 **「静まらない実装」を test で再現する台には、天井を置く**(2026-10-02、#1266)。
読み直しの ack が別の板の読み直しを呼び続ける実装を台で再現したら、台の `drain` が
**無限に回って `HUNG`** した(変異ではなく**正しい test が**固まった)。
台の `drain` に**総読み込み数の天井(2000)**を置き、超えたら throw する ── 固まらずに
**「静まらない」という赤**で落ちる。天井は「正しい実装なら絶対に届かない数」にする
(届くなら台が実装を邪魔している)。

## smoke が `EADDRINUSE` で落ちた回を、`KILLED` と読まない(2026-10-02)

変異ごとに smoke を回す(build + preview)ハーネスで、**同じ port を続けて使う**と、
前の回の接続が `TIME_WAIT` に残り、**自分の preview が port を取れず `EADDRINUSE`** で落ちる。
落ちた smoke は「test が落ちた = `KILLED`」と読まれ、**変異が効いていないのに緑の側(守られている)に数えられる**。
目的:**変異の結果を、port の事故と混ぜない**。

🔑 手順:
1. agent ごとに **`PKC3_SMOKE_PORT` / `PKC3_PLAIN_PORT` / `PKC3_SUBPATH_PORT` を固有の値**にする
   (例:`4799x` の帯で、agent ごとに 1 桁ずつずらす)── 他の worktree とも被らないこと
   (`smoke-testing` の SKILL.md §3「並走・負荷の規則」)。
2. **落ちた回の log に `EADDRINUSE` が無い**ことを見てから 3 値を書く(grep 1 回)。
   在れば `KILLED` ではなく**判定不能**として、port を替えて回し直す。
3. 🔑 **変異が効いて落ちた**ことの確かめは、落ちた理由の 1 行が**狙った assert の文言**であること
   (`first_reason` を結果行に出す)。「何かで落ちた」は KILLED の根拠にならない。

## harness の stub が、実物の「呼び方」を写していないと、書き方の誤りを見逃す(2026-10-08、#1408 (c) / PR #1423)

C++ の patch を g++ の stub harness で確かめるとき、`emscripten_sync_run_in_main_runtime_thread` を**関数として** stub したら、
実物は**可変長 macro** なので「lambda の最上位カンマで引数が割れる」誤りが**そのままコンパイルできてしまい**、1 稿目は焼きが落ちる形のまま通った(着地前レビューが g++ で再現)。
🔑 stub は**意味論だけでなく呼び方**(macro / 可変長引数 / attribute)も写す。macro は上流の `#define` を fixture に抜いて harness に取り込む。
⚠ 「stub が本物より甘い」(CLAUDE.md §3「stub は本物の意味論を真似る」)の、呼び方版である。
