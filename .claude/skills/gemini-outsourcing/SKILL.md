# Gemini へ外注する(PKC3)

> user の言葉(2026-10-09、こちらの解釈):**Gemini は堅実なコードを最新の形にリファインしてくれる。
> test が在るぶん品質も担保される。外注の仕方をスキルにしてよい。**
> 協働の約束事(🔵 / 🟣 の印、user 裁定の線、対話の型)は **issue #1163 の本文**が正本。
> このスキルは**こちら側の手順**だけを持つ。

## 0. いつ出すか ── 判定は「閉じているか」

| 出してよい | 出さない |
|---|---|
| **主題が閉じている**(1 関数 / 1 flake / 1 CI job)で、**test が既に在り**、効いたかを**数字で言える**物 ── perf の 1 関数(#1478 `buildBlockPartition`)/ 既知の flake の根本(#1480 `read-columns`)/ CI の軽量化(#1392) | 設計の判断が要る物 / user の見え方(色・大きさ・並び・名前)に触る物 / 不可侵指示に当たる物 / 「調べて考えて」の開いた問い |
| **こちらが同じ手を 3 回以上繰り返す**作業(計器の整備、同型の修正の横展開) | user 裁定待ちの物(2 者で決めない ── #1163 約束事 5) |

🔑 理由:Gemini の強みは**堅実な土台を最新の書き方に直す**こと。土台(test と観測点)が無い所へ
出すと、返ってきた PR を**こちらが検算できない**(検算できない PR は着地できない)。

## 1. 依頼の書き方(#1163 のコメント。1 行目は `🔵 Claude:`)

```
🔵 Claude: 依頼 ── <主題を 1 行>(issue #NNN)

- 直す物: <file> の <関数 / 規則>。⚠ 触らない物: <file>(理由 1 行)
- いまの数字: <計器名> で <値>(測った条件 ── N 行 / 回数 / 箱)
- 返してほしい物: PR 1 本(1 主題)+ 変異の表(KILLED / SURVIVED / NOT-APPLIED / TIMEOUT / INFRA)
  + 前後の数字(同じ計器・同じ条件)
- 測り方: seed は 1 回 / 他の重い物を同じ箱で回さない / before と after を交互に 2 回ずつ
- 核(これを失ったら意味が無い): <1 行>
```

- 🔴 **1 依頼 1 主題**。2 つ束ねると、片方が落ちたときに**両方止まる**(#1480 と #1481 を 1 本にしていたら、両方待ちになっていた)
- 🔴 **触らない file を書く**。Gemini は親切に周りも直す ── 直されると、こちらの進行中の PR と衝突する
- 🔑 **返ってくる物の形を書く**(表 / 数字 / 3〜5 値)── 形が無い報告は送り直しになり、それがムダ撃ちである(CLAUDE.md 2026-09-20)
- ⚠ 期限は書かない。次の同期で拾う(Gemini のセッションは別の時間に動く)
- ⚠ **内部の語彙で書かない**(「面」「口」「器」…)。Gemini は CLAUDE.md を前提にしない(#1163 本文)

## 2. 受け取ったら ── 自己申告は観測ではない

🔴 **2026-10-09 の実例**:#1480 は「flake を直した。変異 3 件 KILLED」と自己申告していたが、
こちらの計器で回すと **2/10 → 9/10 に悪化**していた。自己申告の緑は、**向こうの箱の 1 回**でしかない。

| 順 | やること | なぜ |
|---|---|---|
| ① | PR の branch を **worktree に `--detach` で checkout**(`git fetch origin pull/NNN/head`)。⚠ 自分の作業ツリーでは開かない | branch を切り替えると、進行中の物が混ざる |
| ② | **申告された変異を自分で当て直す**(`mutation-testing` の雛形。表は file に書く) | KILLED の自己申告は、変異が**当たっていた**ことを言っていない(NOT-APPLIED と見分けがつかない) |
| ③ | **自分の計器で前後を測る**(before = base の sha、after = PR の head。交互・直列・静かな箱) | 向こうの数字は向こうの条件。同じ計器で揃えないと比べられない |
| ④ | `npm test` 全量を**最終の sha で 1 回**(pkc3-runner、worktree) | 触った層の test だけでは、共有面の退行が見えない |
| ⑤ | `pkc3-reviewer` に通す(read-only) | 「test が緑のまま壊れている」所は、回しただけでは出ない |
| ⑥ | 着地 → #1163 に 1 行(PR / sha / 数字)→ issue に観測点 → close | 「済んだ」には観測点(#1163 約束事 4) |

⚠ ③で向きが揃わない(こちらでは効かない)ときは、**条件の差**を先に疑う(N / 箱の負荷 / seed の違い)。
揃えても出ないなら、それが結論 ── 着地しない。

## 3. 突き返すとき ── 「何が違うか」ではなく「何を見れば分かるか」

```
🔵 Claude: #NNN ── こちらの計器では <値> でした(条件: …)。申告の <値> と向きが違います。
観測点のヒント: <何を / どう見ると差が出るか を 1 つ>(例: debounce は等間隔の打鍵では 1 度も発火しない ── 途中で 1.2 秒止める群を作る)
核(<1 行>)はそのままで、<直してほしい 1 点> だけお願いします。
```

- 🔑 **核を壊さない**(#1163 対話の型)── 突き返すのは**検算に落ちた 1 点**であって、提案の意図ではない
- ⚠ 「直してください」だけでは同じ物が返る ── こちらの計器が**何を見たか**を渡す(向こうの計器が無い所を補う)
- ⚠ 2 往復で揃わなければ、こちらで引き取る(待ちで止めない ── #1163 ⚠)

## 4. 同期(#1163)

着地・突き返し・新しい依頼のたびに、#1163 へ**表 1 行**(PR / sha / 状態 / 次に誰が動くか)。
⚠ 「待っています」と書いた物は、**次の同期で付いた返事を読んで**から書き直す
(Gemini裁定待ち のラベルの腐り ── CLAUDE.md 2026-10-04)。

## 5. 自己点検(依頼を出す前)

- [ ] 主題は 1 つか。test は既に在るか。数字で言える計器が在るか
- [ ] 触らない file を書いたか。返ってくる物の形を書いたか
- [ ] user 裁定の線(見え方 / 不可逆 / 過去の裁定)に触っていないか
- [ ] 内部の語彙が 1 つも無いか
