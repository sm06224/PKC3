# PKC2 から PKC3 へ移行する

> ⚠ **この doc は「いま動くもの」だけを書く。** 最終更新: 2026-10-06(用語の総直し。字を画面の言い方に揃えた)
> 関連: [マニュアル](./manual.md) / [P7 設計 doc](./development/p7-product-release-design-2026-08.md)

---

## 0. 3 行でいうと

1. **PKC2 で「バックアップ」を書き出す** → 2. **PKC3 の「取り込む」に渡す** → 終わり。
2. PKC2 は消さずに残しておいてください(PKC3 の書き出しは **PKC2 に取り込めません**)。
3. 取り込めなかったもの・書き換えたものは、取り込み後に**画面に全件出ます**。黙って省きません。

---

## 1. PKC3 の書き出しは PKC2 に取り込めない(user 裁定 2026-07-30)

| 向き | 可否 |
|---|---|
| PKC2 の書き出し → **PKC3 に取り込む** | ✅ できる(全 9 形式) |
| PKC3 の書き出し → **PKC2 に取り込む** | ❌ **できない。対応する予定もない** |

PKC3 のバックアップの `format` は `pkc3-archive` で、PKC2 の取り込みは `pkc2-*` に
厳格一致するため、**取り違えて壊れることはありません**(読めないときは受け付けられません)。

→ **PKC2 の `pkc2.html` は手元に残してください。** PKC3 へ移した後で
「やっぱり PKC2 で見たい」と思っても、PKC3 から戻す道はありません。

---

## 2. 受け取れる形式

PKC2 の書き出しは全部そのまま渡せます。判別は**拡張子ではなく中身**
(先頭バイトと `manifest.format`)で行います。

| PKC2 の形式 | 拡張子 |
|---|---|
| 単一 HTML export | `.html` |
| package(バックアップ正本) | `.zip` |
| text bundle / textlog bundle | `.zip` |
| texts / textlogs / mixed container bundle | `.zip` |
| folder export bundle | `.zip` |
| entry bundle | `.zip` |

⚠ **迷ったら「package」を使ってください**。PKC2 側でいちばん情報が落ちない形です。

---

## 3. 何がどう変わるか

### 3-1. 本文はぜんぶ PKC-Markdown になる

PKC2 はノートの種類ごとに **本文が JSON 文字列**でした。PKC3 は
**すべて PKC-Markdown 1 種類**で、種類は「見せ方・編集の仕方」の
フレーバーになります。

| 種類 | PKC2 の本文 | PKC3 の本文 |
|---|---|---|
| `text` / `folder` / `generic` / `opaque` | 素のテキスト | **そのまま**(恒等変換) |
| `todo` | `{status, description, date?, archived?}` の JSON | frontmatter(`status` / `date` / `archived`)+ 本文 markdown |
| `textlog` | エントリ配列の JSON | `## <日時>` の節を並べた markdown(秒まで) |
| `spreadsheet` | セル配列の JSON | csv fence + frontmatter(レイアウト・グラフ・書式) |
| `form` | フィールドの JSON | frontmatter のフィールド群 + 本文 |
| `attachment` | メタ + **内蔵 base64** | frontmatter(`asset_key` / `mime` ほか)+ 説明。**bytes は別置き** |

→ 移行後は**どのノートも素の markdown として読めます**。
「Markdown」の書き出し(`.md.zip`)で外に出せば、PKC3 を捨てても読めます。

### 3-2. 添付は本文から出て、別置きになる

PKC2 が本文に内蔵していた base64 は、取り込み時に取り出されて
**IndexedDB の Blob** になり、本文には `asset:<添付の ID>` の参照が残ります。
同じ中身は 1 つにまとめられます。

- 取り出したものは「古い形式の内蔵データを添付にしました: `<ID>`」と出ます
- **解決できなかった添付参照は、書き換えずに原文のまま残します**
  (「未対応の添付参照は元のまま残ります: …」)。推測で書き換えて壊すよりまし、という判断です

### 3-3. 落ちるもの・変わるもの(全部あとで画面に出ます)

| 何が | どうなる | 画面に出る文言 |
|---|---|---|
| `__…__` 形式の予約 ID / `system-*` の種類 | **取り込まない**(PKC2 の内部用) | (なし) |
| ID の衝突 | **付け直す** | `ID が重なったので付け直しました: <旧> → <新>` |
| つなぐ先のノートが無いつながり | **除外** | `つなぐ先のノートが無いつながりを除外: <id>` |
| つながりの kind が未知 | **除外** | `不明な種類のつながりを除外: <id> (<kind>)` |
| 本文の変換に失敗 | **text として保持**(捨てない) | `変換失敗(text として保持): <ID>: …` |

⚠ つながり(PKC2 では relation)の kind は `structural` / `categorical` / `semantic` / `temporal` /
`provenance` の 5 種を受けます。

⚠ **つながりの ID も付け直します。** PKC2 のつながり(relation)に ID が無いと全部空文字で
衝突し、**同じファイルを 2 回取り込むと 1 回目のつながりが消えます**。実際に起きたので、
ID は取り込みのたびに振り直します。

### 3-4. 残るもの

- **並び順** … PKC2 の `entry_order` があればそれを、無ければ配列順を引き継ぎます
- **履歴** … PKC2 の revision は鎖ごと引き継ぎます(古い → 新しい)。
  `created_at` があればそれを正とします
- **ゴミ箱** … PKC2 のゴミ箱の ID も衝突の検査の対象です
  (見逃すと、そのノートがゴミ箱から消えます)

---

## 4. 手順

1. **PKC2 で書き出す**(package 推奨)
2. **PKC3 を開く**(product URL)
3. 左のペインのいちばん下の **取り込む** → 書き出したファイルを選ぶ
4. 画面に出た**注意を全部読む**。閉じるまで残ります
5. **PKC3 側で、左のペインのいちばん下の バックアップ を書き出して保管する**(`.pkc3-full.zip`)
   ⚠ 右の情報ペインの **書き出す** は**選択中の 1 件だけ**です(全体ではありません)
6. **PKC2 の `pkc2.html` とその書き出しは消さずに残す**

⚠ 4 を飛ばさないでください。落ちたものはここでしか分かりません。

### 分けて入れてもよい

複数のファイルを順に取り込めます。ID が衝突したら付け直されるので、
**同じものを 2 回入れると 2 つになります**(上書きにはなりません)。

---

## 5. PKC2 と何が違うか(移行後に気づく差)

| | PKC2 | PKC3 |
|---|---|---|
| 製品の形 | **単一 HTML**(`pkc2.html`)を手元に置く | **Pages 上の PWA**。インストールして使う |
| データの置き場 | IndexedDB(全体を丸ごと 1 件) | **OPFS 上の SQLite**(本文・メタ・履歴)+ IndexedDB(添付の bytes) |
| 本文 | 種類ごとの JSON 文字列 | **全部 PKC-Markdown** |
| オフライン | ファイルを開くだけなので常に動く | Service Worker がバージョンを保存(一度オンラインで開けば以後動く) |
| 更新 | 新しい `pkc2.html` を自分で置き換える | 画面に**案内が出て、押したときだけ**入れ替わる |
| タブ | 複数開ける | 複数開ける。**保存を実際に書き込む「メインのタブ」は 1 つ**で、2 枚目以降の保存は**メインのタブ経由**で届く(ステータスバーに「複数タブ: このタブの保存はメインのタブ経由です」と出る。→ マニュアル「複数タブで開ける」) |

**「閲覧用 HTML」の書き出しが PKC2 の単一 HTML に近い立ち位置**です
(1 つのファイルで配れて、その場で読める)。ただし**PKC3 へ取り込み直せません**。
取り込み直せるのは、`.pkc3-full.zip` のバックアップです。

**取り込み直せる PKC3 入り HTML もあります。** 右のペイン(何も選んでいないとき)の **PKC3 入り HTML で書き出す** です。
PKC3 のアプリそのものと、いまの中身と、添付が 1 つの `.html` になり、
ダブルクリックで開いて**そのまま読み書きできます**(PKC2 の `pkc2.html` に最も近い形です)。
⚠ マニュアル「出す・取り込む」の「PKC3 入り HTML」の注意を、そのまま載せます:

> - **1 ファイルごとに別の保存領域**です。2 ファイル書き出して両方に書くと、**中身は混ざりません**が、
>   **片方に書いたことはもう片方には出ません**。戻すときは、その HTML ファイルの中で
>   **バックアップ**を取って、元の PKC3 に取り込んでください
> - **配布された PKC3 入り HTML からは、さらに「PKC3 入り HTML」を書き出せません**
>   (元になるファイルを取得できないためです)。押すとその旨が出ます
