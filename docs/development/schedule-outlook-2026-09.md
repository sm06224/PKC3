## 0. 何を求められているか(user 指示 2026-09-12。こちらの解釈)

**予定表を、小さな改善の積み足しではなく、Outlook と並べて語れる「予定表アプリ」に
作り直すこと。** ⚠ こちらが出した 6 候補(時刻順 / 日を 2 回押して打てる / 週の面 /
つまみを畳む / 繰り返しの口 / 祝日)は**どれも今の形を前提にした部分直し**で、
「いまの姿は正しい」と暗に決めていた ── そこが誤りだった。

🔑 **だから問うのは「何を足すか」ではなく「軸が合っているか」である。**

### 🔴 いま在る欠陥(実測。#855 に起票して先に直す)

1. 🔴 **`毎日` は開始が 1,599 日より前だと 1 枚も出ない。** 展開の回転上限が
   `200 × 8 = 1600` で、窓の下限が「今日」なので**全回が捨てられる**。
   ⚠ しかも打ち切りの印(`truncated`)が立たないので**画面に何も出ない**
   (実装の docstring が例に挙げている `@2020-01-06 毎日` が、今日の時点で**該当**)。
   ⚠ test はこの次元を持っていない(該当 test は `週` で書かれている)。
2. 🔴 **繰り返しの 2 回目以降は鳴らない。** 見張りが読むのは**規則の行そのもの**で、
   回を展開しているのは**描画の 1 か所だけ**。⚠ 押して増えた実体の行は `- [x]` なので
   そちらも落ちる。
3. 🔴 **繰り返しは「消せるのに置けない」**(片道)。札の `×` は `@… 毎週` を記法ごと
   剥がすのに、**面から毎週に戻す口が 1 つも無い**(本文を手で書くしかない)。
   ⚠ 不可侵「置けるなら外せる」の**逆向きの破れ**である。

## 2. PKC2 / PKC1 から持っていく物(動線で読んだ)

⚠ **PKC2 のカレンダーは月グリッド 1 枚**で、時刻も期間も繰り返しも優先度も通知も
持っていなかった(予定の属性は **4 欄**だけ)。🔑 だから「PKC2 に追いつく」は目標にならない。

**持っていく価値(形ごと真似てよい)**

- 🔑 **掴んだまま面をまたいで作業が続く**(タブに 600ms 留まると面が変わり、そのまま落とせる)
- 🔑 **落とす先が「何を変えるか」を 1 つだけ決める**(列 = 状態 / 日 = 日付 / フォルダ = 所属)
  ので、**荷物は lid 1 個で足りる**。⚠ 1 つの操作で 2 つの欄を変えない
- 🔑 **面を変えても選択が生き残る**
- ⚠ 指で触る端末では `+` を**常時出す**(PKC2 は後から直した ── 最初からそう書く)

**🔴 前世代(PKC1)が持っていて、PKC2 で失われた物**

**期日で束ねた時系列の一覧(agenda)/ 「今日へ戻る」1 手 / 優先度 / 4 状態
(todo・doing・done・wait)/ `.ics` の書き出し** ── ⚠ PKC3 はここから
**取り戻す**側にいる(「PKC2 に無いから要らない」ではない)。

**🔴 持ち込まない実装形**(PKC2 が実際に困っていた形)

同じ予定カードを面ごとに手で描く(6 本あって 2 本が食い違っていた)/ 書式を
アンビエントな変数で配る(子窓が黙って既定へ落ちる)/ 子窓へ CSS 1,249 行 +
JS 1,609 行を手写し / 日付の索引を全件 JSON parse で作る / 面の名前が付いた
描画の例外を彫る / 面を中央の 1 枚に排他で置く。

## 3. ブラウザ完結で「どこまで Outlook か」── 境界は 1 本

> **自分の端末の中で完結することは全部できる。
> 「他人のいま」を知ること・「他人へ今すぐ届けること」だけができない。**

| | 中身 |
|---|---|
| 🟢 **そのまま作れる** | 日/週/月/一覧の面・**時間の帯と重なりの段組み**・ダブルクリックで新規・掴んで移動・端を掴んで伸縮・**繰り返し(RRULE 相当)の展開**・例外日・タイムゾーンと夏時間・カテゴリ色・**複数カレンダーの重ね合わせ**・検索・`.ics` の読み書き・**開いている間の通知**・アイコンのバッジ |
| 🟡 **形を変えれば届く** | **招待** → `.ics`(METHOD:REQUEST)を書き出して渡す / **受け取り** → 取り込み(インストール済みなら file を開くと PKC3 が起動)/ **他人のカレンダー** → `.ics` を落として取り込む / **10 分前に鳴らす** → 🔑 **OS のカレンダーへ `.ics`(VALARM つき)を渡して、OS に鳴らしてもらう** |
| 🔴 **原理的に無理** | 招待の即時往復(メール送信が要る)/ 相手の空き時間 / 会議室の予約 / 共有カレンダー / **`webcal:` や CalDAV の直読み**(CORS)/ **端末が寝ている間の通知**(サーバの鍵が要る)/ ブラウザに時刻を予約して鳴らしてもらう(**その API は開発終了**) |

⚠ **「寝ている間に鳴らす」は作れない。** だから **UI で約束しない** ──
「10 分前に通知」のつまみを、閉じていると鳴らないまま置くのは**無言の dead click** と
同じ型で、しかも user は**鳴らなかったことにしか気づけない**。

### 🔑 Outlook「らしさ」の本体は 4 つ(機能一覧ではない)

1. 🔴 **時間が「量」として置いてある** ── 縦軸が時刻の連続量で、予定は長方形。
   長さ = 所要時間が測らずに分かる。⚠ **月の升に字を並べる形をいくら磨いても、
   軸が違うので Outlook にはならない。**
2. 🔴 **手で掴める**(ダイアログを開かずに 8 割終わる)
3. **配置が動かない**(= PKC3 の「業務画面」方針そのもの)
4. **色は情報にだけ**(= PKC3 の既存方針そのもの)

⚠ 招待・空き時間・会議室は **Exchange らしさ**であって、Outlook らしさの本体ではない。
⚠ ただし「Outlook 的」の半分が**メールクライアント**であることは、境界として先に言う。

🔑 **PKC3 が Outlook に勝てる 1 点**:予定・タスク・メモが**同じ本文の中に在り**、
面から双方向に触れる(Outlook の To Do 統合は実際には繋がりきっていない)。

| 段 | 中身 | 量 |
|---|---|---|
| **0** | 🔴 **いま在る欠陥 3 件を直す**(§1。`毎日` が 0 枚 / 2 回目が鳴らない / 繰り返しが片道) | S |
| **A** | **時間の帯(週 + 日)+ 重なりの段組み** ── らしさの本体① | L |

| **C** | **記法を外の語彙に合わせる**(時刻の**幅**= 開始〜終了 / 隔週・複数曜日 / **壁時計 + タイムゾーンで保存し、UTC は派生**) | M〜L |
| **D** | **`.ics` の書き出しと取り込み** ── 外の世界への唯一の口 | M(書き)/ L(読み) |
| **E** | **カテゴリの色と、複数カレンダーの重ね合わせ** ⚠ **見え方なので user 裁定が要る** | M |
| **F** | **通知を誠実にする**(開いている間は確実に / **閉じている間は OS へ外注** / 起動時に見逃しを回収 / バッジ) | M |
| **G** | 月の面の作り直し(升に字)/ 印刷 / 祝日 | M |

⚠ **段 C を後回しにすると、後から入れるとき全データの読み直しになる**(保存の形が変わるため)。
⚠ **段 A は面の中核 file を触るので、実ブラウザの検査がほぼ全量引かれる**(実測 91/95)──
着手の前に**面を分割する**(1 file 581 行のまま触らない)。

### 🔴 `.ics` で必ず踏む落とし穴(先に門にする)

`VALARM` は `VEVENT` の**いちばん最後**(途中に置くと新しい Outlook が**場所を黙って落とす**)/
終日の終わりは **+1 日**(排他)/ 繰り返しの終了だけは **UTC** / **VTIMEZONE を同梱**(でないと
Outlook が時刻をずらす)/ 例外日は**時刻と TZ が完全一致**しないと消えない / 改行は CRLF・
**75 バイト**で折る(⚠ 日本語は 25 文字で溢れる)/ 更新は**同じ UID + 連番を増やす** /
招待は `ORGANIZER` と `ATTENDEE` が揃って初めてボタンが出る。

⚠ **手で添付した `.ics` は招待として認識されない**(ただのファイルに見える)。
