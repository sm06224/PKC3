## 測って「問題なし」と分かったこと(結論。再調査しない)

- **定常は増えない** ── 編集 90 ラウンドでヒープ・DOM・ObjectURL 残高が横ばい
- **添付を抱えても増えない** ── 14.1MB を抱えて 50 ラウンドで heap 差 0.1MB
  (bytes は IDB の Blob にあり heap に載らない)
- **図キャッシュの 32MB 上限は効いている** ── 185 枚目で追い出しが走り、超過 0。
  一気に焼くと 161KB(図 1 枚ぶん)行き過ぎるが 29.7MB へ収束する
- **待機タブは太らない** ── Web Locks で待つので polling が無い
- **昇格は実データで通る** ── memory fallback していない(最新の本文が出る)

## 踏んだ罠

⚠ 最初この節を「正本は `.claude` 側」と書いたが、**PKC3 に `.claude/` は無い** ──
つまり**どこにも残らないところだった**。`CLAUDE.md` の「検証の規律」へ入れた(本 PR に同梱)。
以下はその要約。

このセッションで繰り返し踏んだのは **「変異試験の変異が当たっていない」** 2 件:

1. shell の引用(`&&`/クォート)で python が SyntaxError → 変異が適用されず「生存」に見えた
2. `  armDpr();` が意図した行ではなく **4 字下げの別行に部分一致**して先にヒットした

→ **変異試験の走りを file に出し、「当たっていない」を別の判定として出す**。
`SURVIVED` と `NOT-APPLIED` を区別しないと、**空振りを合格と読む**。

⚠ もう 1 件、**サブエージェントが作業ツリーに変異を残した**(`MUT-A: revoke removed` が
`rasterize` の revoke を消していた)。**書き込み権のあるエージェントを自分の作業ツリーに
並行で走らせない**。
