# 録った音の前後を削る(#683 段②a)── 設計

> user 裁定 2026-09-14:**録った音の前後を削ったら、元と同じ形(opus)で保存する。**
> 切り出した結果は**新しい添付として 1 つ増え**、元のものは残る。
> ⚠ WAV だと 1 分 10MB になり「削ったのに元より重くなる」ので、それは避ける。

⚠ この doc は**裁定を仰ぐため**のものです(doc-first)。量が L なので、実装の前に出します。

---

## 1. 画面で何が起きるか

1. **音/動画** の面で、録ったものを**聞く**(いまも聞ける)
2. 聞きながら「**ここから**」「**ここまで**」を押す ── 押した所に**時刻が出る**
3. 「**この範囲で切り出す**」を押すと、**新しい添付が 1 つ増える**
4. **元のものはそのまま残る**(⚠ 上書きしない)

⚠ **波形は出しません**(裁定どおり)── 「前後を削る」だけなら聞きながら印を付けるほうが
手数が少なく、作るものも小さいためです。波形が要るのは「真ん中を抜く」「細かく合わせる」で、
それは別の段です。

## 2. 🔴 いちばん大きい発見 ── **符号化し直す必要が無い**

裁定のときに「**音を符号化する部品を 1 つ足す**(数百 KB)」と書きましたが、⚠ **2 段階で違いました。**

### ① 部品は要らない(実測 2026-09-14)

ブラウザが **WebCodecs** で opus を持っています:

```
AudioEncoder: function / AudioDecoder: function
isConfigSupported({codec:'opus', 48kHz, 1ch, 64kbps}) → true
1 秒ぶん符号化 → packet 51 本 / 8371 バイト(≒ 67 kbps)
```

⚠ **測り方で 1 度外しかけました** ── 1 回目は `about:blank` で測って `AudioEncoder` が
`undefined` でした。真因は **WebCodecs が `[SecureContext]`** であることで、`https:` の文脈で
測り直したら**両方のビルドに在りました**。
⚠ `AudioData` と `EncodedAudioChunk` は `about:blank` でも見えるので、
**「一部だけ在る」が嘘の結論を後押しします**(CLAUDE.md §4 観測点)。

### ② 🔑 そもそも**復号も符号化もしない**で済む

録ったものは **webm の中の opus** です(`MediaRecorder` の既定)。
🔑 **opus の packet はそれ自体で完結している**ので、

> **要る範囲の packet を、そのまま新しい入れ物へ移すだけ**

で切り出せます。⚠ **音は 1 ビットも作り直しません**(劣化ゼロ・速い・記憶をほとんど使わない)。

| | 復号 → 符号化 | 🔑 **packet を移すだけ** |
|---|---|---|
| 音の劣化 | 有る(2 回目の符号化) | **無い**(bit そのまま) |
| 速さ | 実時間の数分の 1 | **ほぼ file を読む速さ** |
| 記憶 | 下の §3 のとおり重い | **切り出した範囲の圧縮済みバイトだけ** |
| ブラウザ | WebCodecs が要る | **要らない**(素の JS で足りる) |

⚠ **WebCodecs が要らない**のは大きい ── Safari / Firefox で「押せるのに使えない」を作らずに済みます。

### ③ 前提を測った(2026-09-14、この箱の Chromium)

⚠ 上の道は「**録ったものは webm の中の opus**」が前提なので、**書く前に測りました**:

```
MediaRecorder（製品と同じく mime を指定しない）→ recMimeType = "audio/webm;codecs=opus"
先頭 4 バイト = 1a 45 df a3（EBML）/ CodecID = A_OPUS / CodecPrivate に OpusHead 在り
```

再生できる入れ物も測りました(`canPlayType`):

| | |
|---|---|
| `audio/webm; codecs=opus` | **probably** |
| `audio/ogg; codecs=opus` | **probably** |
| `audio/mp4; codecs="mp4a.40.2"` | **(空)= 再生できない** |

⚠ `MediaRecorder.isTypeSupported('audio/ogg;codecs=opus')` は **false** ですが、
それは「**録る**ときに選べない」だけで、**こちらが組んだ ogg を再生できるか**とは別の話です
(上の表のとおり再生はできます)。⚠ 2 つを混同すると、出す入れ物の判断を誤ります。

### ④ 🔴 ほどく所を試作して、**本物の録音**に当てた(repo の外)

3 秒の録音(38,456 バイト)を落として、EBML を読む 60 行の試作を当てた結果:

| 測った物 | 値 |
|---|---|
| `CodecID` | **`A_OPUS`** |
| `CodecPrivate` | **`OpusHead`**(19 バイト) |
| `TimestampScale` | 1,000,000(= 1ms) |
| packet の数 | **50**(3 秒ぶん) |
| 🔴 **packet の間隔** | **60ms**(49 個すべて。⚠ **20ms ではない**) |
| lacing | **0**(= 使っていない)── 49 個すべて |
| `OpusHead` の `pre-skip` | **0** |
| `CodecDelay` | **無し** |

🔴 **これで設計が 2 か所変わりました**:

1. **packet の境目のずれは最大 60ms** ── ⚠ 「普通 20ms」はこちらの思い込みでした。
   §5 の埋め合わせは**そのぶん大きく**なります(それでも u16 に収まります ── 下記)。
2. **元の音には遅れが無い**(`pre-skip` 0 / `CodecDelay` 無し)ので、
   **こちらが書く値をそのまま入れられます**(元の値との足し算が要らない)。

⚠ **この試作は repo の外**(`/tmp/…`)に置いてあり、実装はここから書き起こします。

### ⑤ 🟢 **詰める所まで試作して、ブラウザに食わせた**(端から端まで通った)

同じ 3 秒の録音から **1.000〜2.000 秒**を切り出し、**packet をそのまま**新しい webm へ詰めて、
ブラウザの `<audio>` に食わせました:

| 測った物 | 値 |
|---|---|
| 元 | 38,456 バイト / 3 秒 |
| 切り出し | **18,252 バイト** / 残した packet **21 個** |
| 頭で捨てさせる `CodecDelay` | 160ms |
| 尻で捨てさせる `DiscardPadding` | 100ms |
| 🟢 **`<audio>.duration`** | **1.000 秒**(= 頼んだとおり) |
| 音が入っているか | **入っている**(復号して振幅の平均 0.035) |

🔑 **21 packet × 60ms = 1,260ms から、頭 160 + 尻 100 を捨てて 1,000ms** ── 計算どおりです。

#### 🔴 ここで 1 つ、test の書き方が決まりました

⚠ **`decodeAudioData` は `CodecDelay` / `DiscardPadding` を見ません** ── 同じ file を
復号させると **1.26 秒 / 60,480 サンプル**(= 21 packet ぶん丸ごと)が返りました。
🔑 だから **長さを見るのは `<audio>.duration`**、**音の有無を見るのは復号**、と
**計器を分けます**(片方で両方を測ろうとすると、必ずどちらかで嘘になる)。

⚠ **user に見える所では正しい**(アプリが鳴らすのは `<audio>`)。
⚠ ただし**書き出した file を、端の指示を見ない道具で開くと**、前後が 0.1〜0.2 秒ぶん
長く聞こえます ── **既知の限界として書いておきます**(消したければ符号化し直すしかなく、
それは音を作り直すことになるので採りません)。

## 3. ⚠ 丸ごと PCM にする道は採れない(なぜ書くか)

いちばん素直な道は `decodeAudioData` で丸ごと PCM にしてから切ることですが、**採れません**:

| 録ったものの長さ | 丸ごと PCM(48kHz / f32 / 1ch) |
|---|---|
| 5 分 | 約 57 MB |
| 30 分 | 約 345 MB |
| 12 時間(いまの上限 `MAX_CAPTURE_MS`) | **論外** |

⚠ 「ゼロコピー・生成物のライフサイクル終端での即破棄」(不可侵指示 2026-07-27)と正面から反します。
🔑 §2② の道なら、記憶に載るのは**切り出した範囲の圧縮済みバイトだけ**です
(1 分の切り出し ≒ 0.5 MB)。

## 4. 段取り(3 段)

```
元の添付(webm/opus)           切り出した添付(webm/opus)
        │                                 ▲
        │ ① ほどく(WebM/EBML)            │ ③ 詰める(WebM/EBML)
        ▼                                 │
   packet の列 + OpusHead  ──② 選ぶ──▶  要る packet だけ
                            （範囲）
```

### ① ほどく(WebM / Matroska)

読むのは**必要な所だけ**です:

| 何を | どこから |
|---|---|
| `TimestampScale`(既定 1ms) | Segment → Info |
| `TrackNumber` / `CodecID`(`A_OPUS` か) | Segment → Tracks → TrackEntry |
| 🔑 **`CodecPrivate` = 元の `OpusHead` そのもの** | 同上 |
| packet と時刻 | Segment → Cluster(`Timestamp`)→ `SimpleBlock` |

⚠ **`A_OPUS` でなければ、この道は使いません**(→ §6 の梯子)。
⚠ **lacing(1 つの block に複数 frame)は受けない** ── ⚠ **実測でも 0**(§2④)ですが、
**受けないことを声に出して**断ります(黙って壊れた file を作らない)。

### ② 選ぶ

- 範囲の**始まり以前で、いちばん近い packet 境界**から取る
- 🔑 **80ms ぶん余分に前から取る** ── opus の復号器は立ち上がりに前の音を要るので、
  いきなり切ると**頭が濁ります**(仕様が 80ms 以上を推奨)。
  ⚠ 実測の packet は **60ms** なので、**2 つ前から**取れば足ります(120ms)
- 余分に取ったぶんと、境界と範囲のずれは **`CodecDelay` で捨てさせる**(下の §5)

### ③ 詰める(WebM / EBML)── ⚠ **Ogg ではなく WebM にする**

裁定の言葉は「**元と同じ形**」です。opus のままでも **入れ物を変えると拡張子も mime も変わる**
(`.webm` → `.opus`)ので、**入れ物も元と同じ WebM にします**。

| 何を書くか | 中身 |
|---|---|
| `EBML` 頭 / `Segment` | 最小限(`DocType = webm`) |
| `Info` | `TimestampScale`(1ms)/ `Duration` |
| `Tracks` → `TrackEntry` | 🔑 **元の `CodecID` / `CodecPrivate`(= `OpusHead`)をそのまま写す** |
| `Cluster` | `Timestamp` + packet を並べる |

🔑 **ほどく側と同じ EBML の道具**(可変長整数の読み書き)を使い回すので、
別の入れ物を覚えるより**足す行が少ない**。

#### ⚠ Ogg を選ばなかった理由(測ったうえで)

| | Ogg/Opus | 🔑 **WebM/Opus** |
|---|---|---|
| 再生できるか | probably | probably |
| 拡張子・mime | **変わる**(`.opus`) | **変わらない**(`.webm`) |
| 書く量 | 少ない(ページ + CRC32) | 少し多い(EBML) |
| 下流 | ⚠ `EXT_MIME` の逆引きに `audio/ogg` を足す必要が出る(書き出しの名前が `.bin` になる罠。`capture.ts` に前例) | **そのまま** |

⚠ Ogg のほうが**書く量は少ない**ので、実装を始めて WebM の側で詰まったら
**ここへ戻って選び直します**(そのときは拡張子と `EXT_MIME` の手当てが要る、と分かっている)。

## 5. 端の合わせ方(⚠ ここが唯一の細かい所)

opus の 1 packet は 2.5〜120ms で、⚠ **この箱の `MediaRecorder` は実測 60ms** でした(§2④)。
packet の境目でしか切れないと、**最大 60ms ずれます** ── それを 2 つの仕掛けで消します:

| 端 | 仕掛け(WebM) | 効き方 |
|---|---|---|
| **始まり** | `TrackEntry` の **`CodecDelay`**(ナノ秒) | 復号器が頭の N サンプルを**捨てて**から出す |
| **終わり** | 最後の block の **`DiscardPadding`**(ナノ秒) | 復号器が尻の余りを**出さない** |

⚠ `DiscardPadding` は `SimpleBlock` には書けません ── **最後の 1 つだけ `BlockGroup`** にします
(前の block は `SimpleBlock` のままでよい)。
🔑 これで **サンプル 1 つの精度で切れます**(符号化し直さずに)。

⚠ Ogg なら同じことを `OpusHead` の `pre-skip`(u16)と最後のページの `granulepos` でやります
── **どちらの入れ物でも精度は落ちません**。

#### ⚠ 入る値の大きさを検算する(u16 に収まるか)

| 何が | サンプル(48kHz) |
|---|---|
| 余分に取る 2 packet | 120ms = **5,760** |
| 境目と範囲のずれ | 最大 60ms = **2,880** |
| 合計(最悪) | **8,640** |

🔑 Ogg の `pre-skip` は **u16(65,535)**なので**十分収まります**。
WebM の `CodecDelay` はナノ秒の整数なので上限はありません。

## 6. 受けられない形のときは(梯子)

| その file が | どうするか |
|---|---|
| **webm の中の opus**(いまの録音は全部これ) | 🟢 §4 の道(packet を移すだけ) |
| webm だが opus でない / lacing 有り | ⏸ **WebCodecs が在れば**復号 → 符号化(§2①)。⚠ 無ければ**押し所を出さない** |
| mp4 / その他 | ⏸ 同上 |

🔴 **押せるのに何も起きない口を作らない** ── 切り出せない形のときは
**ボタンを出さず、理由を 1 行その場に書きます**(「この形はまだ切り出せません」)。
⚠ 「押したら断る」ではなく「**出さない + 理由**」にするのは、この repo の既定です。

## 7. どこに置くか

| もの | 置き場 | 理由 |
|---|---|---|
| ほどく / 選ぶ / 詰める | `src/features/audio/`(純関数) | browser API を持たない ── **node の unit で全部殺せる** |
| 走らせる | 🔴 **ワーカー**(`WorkerLease`) | 「重い処理はワーカーへ・使い終わったら捨てる」(不可侵指示 2026-08-03)。⚠ 形は `asset-client.ts` と同じ |
| 元の bytes を読む | `AssetLender.getBlob(key)` | 既に在る口 |
| 新しい添付にする | 🔑 **`attachOne()`** | 既に在る口 ── **新しい取込口を作らない** |
| 押し所 | `captures.ts` の行 | `capture-play` と同じ並び |

⚠ ワーカーへ渡すのは **`ArrayBuffer` を transfer**(ゼロコピー)。
⚠ 出来た bytes も transfer で返し、**ObjectURL は寿命の終端で revoke**。

## 9-b. ⚠ 実装して分かったこと(2026-09-14 追記)

設計のときに**書いていなかった**ことが 4 つ出た。どれも「試作が 1 秒しか切らず、
自分で録った file しか相手にしなかった」ために見えていなかったものである。

| 何が | どう直したか |
|---|---|
| 🔴 **block の相対時刻は 16 ビット**(±32.767 秒) | 1 つの `Cluster` に詰め続けると**33 秒を超える切り出しが書けずに落ちる**。`Cluster` を 30 秒ごとに切り直す |
| 🔴 **外から来た webm は 0 から始まらないことが在る** | 印は `<audio>.currentTime` から採るが、**ブラウザは最初の時刻を 0 と見せる**(実測:`Cluster` を +5000ms ずらしても `currentTime` は 0 起点、`seekable` も `[0, …]`)。揃えないと**まるで違う所を黙って切る** → packet の時刻を 0 起点に直す |
| 🔴 **track は 1 本とは限らない** | 2 本あると「最後に読んだ track」で上書きされ、①opus が在るのに断る ②**別の track の中身が混ざる**。`A_OPUS` の `TrackEntry` を選び、その `TrackNumber` の block だけ採る |
| 🔴 **切り出した物をもう一度切ると、札のぶんずれる** | 切り出した物には `CodecDelay` が付いているので、`<audio>` の時刻は packet の時刻より札のぶん手前。**元の札を読んで足してから**探す |

⚠ **§9 の「まだ測っていないこと」は 1 つ減った**(起点のずれ)。残る 3 つ
(Safari / Firefox が何を吐くか・実機での所要・12 時間の file をほどく時間)は**まだ測っていない**。

## 10. 裁定をお願いしたいこと

⚠ **実装の作り方は裁定の外**(委任の内側)なので、聞きたいのは**画面の見え方**だけです。

| | 画面で何が起きるか |
|---|---|
| **A(推薦)** | 切り出したものは**新しい添付**として増え、名前は元の名前 + 範囲(例:`録音-0912-1430 (0:12〜1:05).webm`) |
| B | 名前は聞かれる(小窓が出る) |
| C | 元の添付を**置き換える** ── ⚠ 裁定と反する(元は残す)ので出しません |

**推薦は A** です ── 手数が 1 つ少なく、名前を見れば**どこを切ったか**が分かるためです
(直したければ、いつもの改名でできます)。

🔑 **これが分かったら覆ります**:切り出しを**何度も繰り返す**使い方が主なら、
名前が長くなるので B(聞く)のほうがよくなります。
