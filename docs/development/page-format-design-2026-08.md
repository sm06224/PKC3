# 紙面フォーマットの設計(A4 / A3 / フル HD / 4:3・縦横、既定 A4 縦)(2026-08)

> Issue #102 の段 2。裁定待ちの設計 doc である。
> 実地調査(読み幅の面の全数 / settings 基盤 / PKC2 の A4 前提の実装点)に基づく。

## 0. user 裁定(2026-08-08。出典タグ付き = 不可侵)

> **読み幅はA4とA3、フルHDと4:3の縦横を選べるようにし、デフォはA4縦、任意設定可能にし
> 画面での閲覧に適した形式を作ることも可能にしたい。PKC2はA4タテしかなくて、フルHDの
> 画面で使いにくかった。それを解消したいが、デフォの筋をよくして使い勝手も良くしたい。**

## 1. PKC2 の「A4 縦で使いにくい」の実体(調査で確定)

PKC2 は「A4 固定か、無制限か」の**二択で中間が無かった**:

- `layout:` 指定時: 画面でも **21cm(794px)固定カード** ── フル HD(1920px)の窓では
  **約 41% しか使わない**(`PKC2: base.css:2675-2688`)
- `layout:` 無指定時: **読み幅 cap 自体が無い** ── 1 行が全角 90 文字まで伸びる
  (PKC3 実測: 3 列レイアウトで detail 実効幅 1172px、`app.css:885-886` の記録)

PKC3 は既にこの反省を 1 つ入れてある: 読み幅 42rem は**器ではなく各ブロック(散文)にだけ**
掛かり、**表・図・コード・iframe は対象外**(横に広いほど読めるものは全幅を使う。allow-list 方式)。

## 2. 設計の骨子(推薦)

**フォーマット = 「散文の読み幅 R」+「印刷の紙の幾何(@page)」の組**として実装する。
器の幅では実装しない。

理由:
1. **表・図・コードが全幅を使える現在の設計を殺さない**(器 cap を入れると PKC2 の
   「41% しか使わない」に戻る)
2. **mermaid 図が焼き直されない** ── ラスタ幅は器の親幅から決まるので、器を動かすと
   全図の焼き直し + キャッシュ鍵変更が起きる。ブロック側の値差し替えなら図は動かない
3. 「A4 縦 = 現行 42rem」がほぼ恒等(42rem = 672px ≈ A4 印字幅 643〜658px)──
   既定を変えても既存ユーザーの見え方が変わらない

### フォーマットと値(提案。値は裁定で調整可)

| フォーマット | 読み幅 R(画面・書き出し) | 印刷 @page |
|---|---|---|
| **A4 縦(既定)** | 42rem(672px ≈ A4 印字幅)= 現行と同じ | A4 portrait |
| A4 横 | 62rem(992px ≈ A4 横の印字幅) | A4 landscape |
| A3 縦 | 62rem(A3 縦の紙幅 297mm = A4 横と同じ) | A3 portrait |
| A3 横 | 91rem(1456px ≈ A3 横の印字幅) | A3 landscape |
| フル HD(16:9 横) | **cap 解除**(散文も器いっぱい)── 「画面での閲覧に適した形式」の本体 | @page 指定なし(既定紙) |
| フル HD 縦(9:16) | 64rem(1024px 弱 ── 縦長画面の幅) | 同上 |
| 4:3 横 | 60rem(960px) | 同上 |
| 4:3 縦 | 45rem(720px) | 同上 |

- ⚠ 42rem 超の散文は日本語の可読幅(全角 35〜50 文字)を超える ── これは user が
  幅を使う側を選んだ結果なので尊重する(既定は可読幅側の A4 縦)
- 紙系フォーマットの印刷には `@page { size: A4 }` 等を**新設**する(PKC3 に @page は現在 0 件)

### 設定の置き場

- **グローバル**: 正規設定(settings)。`pkc3.page-format` の localStorage 1 鍵
  (theme / external-images と同じ作法: 壊れていても既定へ / export に混ぜない / 戻せる)。
  設定画面「表示」節に 1 項目。**flag ではない**(恒久・user 向け)。URL パラメータも作らない
  (2026-08-07 不可侵指示: クエリパラメータの切替は flag 扱いになるため)
- **ノート単位の上書き**: frontmatter の **`layout:` キー(既存)を拡張**する。
  - `layout:` は PKC2 互換の 9 値(a4-1col 等)が既に受理され、`data-pkc-layout` 属性として
    読む面・プレビュー・ライブ・書き出しの 4 面に**届いているのに、消費する CSS が 0 件**
    (= 書いても何も起きない)── ここに消費 CSS を与える
  - 新値を additive に追加: `a4-landscape` / `a3` / `a3-landscape` / `fullhd` /
    `fullhd-portrait` / `43` / `43-portrait`(綴りは実装時に確定)
  - 既存 9 値は対応する紙に写像(a4-* → A4 縦、b5-* → B5 縦、letter/legal → 準 A4)。
    `-2col/-3col` の段組は本設計の範囲外(現状どおり素通り ── 記法は失わない)
  - 優先順位: **ノートの `layout:` > グローバル設定 > 既定(A4 縦)**

### 機構

- グローバル: 設定値を app root の `data-pkc-page-format` 属性に反映 →
  `[data-pkc-page-format='…'] { --read-w: … }` で `--read-w` を差し替える(tokens は既存)
- ノート上書き: `[data-pkc-layout='…']` が同じ `--read-w` をより近い祖先で上書き
- 書き出し HTML: 読み幅規則は焼き込みで届く(裁定済みの統一と同じ経路)。
  `data-pkc-layout` は既に書き出しへ配られている。グローバル値は書き出し時の引数で渡し
  (allowExternalImages の前例)、器に属性として焼く
- 変えたら描き直す(setExternalImages の `invalidateDetail() + render()` 作法)

### 効く面(全数 ── 「読む場所を数え、数えた数だけ test を持つ」)

| 面 | 適用 |
|---|---|
| 読む面(detail)/ 添付の説明 | ○(--read-w 差し替えで自動) |
| 書き出し HTML(画面・印刷) | ○(焼き込み + 属性) |
| アプリの印刷 | ○(--read-w のまま + 紙系は @page) |
| 編集 split プレビュー / ライブエディタ | **○ に揃える(推薦)** ── 現在この 2 面は cap 無しで読む面と非対称。同じ文書は同じ幅で見えるべき |
| ヘルプ(マニュアル面) | ✗(アプリの文書であり user 文書ではない。現状のまま) |
| 未選択の案内 | ✗(1 行の案内。現状のまま) |

## 3. 実装計画(2 段)

- **段 1(M)**: グローバル設定 + `--read-w` 差し替え + 紙系 @page + settings UI +
  面ごとの test(smoke 1 本含む)+ お知らせ
- **段 2(M)**: `layout:` 拡張(新値の受理 + 消費 CSS + ノート上書きの優先順位)+
  書き出しへの引数渡し + goldens/parity の追随
- 段 1 だけでも「フル HD で幅が使えない」は解消する(設定でフル HD を選べば cap 解除)

## 4. 覆る条件・裁定してほしい点

1. **「A4 縦 = 現行 42rem(器 cap 無し)」で良いか** ── もし「A4 縦を選んだら PKC2 の
   ように紙の形の器(794px カード + 中央寄せ)で見たい」なら、器方式を追加する
   (mermaid 焼き直しのコストを受け入れる)。**推薦は R 方式**(上記理由 1〜3)
2. 値の表(§2)の具体値 ── 使ってみて調整する前提の初期値として妥当か
3. split プレビュー / ライブエディタも同じ R に揃える推薦で良いか
4. 段 1 → 段 2 の順で良いか(先にグローバル、次にノート単位)
