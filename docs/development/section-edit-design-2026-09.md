# 章だけ編集・章の別ウィンドウ・コード枠のその場編集(設計、2026-09-25)

> 出どころ:#1044(#1038 台帳③ 段 1 の C7 / C8。`touch-and-unity-design-2026-09.md` §3.2 / §8 段 I)。
> #582 §3.3 が「開かずに済ませる道(常設の追記欄・章だけ編集)」を**採る**と裁定済みで、無かったのは設計だけ。
> ⚠ **実装はしない**(doc-first)。§4 の 4 問に答えをいただいてから段ごとに入れる。

## 0. 何のためか

思想⑥「**編集の大半は追記と差し挟み ── 開かずに済ませる道を持つ**」(PKC3 `CLAUDE.md`)。
⚠ この句は PKC2 の実装の注釈(`renderer.ts:8370`、`tests/adapter/text-append.test.ts:4-6`)に
「user direction(2026-06-24)」として**開発側が要約して**書いたもので、user の逐語ではない
(2026-09-25 の PKC2 調査で確認。逐語の出典は PKC2 の浅い履歴の外)。

いまの PKC3 で、見出しを右クリックして「ここから編集する」を押すと、
**アプリ全体が編集中になる**(帯の「編集」と 1 バイトも違わない。違うのは開いた位置だけ ── `binder.ts` の `startEditAt`)。
その間は:

- 一覧で別のノートを選べない(`SELECT_ENTRY` は編集中を断る)
- 右の列のボタンが全部押せなくなる
- 本文の下の追記欄が消える
- **ほかのノート**のチェックや表のセルも押せない(#1043 で直す予定の分)

── 章の 1 行を直したいだけなのに、画面ごと「書く状態」へ切り替わる。

## 1. 物語(いま → 案)

**物語 A ── 長いノートの 1 章だけ直す。**
いま:見出しを右クリック →「ここから編集する」→ 全文の編集欄に切り替わり、その章の位置へ飛ぶ →
直して「保存」→ 読む画面へ戻る。**途中で別のノートを見に行けない**。
案:見出しを右クリック →「**この章を編集する**」→ **その章の所だけ**が編集欄になる
(見出しから次の同じ深さの見出しの手前まで)。ほかの章は読むままで、一覧で別のノートを選ぶことも、
右の列を使うこともできる。「**章を保存する**」で戻る / 「**章の編集をやめる**」で捨てる。

**物語 B ── 書きながら、同じノートの別の章を横に置いて読む。**
いま:同じノートを 2 か所で見る手段は、付箋(別のウィンドウ)でノートを丸ごと開くことだけ。
案:見出しを右クリック →「**この章を別のウィンドウで開く**」→ その章だけが小さなウィンドウに出る。

**物語 C ── コード枠(``` の囲み)の設定を 1 か所だけ直す。**
いま:全文編集に入り、囲みを探して直す。
案:読む画面でコード枠に乗せると、コピーのボタンの隣に「✎」が出る → 押すと**その枠だけ**が編集欄になる。

## 2. PKC2 の証拠(動線と、踏んでいた穴)

PKC2 は 3 つとも持っていた(read-only で調べた。file:line は §7)。

| | PKC2 の動き | 🔴 踏んでいた穴 |
|---|---|---|
| 章だけ編集(本文の中) | 追記欄の「挿入先」で章を選んで「✎ 章を編集」→ 中央が**その章だけの編集欄に丸ごと差し替わる**。アプリ全体は編集中にならない | ① 書いている途中で別のノートを選ぶと、**確認なしに書きかけが捨てられる** ② 保存は「**何番目の章か**」で当て直すだけで中身を比べない ── 別の場所で見出しが増減していると、**違う章を黙って上書き**しうる |
| 章を別のウィンドウで | 見出しの右クリック「✎ この章を編集(別ウィンドウ)」→ 章だけを本文にした仮のノートを別窓で編集 | ②と同じ上書き。しかも**競合の警告が 1 つも出ない**。閉じるときの未保存の扱いは「別 issue」のまま未解決 |
| コード枠の ✎ | 読む画面で枠に乗せると ✎ → 小さな編集の窓 → 保存 | 🟢 **開いた時の中身と比べてから保存**(違えば断る)── これだけは正しかった。本体の画面だけに出す(別窓・読むだけの窓では出さない)も設計どおり |

🔑 **採るのは動線、採らないのは形**:PKC2 の「章だけを本文にした仮のノート(合成 lid)」は使わない(PKC3 `CLAUDE.md`「実装形の丸写し禁止」)。

## 3. 聞かずに決まる物(穴を塞ぐ側・既存の作法に寄せる側)

| 決めたこと | なぜ聞かないか |
|---|---|
| **章を探し直すのは見出しの名前で**(何番目かではなく)。保存の前に「開いた時の章の中身」と「いまの章の中身」を比べ、**違えば 1 文字も書かずに断る**(書きかけは欄に残す。断り文は「この章は別の場所で書き換えられました ── 書きかけをコピーしてから、開き直してください」) | PKC2 の穴②を塞ぐ修理。比べ方はコード枠の ✎(PKC2 で唯一正しかった物)と、PKC3 の表のセル・板の付箋の「開いた時の字と一致しなければ書かない」と同じ作法 |
| **同じノートを別のタブで全文編集中なら、章の欄は開かない**(理由を出す)。逆も同じ(章の欄を開いている間、別のタブはそのノートを編集に入れない) | 編集ロックは**ノート単位のまま**使う(章単位にすると、同じノートの 2 章を 2 か所で書けるが、保存の比べ合いが 2 重になり、得る物より壊れ方が増える) |
| 章の欄を開いている間、**同じノート**に書く他の操作(チェック・表のセル・追記・板)は断る。**ほかのノート**は自由 | 同じ章を 2 か所から書かない。#1043(編集中でも他のノートは止めない)と同じ「そのノートだけ止める」門を使う ── **#1043 の後に入れる** |
| 章の欄は、描き直されても**打ちかけの字と文字カーソルを保つ** | 表のセルのその場編集(`cell-input.ts`、#745)が既に同じことをしている。土台にする |
| 「章を保存する」は**履歴に 1 版積む**(全文編集の保存と同じ) | 書いた字を戻せる道を減らさない。表のセル・チェックは積まない(1 押しの変更)が、章は文章の書き換えである |
| 章の範囲 = 見出し(# 〜 ###)から、**次の同じ深さか浅い見出しの手前まで**。囲み(``` / ~~~)の中の # は見出しに数えない | 追記欄の「入り先」の章の決め方(`append-target.ts`)と**同じ関数**を使う(2 つ目の規則を作らない) |
| 章の欄には**書式のボタンの帯を出さない**(近道のキーは効く) | 章の欄は「少し直す」ための物。帯を出すと章ごとに 20 個のボタンが本文の中に並ぶ。覆る条件は §6 |
| コード枠の ✎ は**本体の読む画面だけ**に出す(別のウィンドウ・読むだけの窓には出さない) | PKC2 が同じ理由で決めていた(押しても書く先が無い所に出すと、押して何も起きない) |

## 4. user に伺う 4 問

**Q1. 見出しの右クリックの「ここから編集する」をどうするか**
- **A(推薦)**:残して、その上に「**この章を編集する**」を足す。
  理由:「ここから編集する」は**マウスだけで**その見出しの位置から全文編集に入れる唯一の道
  (もう 1 つの道の Ctrl+クリックはキーが要る)── 思想③「マウスだけで完結し、キーボードは近道」
- B:「ここから編集する」を章だけの編集に置き換える(メニューが 1 行短い。全文編集は本文の上の「編集」から)

**Q2. 章を書きかけのまま、一覧で別のノートを選んだら**
- **A(推薦)**:「**書きかけの章があります**」と聞く ──「章を保存して移る」/「捨てて移る」/「移らない」。
  理由:書きかけを黙って捨てない(PKC2 の穴①)。持ったまま移ると、書きかけがどのノートに残っているか画面から見えなくなる
- B:聞かずに移り、書きかけを持っておく(戻ってきたら欄が開いたまま。タブを閉じると消える)

**Q3. 章を別のウィンドウで開いたとき**
- **A(推薦)**:**読むだけ**で開く。書くのはいまのウィンドウの章の欄で。
  理由:別のウィンドウでも書けると、同じノートを 2 か所で書くことになり、保存の比べ合いをウィンドウの間で持つ必要がある(PKC2 はここで黙って上書きしていた)。まず読むだけで入れ、書きたい声が出たら段を分けて足す
- B:別のウィンドウでも書ける(保存の前に比べて、違えば断る)

**Q4. コード枠の ✎ を入れるか**
- **A(推薦)**:入れる。読む画面でコード枠に乗せると「✎」が出て、その枠だけが編集欄になる(保存の前に比べて、違えば断る)。
  理由:PKC2 で user が求めた機能(2026-07-25「アセットとコードブロック両方を対象とした簡易的な編集機能をつけます」── PKC2 `docs/development/code-edit-lite-design-2026-07.md:12`)
- B:入れない(全文編集で直す)

## 5. 段取り(裁定の後)

| 段 | 中身 | 前提 |
|---|---|---|
| 1 | **#1043**(編集中でも**他の**ノートの書込を止めない ── 門を「どのノートか」で見る形へ) | 済んでいないと、章の欄が「同じノートだけ止める」を持てない |
| 2 | 章の欄(Q1 / Q2 の答え)── 状態に「章の下書き」を 1 つ足す(アプリ全体の編集中とは別)。保存は「見出しの名前で探し直す → 開いた時の中身と比べる → 書く + 履歴に積む」。別のタブの書込を受ける口(`REMOTE_BODY_CHANGED`)にも章の下書きの分岐を足す | 段 1 |
| 3 | コード枠の ✎(Q4)── 本文の書き換えに「コード枠を丸ごと差し替える」種類を 1 つ足す(引用の中の枠は #775 と同じく前置きを剥がして読む) | 段 2 の「打ちかけを保つ」作りを共有 |
| 4 | 章を別のウィンドウで(Q3)── 付箋の仕組みに「どの章か」を 1 つ足す(同じ章の 2 枚目を作らない鍵を `(ノート, 章の名前)` に)。アドレスで渡すなら `section=` を 1 つ足す(合成 lid にしない) | 段 2 |

各段:実ブラウザの smoke 1 本(章の欄を開く → 別のノートを選ぶ → 戻る / 保存が断られる場面)+ お知らせ 1 件 + マニュアル。

## 6. 覆る条件

- 章の欄で書式のボタンが欲しいという声 → 帯を出す(本文の中に出すか、欄の上に畳んで出すかは実測してから)
- 章の範囲の決め方(見出しの深さ)が追記欄と違ってほしいという声 → 同じ関数のまま引数で分ける
- 別のウィンドウで書きたいという声 → Q3 の B を段 5 として足す
- 同じノートの別の章を 2 か所で同時に書きたいという声 → ロックを章単位にする設計をやり直す(§3 の 2 行目)
