# 章だけ編集・章の別ウィンドウ・コード枠のその場編集(設計、2026-09-25)

> 出どころ:#1044(#1038 台帳③ 段 1 の C7 / C8。`touch-and-unity-design-2026-09.md` §3.2 / §8 段 I)。
> #582 §3.3 が「開かずに済ませる道(常設の追記欄・章だけ編集)」を**採る**と裁定済みで、無かったのは設計だけ。
> ⚠ **実装はしない**(doc-first)。§4 の 4 問に答えをいただいてから段ごとに入れる。

## 0. 何のためか

思想⑥「**編集の大半は追記と差し挟み ── 開かずに済ませる道を持つ**」(PKC3 `CLAUDE.md`)。
⚠ この句は PKC2 の実装の注釈(`renderer.ts:8370`、`tests/adapter/text-append.test.ts:4-6`)に
「user direction(2026-06-24)」として**開発側が要約して**書いたもので、user の逐語ではない
(2026-09-25 の PKC2 調査で確認。逐語の出典は PKC2 の浅い履歴の外)。

いまの PKC3 で、見出しを右クリックして「ここから編集する」を押すと、
**アプリ全体が編集中になる**(帯の「編集」と 1 バイトも違わない。違うのは開いた位置だけ ── `binder.ts` の `startEditAt`)。
その間は:

- 一覧で別のノートを選べない(`SELECT_ENTRY` は編集中を断る)
- 右の列のボタンが全部押せなくなる
- 本文の下の追記欄が消える
- **ほかのノート**のチェックや表のセルも押せない(#1043 で直す予定の分)

── 章の 1 行を直したいだけなのに、画面ごと「書く状態」へ切り替わる。

## 1. 物語(いま → 案)

**物語 A ── 長いノートの 1 章だけ直す。**
いま:見出しを右クリック →「ここから編集する」→ 全文の編集欄に切り替わり、その章の位置へ飛ぶ →
直して「保存」→ 読む画面へ戻る。**途中で別のノートを見に行けない**。
案:見出しを右クリック →「**この章を編集する**」→ **その章の所だけ**が編集欄になる
(見出しから次の同じ深さの見出しの手前まで)。ほかの章は読むままで、一覧で別のノートを選ぶことも、
右の列を使うこともできる。「**章を保存する**」で戻る / 「**章の編集をやめる**」で捨てる。

**物語 B ── 書きながら、同じノートの別の章を横に置いて読む。**
いま:同じノートを 2 か所で見る手段は、付箋(別のウィンドウ)でノートを丸ごと開くことだけ。
案:見出しを右クリック →「**この章を別のウィンドウで開く**」→ その章だけが小さなウィンドウに出る。

**物語 C ── コード枠(``` の囲み)の設定を 1 か所だけ直す。**
いま:全文編集に入り、囲みを探して直す。
案:読む画面でコード枠に乗せると、コピーのボタンの隣に「✎」が出る → 押すと**その枠だけ**が編集欄になる。

## 2. PKC2 の証拠(動線と、踏んでいた穴)

PKC2 は 3 つとも持っていた(read-only で調べた。file:line は §7)。

| | PKC2 の動き | 🔴 踏んでいた穴 |
|---|---|---|
| 章だけ編集(本文の中) | 追記欄の「挿入先」で章を選んで「✎ 章を編集」→ 中央が**その章だけの編集欄に丸ごと差し替わる**。アプリ全体は編集中にならない | ① 書いている途中で別のノートを選ぶと、**確認なしに書きかけが捨てられる** ② 保存は「**何番目の章か**」で当て直すだけで中身を比べない ── 別の場所で見出しが増減していると、**違う章を黙って上書き**しうる |
| 章を別のウィンドウで | 見出しの右クリック「✎ この章を編集(別ウィンドウ)」→ 章だけを本文にした仮のノートを別窓で編集 | ②と同じ上書き。しかも**競合の警告が 1 つも出ない**。閉じるときの未保存の扱いは「別 issue」のまま未解決 |
| コード枠の ✎ | 読む画面で枠に乗せると ✎ → 小さな編集の窓 → 保存 | 🟢 **開いた時の中身と比べてから保存**(違えば断る)── これだけは正しかった。本体の画面だけに出す(別窓・読むだけの窓では出さない)も設計どおり |

🔑 **採るのは動線、採らないのは形**:PKC2 の「章だけを本文にした仮のノート(合成 lid)」は使わない(PKC3 `CLAUDE.md`「実装形の丸写し禁止」)。

## 3. 聞かずに決まる物(穴を塞ぐ側・既存の作法に寄せる側)

| 決めたこと | なぜ聞かないか |
|---|---|
| **章を探し直すのは見出しの名前で**(何番目かではなく)。保存の前に「開いた時の章の中身」と「いまの章の中身」を比べ、**違えば 1 文字も書かずに断る**(書きかけは欄に残す。断り文は「この章は別の場所で書き換えられました ── 書きかけをコピーしてから、開き直してください」) | PKC2 の穴②を塞ぐ修理。比べ方はコード枠の ✎(PKC2 で唯一正しかった物)と、PKC3 の表のセル・板の付箋の「開いた時の字と一致しなければ書かない」と同じ作法 |
| **同じノートを別のタブで全文編集中なら、章の欄は開かない**(理由を出す)。逆も同じ(章の欄を開いている間、別のタブはそのノートを編集に入れない) | 編集ロックは**ノート単位のまま**使う(章単位にすると、同じノートの 2 章を 2 か所で書けるが、保存の比べ合いが 2 重になり、得る物より壊れ方が増える) |
| 章の欄を開いている間、**同じノート**に書く他の操作(チェック・表のセル・追記・板)は断る。**ほかのノート**は自由 | 同じ章を 2 か所から書かない。#1043(編集中でも他のノートは止めない)と同じ「そのノートだけ止める」門を使う ── **#1043 の後に入れる** |
| 章の欄は、描き直されても**打ちかけの字と文字カーソルを保つ** | 表のセルのその場編集(`cell-input.ts`、#745)が既に同じことをしている。土台にする |
| 「章を保存する」は**履歴に 1 版積む**(全文編集の保存と同じ) | 書いた字を戻せる道を減らさない。表のセル・チェックは積まない(1 押しの変更)が、章は文章の書き換えである |
| 章の範囲 = 見出し(# 〜 ###)から、**次の同じ深さか浅い見出しの手前まで**。囲み(``` / ~~~)の中の # は見出しに数えない | 追記欄の「入り先」の章の決め方(`append-target.ts`)と**同じ関数**を使う(2 つ目の規則を作らない) |
| 章の欄には**書式のボタンの帯を出さない**(近道のキーは効く) | 章の欄は「少し直す」ための物。帯を出すと章ごとに 20 個のボタンが本文の中に並ぶ。覆る条件は §6 |
| ~~コード枠の ✎ は**本体の読む画面だけ**に出す(別のウィンドウ・読むだけの窓には出さない)~~ ⚠ **2026-09-26 に覆った**(§8 の追記)── 書ける窓(本体と小窓)に出し、読むだけの窓・書き出した HTML・印刷には出さない | PKC2 が同じ理由で決めていた(押しても書く先が無い所に出すと、押して何も起きない)。⚠ **PKC3 の小窓には当たらなかった** ── 小窓は本体と同じアプリで、追記もチェックの印も効く「書ける窓」である(PKC2 の別窓は書く口を持たない独立した document だった) |

## 4. user に伺う 4 問

**Q1. 見出しの右クリックの「ここから編集する」をどうするか**
- **A(推薦)**:残して、その上に「**この章を編集する**」を足す。
  理由:「ここから編集する」は**マウスだけで**その見出しの位置から全文編集に入れる唯一の道
  (もう 1 つの道の Ctrl+クリックはキーが要る)── 思想③「マウスだけで完結し、キーボードは近道」
- B:「ここから編集する」を章だけの編集に置き換える(メニューが 1 行短い。全文編集は本文の上の「編集」から)

**Q2. 章を書きかけのまま、一覧で別のノートを選んだら**
- **A(推薦)**:「**書きかけの章があります**」と聞く ──「章を保存して移る」/「捨てて移る」/「移らない」。
  理由:書きかけを黙って捨てない(PKC2 の穴①)。持ったまま移ると、書きかけがどのノートに残っているか画面から見えなくなる
- B:聞かずに移り、書きかけを持っておく(戻ってきたら欄が開いたまま。タブを閉じると消える)

**Q3. 章を別のウィンドウで開いたとき**
- **A(推薦)**:**読むだけ**で開く。書くのはいまのウィンドウの章の欄で。
  理由:別のウィンドウでも書けると、同じノートを 2 か所で書くことになり、保存の比べ合いをウィンドウの間で持つ必要がある(PKC2 はここで黙って上書きしていた)。まず読むだけで入れ、書きたい声が出たら段を分けて足す
- B:別のウィンドウでも書ける(保存の前に比べて、違えば断る)

**Q4. コード枠の ✎ を入れるか**
- **A(推薦)**:入れる。読む画面でコード枠に乗せると「✎」が出て、その枠だけが編集欄になる(保存の前に比べて、違えば断る)。
  理由:PKC2 で user が求めた機能(2026-07-25「アセットとコードブロック両方を対象とした簡易的な編集機能をつけます」── PKC2 `docs/development/code-edit-lite-design-2026-07.md:12`)
- B:入れない(全文編集で直す)

## 6. 覆る条件

- 章の欄で書式のボタンが欲しいという声 → 帯を出す(本文の中に出すか、欄の上に畳んで出すかは実測してから)
- 章の範囲の決め方(見出しの深さ)が追記欄と違ってほしいという声 → 同じ関数のまま引数で分ける
- 別のウィンドウで書きたいという声 → Q3 の B を段 5 として足す
- 同じノートの別の章を 2 か所で同時に書きたいという声 → ロックを章単位にする設計をやり直す(§3 の 2 行目)

## 9. 段 3「コード枠の ✎」の作り(2026-09-26)

段 2 の着地前に 5 巡の修理で固めた作り(離れる操作を外側 1 か所で止める / 保存は保存先から読み直す / 書きかけの判定を 1 つに揃える / 断り文の寿命 / 打ち切り / 箱の大きさ)を、**コード枠でも同じ物を使う**。2 つ目の仕組みを作らない。

| 決めたこと | 理由 |
|---|---|
| ✎ を出すのは**普通のコード枠**と、図や表にせず**原文のまま出している枠**(`-norender` / csv の読み損ね)だけ。mermaid などの図・csv の表・添付から中身を取る枠には出さない | 図と表は画面が原文ではない(表はセルのその場編集が既に在る)。添付から取る枠は本文に中身が無い |
| ✎ は ⧉(コピー)の隣に、⧉ と同じ出方(乗せたとき・焦点が入ったとき。指で触る端末では最初から) | 同じ枠の同じ種類の押し所を、別の出方にしない |
| 押すと**その枠の中身だけ**がその場の入力欄になる(``` の行はそのまま)。引用の中の枠は `> ` を剥がして見せ、保存で付け直す(#775 と同じ) | 言語の指定や柵を打ち間違えて、枠そのものを壊さない |
| 保存は**保存する瞬間に保存先から本文を読み直し**、開いた行の枠が開いたときの中身と同じなら差し替える。行がずれていたら**同じ柵・同じ中身の枠を探し直し**、1 つに決まれば差し替える(0 個 = 別の場所で書き換えられた / 2 個以上 = 決まらない、は 1 文字も書かずに断る) | 段 2 と同じ守り。PKC2 は位置だけで探したので、別の窓が上に行を足すと偽の断りが出た |
| 「コードを保存する」/「コードの編集をやめる」。書きかけのまま離れようとしたら「コードを保存して移る / 書きかけを消して移る / 移らない」 | 章の欄と同じ形。出口のボタン名を断り文でも言う |
| 章の欄とコード枠の欄は、**同じノートで同時に 1 つだけ**(状態の「部分の下書き」を 1 つにし、種類で分ける) | 2 つ開けると、章の欄の箱が枠の箱を飲み込む / 保存の比べ合いが 2 重になる |


## 10. 段 4「章の別ウィンドウ(読むだけ)」の作り(2026-09-27)

裁定(§8 Q3)は「**読むだけ**で開く。書くのはいまのウィンドウの章の欄で」。調べた材料(PKC3 の小窓・読むだけの面・章の範囲、PKC2 の実物)から、次の形にする。

### 10.1 窓の作り ── アプリをもう 1 つ起動しない

| 決めたこと | 理由 |
|---|---|
| **開いた側(本体 / ノートの別ウィンドウ)が空の窓を掴み、中身を組む**(添付の窓・マニュアルの窓と同じ作法)。アプリ(PKC)をもう 1 つ起動しない | ① 読むだけが**作りで**守られる ── 窓の中には押し所の受け手(binder)も近道の鍵も貼り付けの受け手も**居ない**ので、書く口を 1 つずつ塞ぐ必要が無い(塞ぎ忘れが起こりようがない)。ノートの別ウィンドウ(小窓)は書ける窓なので、そちらを流用すると追記欄・チェック・セル・✎・貼り付け・落とす・近道の鍵……と 10 か所以上を塞ぐことになる ② もう 1 つの PKC は常駐の記憶域(保存の worker 等)をもう 1 組持つ ③ #292 で user が「もう一つ PKC が開いて混乱する」と言っている(`manual-window.ts` の注記) |
| 中身は**本体と同じ描画**(同じ worker・同じ関数)でノート全文を描き、**章の範囲の塊だけ**を窓へ移す | 章だけを描き直すと、見出しの番号・見出しの id・`{{vars}}` が全文の描画と食い違う(調べた)。範囲の決め方は章の欄と**同じ 1 本**(`sectionRange` → 剥がした本文の行 → `data-pkc-source-line` で直下の塊を拾う、`section-box.ts` の `blocksInRange`) |
| 押して書く口は**焼かない**(チェック・表のセル・コード枠の ✎・本文のタグは、描画に「押せる形」の旗を渡さない)。コード・表・図の頭の ⧉ は**取り除く** | 書き出した HTML・マニュアルの窓と同じ作法(binder の居ない面では押せない形のまま出す / ⧉ は沈黙する飾りになるので取り除く) |
| 見た目は `BODY_CSS`(本文の CSS の正本)に、**本体でいま効いている配色の値**を写す | `BODY_CSS` だけだと明暗が OS の設定に従い、設定で選んだ配色にならない(マニュアルの窓がそう) |
| 画像(添付)は窓ごとに借り、**窓を閉じたら・組み直したら返す**。図(mermaid・グラフ・数式)は本体と同じ後付けの関数を当てる | ObjectURL は表示の寿命終端で破棄する(不可侵指示 2026-07-27)。本体の IntersectionObserver と blob URL が別の窓の要素でも効くことは実ブラウザで確かめた |

### 10.2 窓の中で押せる物

| 押す物 | 何が起きるか |
|---|---|
| 章の中を指すページ内リンク(`#…`) | 窓の中でそこへ移る |
| 章の**外**を指すページ内リンク(`:::toc` の一部など) | 押せない字にする(窓に飛び先が無いので、押しても何も起きない形を残さない) |
| 外のリンク(`https://…`) | 別のタブで開く |
| ノート・カード・添付へのリンク | **本体のウィンドウで**開く(本体を手前へ出す)── 本体で押したときと同じ受け手を通す |
| Esc | 窓を閉じる(ノートの別ウィンドウと同じ) |

### 10.3 鍵・追従・終わり方

| 決めたこと | 理由 |
|---|---|
| 同じ章をもう一度開くと、**同じ窓**が手前に出て、中身を**いまの本文で組み直す** | 2 枚目を作らない。PKC2 は同じ窓を手前に出すだけで古いままだった |
| 章は「見出しの字 + 同じ字の中で何番目か」で追う(`headingRefAt` / `resolveHeadingRef`、章の欄と同じ 1 本) | 行番号で追うと、上に行が足されただけで別の章を出す(PKC2 の穴) |
| 本体が開いている間は、**そのノートが書き換わったら組み直す**(このウィンドウ・別のタブ・別のウィンドウのどれで書いても) | 「書きながら横に置いて読む」ので、書いた結果が窓に出ないと役に立たない。PKC2 は 1 度も更新されなかった |
| 章を見失ったら(見出しの字が変わった・消えた・同じ字の見出しが増えた)、窓に「この章が見つかりません」と出す。ノートが消えたら「このノートはもうありません」 | 黙って古い中身を出し続けない |
| 本体のウィンドウを閉じる・読み直すと、窓に「本体のウィンドウが閉じたため、この窓は新しくなりません」と出す | 追従する側が居なくなったことを言う(黙って古くならない) |
| 窓で F5 を押して白くなったら、本体が開いていれば組み直す | 空の窓は F5 で白紙に戻る(マニュアルの窓の段①が踏んだ)。本体の見張りで気づいて組み直す |
| ポップアップが塞がれたら理由を出す。**本体の中央へ退避しない** | ノートの別ウィンドウと同じ(CLAUDE.md「別窓が塞がれたときの退避先を、中央にしない」) |
| 入口は見出しの右クリック「**この章を別のウィンドウで開く**」。出す条件は「この章を編集する」と同じ**形の**条件(本文の直下の `#` 〜 `###`)。ただし書けるかどうか(編集中・ロック)には**依らない** | 読むだけなので、書けない状態でも開ける。範囲の決め方が章の欄と同じなので、出す見出しも同じにする |

### 10.4 覆る条件

- 窓で書きたいという声 → §6 のとおり段 5 として足す(そのときは小窓の流用を再検討する)
- 窓を F5 で読み直しても本体が無いと白紙のまま、が困るという声 → 章の窓を焼いた 1 枚(マニュアルの段②と同じ)にする
