## 0. 出発点 ── 読み落としていたヒント

user の言葉の中に、こちらの語彙に無い名詞が 6 つ出ていた。どれも「型」の指定だった。

| # | user の言葉 | 型として読むと |
|---|---|---|
| ① | 「**システム用ノート**」(メッセージの置き場) | メッセージは user のノートと**型が違うノート**。同じ container に入るが、**別の領域**(realm)に属する |
| ② | 「**アセットも含めて資産**」(バックアップの中身) | バックアップの中身は**型の積**(ノート × 添付 × つながり × 履歴)。どれを含むかで**別の型の file**になる |
| ③ | 「**二重拡張子**で分ければ」(`.pkc3-full.zip` / `-part` / `-notes`) | file の型を名前に書く |
| ④ | 「**設定をシステムに変更して、その中に作り込めば**」 | 「設定」は好みの袋ではなく、**システムという領域**の入り口。設定・メッセージ・保存領域・Office の一式は**同じ領域の別の型**の値 |
| ⑤ | founding doc「**全 body = PKC-Markdown、アーキタイプ = フレーバー**」 | ノートの型ごとに、抽出(`extract`)・取込の変換(`fromPkc2`)・初期の本文(`seed`)が**宣言**される(`FlavorSpec`、全 47 行。⚠ 見せ方・編集の宣言は**ここには無い** ── 実測)。この「型ごとに宣言する」形が型システムの器である |
| ⑥ | 「**メッセージングの集積地**」「PKC は KB + messaging の node」 | 知らせも型を持つ値 |

🔑 **検算(この稿の全部に当てる)**:画面の要素・ボタン・file・名前を、**どの型の値に付く物か**で言えるか。
言えない物(「その他」「データ」「管理」に落ちる物)は、型が未定義である ── 袋を作らず、型を定義する。

## 1. 型の一覧

### 1.1 領域(realm)── 2 つ

| 領域 | 何か | 誰が書くか | 画面での扱い |
|---|---|---|---|
| **user** | user が書いた物・user の資産 | user | 左の列(一覧 / フォルダ / 予定 / 連絡先 …)・検索・バックアップに**入る** |
| **system** | アプリが自分について持つ物・アプリが user に言う物・この端末の状態 | アプリ | 左の列・検索・バックアップに**入らない**。入り口は **「システム」** 1 つ(裁定 2026-09-20「user のディレクトリと明確に分ける」) |

⚠ 領域の判定は **1 か所**(entries の列)で持つ。読み手(一覧 / フォルダ / 検索 / バックアップ / スマートフォルダ / 集計)が
それぞれ別の条件で除外する形にしない ── 除外の口が 2 つになると、片方だけ壊れて「バックアップに環境の記録が漏れる」形で出る(CLAUDE.md §7)。

### 1.2 領域の中の「開放先」── user 向け / 開発者向け

user 裁定 2026-08-07:**設定は user に開放された物、フラグは開発者とパワーユーザーに開放された物。別々に見えるようにせよ**(P11 裁定 Q3)。
これは system 領域の中の**第 2 の軸**である。

| 開放先 | 型 | 入り口 |
|---|---|---|
| **user** | メッセージ(ワーカーの記録も**種類「処理」として**ここ ── 裁定 2026-09-20)/ 設定 / 許可 / 記録 / 保存領域 / Office の一式 / お知らせ | **「システム」** |
| **開発者** | フラグ | **「フラグ」**(いまのまま別の画面) |

⚠ v5 は「処理(ワーカー)」を開放先で開発者側へ置いたが、裁定は**メッセージの一種(種類が違うだけ)**だった ──
「アプリが自分の中で起きたことを user に言う」という型で見れば、ワーカーの記録も結果・問題と同じ型である。開放先の軸は**フラグにだけ**効く。

### 1.3 型の表

| 型 | 何か | 実体(どこに在るか) | 領域 | 持ち出せるか |
|---|---|---|---|---|
| **コレクション** | user の資産の全部 = **ノート × 添付 × つながり × 履歴** | sqlite(`containers` + 4 表)+ IndexedDB(添付の bytes) | user | ○(§5 の file 型) |
| **ノート** | 題名 × **フレーバー** × 本文(PKC-Markdown) × 領域 | `entries` | user / **system** | ○ |
| ├ フレーバー | ノート / ログ / 表 / フォルダ / スマートフォルダ / スタック / アプリのグループ / 添付 / 雛形 / Todo / フォーム(`ARCHETYPE_LABELS` 11 種) | `FlavorSpec`(extract / seed / 見せ方 / 編集) | ── | ── |
| **添付** | ノートに付く file の実体 | `assets`(目録)+ IndexedDB(bytes) | user | ○ |
| **つながり** | ノート間の関係(from / to / kind) | `relations` | user | ○ |
| **履歴** | ノートの過去の版 | `revisions` | user | ○ |
| **タグ** | 本文から導かれる語(`body_tags`)── 独立の値ではない | 派生列 | user | (本文に含まれる) |
| **保存領域** | コレクションを置いている**この端末の入れ物** | OPFS の sqlite + IndexedDB | system | ✗(端末固有) |
| **設定** | この端末での**好み**(見た目 / 編集の仕方 / 通知 / 開き方) | localStorage `pkc3.*` のうち **22 件**(`PORTABLE_KEYS`) | system | ○(`PKC3-settings-<日付>.json`) |
| **許可** | この端末で user が**許した事実**(外部の画像 / ノートを渡すアプリ / 目次を見せるアプリ / 埋め込み元) | localStorage 4 件(`SKIPPED_KEYS` の「許可」) | system | ✗(渡してはいけない) |
| **記録** | この端末での**行動の事実**(最近開いた 200 件 / コピーの履歴 20 件 / お知らせの既読 60 件 / 狭い画面の了承) | localStorage 4 件 | system | ✗(lid を持つ / その端末の事実) |
| **メッセージ**(新) | アプリが user に言うこと(結果 / 注意 / 問題 / 配信) | **system 領域のノート(フレーバー = ログ)1 件**(§7) | system | ○(バグ報告に貼る) |
| **お知らせ** | 開発側からの配信(版に同梱) | `notice-log.ts`(既読は「記録」) | system | ── |
| **一式** | 端末に置く大きな部品(Office の wasm / DuckDB の wasm) | IndexedDB の cache | system | ✗(置き直せる) |
| **フラグ** | 開発者向けの切替(最大 15 / `foldWhen` 必須) | localStorage `pkc3.flags` | system(開発者) | ✗ |
| **アプリ** | 版 / マニュアル / ショートカットの表 | 配布物 | system | ── |

🔑 **`settings-file.ts` の `PORTABLE_KEYS` / `SKIPPED_KEYS` は、既に「設定 / 許可 / 記録」の型宣言である**(全 37 鍵を 2 表に分け、CI が全数を pin している)。
この稿はそれを画面の分類にも使う ── 新しい分類を作るのではなく、**在る型宣言を画面へ写す**。

⚠ `sqlite` の `settings` 表と `flags` 表は user 向けの値を持たない(`settings` は索引の版と点検の時刻だけ、`flags` は読み書き 0 件、`workspaces` は未使用)── 型の表に載せない。

## 2. 型が決める 4 つ

| 型から導く物 | 規則 |
|---|---|
| **置き場**(§3) | user 領域のノートは左の列。system 領域は「システム」の中に**型ごとの節**。**右の列は「いま選んでいる値の型」の操作** |
| **操作**(§4) | 操作は**型に付く**。同じ操作(書き出す / 削除 / 履歴)は、どの型の値を選んでいても**同じ場所・同じ名前**で出る(思想③「同じ物が同じ場所」) |
| **出し入れ**(§5) | file の型 = **含まれる型の積**。名前の末尾(二重拡張子)がそれを言う |
| **名前**(§6) | 見出し = **型の名前**、ボタン = **動詞だけ**。造語・動詞句・評価語を使わない |

## 3. 置き場 ── 型から導く

### 3.1 画面の 5 か所と、そこに出る型

| 場所 | 出る物 | 規則 |
|---|---|---|
| **左の列(タブ)** | user 領域のノート(一覧 / フォルダ / 予定 / 連絡先 / 2 ペイン …) | いまのまま。system 領域のノートは**出ない** |
| **中央** | いま選んでいる値(ノート 1 件 / 集計 / システムの節) | いまのまま |
| **右の列** | **いま選んでいる値の型の操作と情報** | ノートを選んでいれば「そのノート」の操作。⚠ **何も選んでいない = コレクションを選んでいる**ので、コレクションの情報(件数 / 添付の量)と操作(§4)が出る。いまは「左の一覧から選ぶと、ここに情報が出ます。」の 1 文だけ(#582 R2 実測:1280×800 で中身 14%) |
| **左下の帯** | コレクションの出し入れ(取り込む / バックアップ)+ **system 領域の入り口 2 つ**(「システム」= user 向け / 「フラグ」= 開発者向け)+ ヘルプ + 集計 + 操作を探す | 「設定」→ **「システム」**(裁定)。⚠ 新しいボタンは**足さない**(v4 の「保存領域」を帯に足す案は取り下げ ── それは「システム」の中の節である) |
| **ステータスバー** | **いま起きていること**(保存中 / 本体タブ経由)+ **未読 N 件** | 押すと「システム」のメッセージの節が開く。知らせの本文はここに出さない(裁定 2026-09-20「ステータスバーをメッセージの置き場に使うな」) |

左下の帯(いま → 案):**取り込む / バックアップ / 操作を探す / 集計 / 設定 / フラグ / ヘルプ** →
**取り込む / バックアップ / 操作を探す / 集計 / システム / フラグ / ヘルプ**(名前が 1 つ変わるだけ。数は同じ)。

### 3.2 「システム」の中 ── system 領域(user 向け)の型を、型ごとの節にする

| 節(= 型の名前) | 中身(いま「設定」に在る物を型で仕分けた結果) | 操作(ボタンは動詞だけ) |
|---|---|---|
| **メッセージ**(未読 N) | §7。種類 = 結果 / 注意 / 問題 / 配信 / **処理**(ワーカーの記録)。起動のたびの 1 節(版 / 保存先 / フラグ / ブラウザ / 画面幅) | 開く(普通のノートと同じ ── 検索 / 別窓 / 印刷)/ **書き出す**(バグ報告に貼る)/ 種類で絞る |
| **設定** | 好み 22 件 ── 表示(配色 / 紙面 / 本文の置き場所 / 文字の大きさ / 段組み / 段の境界線 / タグの見せ方)/ 編集(編集の仕方 / 開いたときの状態 / 貼り付け / 電話番号 / ショートカットキー)/ 通知(予定の知らせ / 音)/ 開き方(zip を開く場所 / アプリの開き方) | 変える / **持ち出す**(`PKC3-settings-<日付>.json`)/ **取り込む** / 既定に戻す |
| **許可** | この端末で許した事実 ── 外部の画像 / ノートを渡して開くことを許したアプリ / 目次を見せているアプリ | **取り消す** |
| **記録** | この端末の行動の事実 ── 最近開いたノート(200 件)/ コピーの履歴(20 件)/ お知らせの既読 / 狭い画面の了承 | **消す** |
| **保存領域** | この端末の入れ物の状態 ── **使用量**(ノート / 添付 / 履歴の量)/ 起動時の点検の結果(#1015)/ Office の一式・DuckDB の一式(置いてあるか・大きさ) | **点検する** / **片づける**(使っていない添付を消す)/ 一式を**置く** / **消す** / ── 畳んだ中に **作り直す** / **初期化する**(点検で問題が出たときだけ開いた状態で出す) |
| **お知らせ** | 開発側からの配信の一覧(いまはヘルプの中 → ここへ。ヘルプには**リンク 1 行**を残す ── 裁定 2026-09-20) | 読む / 止める |

⚠ **「ヘルプ」は帯に残す**(`shell.ts` の 3 つの理由:困っている人の動線 / 中身が面である / 別窓の退避先)。
お知らせは system 領域の値なので**「システム」に置き**、ヘルプはマニュアル + ショートカット + 版 + **お知らせへのリンク 1 行**にする(裁定 2026-09-20)。

⚠ **「処理(ワーカー)── 開発者向け」は「設定」から消え、メッセージの種類「処理」になる**(裁定 2026-09-20:「ワーカーログはメッセージの一種として。種別違いで 5,000 件保管」)。

🔑 **「システム」の先頭に目次を置く**(user の言葉 2026-09-20「今のところは内部を目次つけて移動しやすくするくらいかな」の解釈)── 節(メッセージ / 設定 / 許可 / 記録 / 保存領域 / お知らせ)へ 1 押しで飛べる行を先頭に並べ、節の見出しには「上へ」を付ける。
⚠ 畳まない(`<details>` は使わない ── user 指示「主要な導線を畳まない」、`tests/docs-parity.test.ts` が落とす)。

🔑 **検算**:各節の下に並ぶ物が **1 つの型**を指すか ── 設定 = 好み 22 件 / 許可 = 4 件 / 記録 = 4 件 / 保存領域 = 端末の入れ物 / メッセージ = 種類ごとのノート。
機械の門:①`PORTABLE_KEYS` の鍵は「設定」の節にしか出ない ②「許可」「記録」の鍵は `SKIPPED_KEYS` に在る ③「システム」の中に書き出しの `action` が居たら落ちる(書き出しはコレクションの操作 ── §4)。

## 4. 操作 ── 型ごとに、同じ場所・同じ名前

### 4.1 規則

- **操作は型に付く。** 「書き出す」はノートにもフォルダにもコレクションにも在る操作で、**選んでいる値の型で範囲が決まる**(ノート 1 件 / フォルダの中 / 全部)
- **右の列は常に「いま選んでいる値」の操作**。何も選んでいない = コレクション
- 頻度の低い操作を左下の帯から逃がす先は「設定」ではなく、**その型の操作が並ぶ場所**(user 指示 2026-08-17「頻度の低いボタンは設定画面へ」は**頻度で分けること**の指示であって、「設定」という名前の場所を指定したのではない ── §8)

### 4.2 いまの操作 267 件を型で数えた(2026-09-20、サブエージェント sonnet が `binder.ts` の受け手を 1 件ずつ読んで分類)

| 型 | 件数 | 押し所(静的走査) | 気づき |
|---|---|---|---|
| ノート | 75 | 26 面(本文 / 右クリック / 情報ペイン / 左の列 / 2 ペイン …) | 右クリックの 50 件は `data-pkc-entry` を持つ **14 面**のどこからでも開く(「面 1 つ」ではない) |
| 表示の状態(View) | 36 | 12 面 | 保存されない状態(畳み / 焦点 / 月) |
| アプリ(タイル・お知らせ・パレット・フラグ) | 31 | 13 面 | ── |
| 設定 | 25 | **23 件が設定画面**。外に出る 2 件は外部の画像の同意(本文にその画像が現れた場で聞く ── 意図的な破れ) | 型と場所がほぼ 1:1 |
| **コレクション** | 22 | **11 面に散る**:設定 7(書き出し 4 / 構成 / 整理案 / 取り込む)/ 左の列 6(並び順・ゴミ箱)/ 情報ペイン 1 / 集計 2 / 種類の絞り込み 2 / 2 ペイン 1 / 連絡先 1 / 状態の行 1 | 🔴 **同じ型の操作がいちばん散っている**。並び順は帯と 2 ペインの 2 か所(同じ `SET_ENTRY_SORT`)、手動の並び順は左の列だけ |
| SQL | 16 | SQL の別窓のみ | 1:1 |
| 録音・タイマー・予定の知らせ | 15 | 3 面 | ── |
| 添付 | 10 | 5 面 | ── |
| **保存領域** | 9 | **7 件が設定画面**(使用量 / 点検 / 作り直す / 初期化 / 拾う ×2 / 片づけ)。残り 2 は「その場で詰まったときにその場で外す」(追記欄の強制解放 / 本文の再試行) | 型は揃っているのに**置き場の名前が「設定」** ── §8 の誤りの実測 |
| フォルダ | 8 | 4 面 | ── |
| Office の一式 | 5 | 設定(Office)/ 添付の詳細 | ── |
| 履歴 | 5 | 情報ペイン / 右クリック / 本文 | ── |
| 複数選択 | 4 | 左の列 | ── |
| つながり / タグ / 別窓 | 2 / 2 / 2 | 情報ペイン | ── |

🔑 数えて分かったこと:**型と押し所が 1:1 なのは 設定 / SQL / 保存領域**で、**散っているのはコレクション**である。
だから §4.3 の置き直しは「設定画面の中身を出す」ではなく、**コレクションの操作を「コレクションを選んでいるとき」の 1 か所へ寄せる**ことである。

### 4.3 型 × 操作(いまの押し口 → 案)

| 型 | 操作 | いま在る所 | 案 |
|---|---|---|---|
| **コレクション** | **取り込む** / **バックアップ**(`.pkc3-full.zip`) | 左下の帯 | いまのまま(頻度が高い) |
| コレクション | **閲覧用 HTML** / **持ち歩ける HTML 1 枚** / **Markdown** / **構成をコピー** / 整理案を適用 | 「設定」の「書き出しと片づけ」 | **右の列(何も選んでいないとき)** ── コレクションの情報(ノート N 件 / 添付 K 件・M MB / 履歴)の下に並べる |
| **ノート**(1 件) | 編集 / 追記 / 削除 / 履歴 / つながり / 添付 / **バックアップ(このノート)**(`.pkc3-notes.zip`)/ 閲覧用 HTML / Word / PowerPoint / PDF / 別窓 … | 右の列(情報ペイン) | いまのまま。⚠ **ノート 1 件の閲覧用 HTML とコレクション全体の閲覧用 HTML が、いまは「右の列」と「設定」という別の場所に同じ名前で在る** ── 上の行で右の列 1 か所になる(マニュアルの「⚠ 設定側の同名は全部をまとめます」という注意書きが要らなくなる) |
| **フォルダ**(フレーバー) | 中身の一覧 / 並べ替え / **バックアップ(このフォルダ)**(`.pkc3-notes.zip`) | 右の列 | いまのまま |
| **保存領域** | 使用量 / 点検する / 片づける / 作り直す / 初期化する | 「設定」の「書き出しと片づけ」+「壊れて直らないときの、最後の手」 | 「システム」→「保存領域」 |
| **一式** | 置く / 消す | 「設定」の「Office 表示」 | 「システム」→「保存領域」の中(端末の入れ物に置く物なので同じ節) |
| **設定** | 変える / 持ち出す / 取り込む | 「設定」の「設定の持ち出し」 | 「システム」→「設定」 |
| **許可** | 取り消す | 「設定」の 3 節 | 「システム」→「許可」 |
| **記録** | 消す | 「設定」の「最近開いたノートの記録」/ 左の列の「コピーの履歴」 | 「システム」→「記録」(⚠ コピーの履歴を**貼る**入口は左の列のまま ── 消す入口だけを移す) |
| **メッセージ** | 開く / 書き出す / 種類で絞る | (新。ワーカーの記録は「設定」の「処理(ワーカー)」) | 「システム」→「メッセージ」+ ステータスバーの「未読 N」 |
| **フラグ** | 切り替える / パラメータ付きで再起動 | 「フラグ」 | いまのまま |

⚠ 「拾って、戻せる形で書き出す」「拾って、読める形で書き出す」は**操作としては無くす** ── バックアップ / Markdown が、
保存領域に問題があるときは自動で読めた分を集めて `.pkc3-part.zip` で落とし、メッセージに「つながりと履歴は入っていません」と書く(§5)。
押し分けを user にさせない。

### 4.4 「操作を探す」(裁定:残す。押し口はいまのまま)

型で言えば「**名前で操作を呼ぶ入口**」であり、どの型の操作にも掛かる横断の道具である。
在る理由は思想①「利便性最大」── ボタンの場所もショートカットの綴りも覚えていなくても名前で呼べる。
とくにボタンを持たない書式 5 件(ルビ / ハイライト / 圏点 / 打ち消し / コピーした物の履歴)は、Ctrl や Alt の無い端末ではこれが唯一の入口。
#425 の根拠を「PKC2 に在った」から「名前で呼べる = 場所を覚えなくてよい」へ書き直す。
⚠ 「打ち始めたら 151 件も出すか」は裁定「回答しない」── **いまのまま**にし、こちらから再度聞かない。

## 5. 出し入れ ── file の型は「含まれる型の積」

裁定 2026-09-20:**二重拡張子で分ける**(`*.pkc3-full.zip` のように)。

| file の型 | 含まれる型 | 誰の操作か | file 名 |
|---|---|---|---|
| **全部** | ノート × 添付 × つながり × 履歴 | コレクション「バックアップ」 | `<題名>-<日付>.pkc3-full.zip` |
| **ノートと添付** | ノート × 添付(1 件 / フォルダの中) | ノート・フォルダ「バックアップ(このノート / このフォルダ)」 | `<ノート名 or フォルダ名>-<日付>.pkc3-notes.zip` |
| **読めた分** | ノート × 添付(保存領域に問題があるとき、読めた分だけ。**つながり・履歴なし**) | コレクション「バックアップ」が自動で切り替える | `<題名>-<日付>.pkc3-part.zip` |
| **設定** | 設定(好み 22 件)。許可・記録は**入らない** | 設定「持ち出す」 | `PKC3-settings-<日付>.json`(いまのまま) |
| **閲覧用** | ノート(描いた形)× 添付 ── **戻せない**(読むだけ) | コレクション / ノート「閲覧用 HTML」 | `<題名>.html`(いまのまま) |
| **持ち歩ける 1 枚** | コレクション × **アプリ** | コレクション「持ち歩ける HTML 1 枚」 | いまのまま |
| **Markdown** | ノート(原文)× 添付 | コレクション / ノート「Markdown」 | いまのまま |

- **3 か所で中身を言う**:①ボタンの下の 1 行(「ノート・添付・つながり・履歴 を全部」/「このノートの本文と添付」)②file 名の末尾 ③取り込む側は zip を読む前に中身の表(ノート N / 添付 K / つながり有無 / 履歴有無)を出す
- 取り込む側は **3 つ + 旧 `.pkc3.zip`** を全部受ける(判定は名前ではなく中身の目録で ── いまもそうかを実装で確かめる)
- 🔑 検算:**file の型が違えば、押した後のメッセージも違う** ── `.pkc3-part.zip` を落としたときは必ず「つながりと履歴は入っていません(N 件のうち M 件 / 添付 K 件)」を書く

## 6. 名前 ── 型の名前 + 動詞

### 6.1 規則

1. **見出し = 型の名前、ボタン = 動詞だけ**(節「保存領域」の下なら「点検する / 作り直す / 初期化する」)。見出しから切り離して読める場所(左の列・右の列)では対象を付ける(「バックアップ(このノート)」)
2. **技術の標準語・形式名は英語かカタカナのまま**:Markdown / HTML / PDF / Word / PowerPoint / zip / CSV / SQL / JSON / URL / バックアップ / メッセージ / ステータスバー / パネル / タブ / メニュー / ボタン / ショートカット / テンプレート / フォルダ / タグ / リンク / システム / フラグ
3. **動詞句(「〜して、〜する」)をボタン名にしない**。説明は下の 1 行と確認の窓へ
4. **造語を使わない**:面 → パネル / 画面、口・器・印・札・検め → 使わない、区画 → 読み込めなかった箇所、小窓 → 別ウィンドウ、雛形 → テンプレート、紙面 → ページ設定、居場所 → フォルダ、解放 → 編集を終える
5. **同じ型の同じ操作は 1 つの名前**(`.pkc3-*.zip` を落とす操作は全部「バックアップ」)。**名前を付ける前に、その字が画面の他の場所に在るか grep する**
6. **評価語・脅し語を使わない**(壊れ / 破損 / 最後の手 / 拾う / 捨てる / 危険 / 救出 / 復旧)。事実を述べ、不可逆は必ず言う。内部の英語を画面に出さない

## 11. これが分かったら覆る

- **領域を entries の列で持つ**:旧ビルドが `realm` 列を持つ DB を開けない(schema の版で断る)なら、列ではなく既存の `archetype` の綴り(`system-log` のような)で表す形へ倒す(⚠ その場合フレーバーと領域が 1 列に混ざるので、読み手の門が弱くなる)
- **メッセージをノートにする**:sqlite が書けない間に来るメッセージが多く、控えから流し込む順が狂うなら、別の入れ物へ倒す
