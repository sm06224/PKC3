### 2.2 設計 ── **メッセージはノートである**(推薦)

PKC の思想②⑤⑥⑦から導く:**container が正本 / 全 body は PKC-Markdown / PKC は messaging の node /
追記で済ませる。** だからメッセージの集積地は**新しい面ではなく、1 件のノート**にする。

| | 中身 |
|---|---|
| 実体 | **`textlog` 型の「システム用ノート」1 件(題名「メッセージ」)**。アプリが最初の起動で作る(消せない・改名できない。中身は user が編集できない) |
| 🔴 user のノートと分ける(裁定 2026-09-20 の条件) | システム用ノートは **user の一覧・フォルダ・検索・バックアップに混ざらない**。entries に `system` の印を持ち、①左の「一覧」「フォルダ」のタブには**出ない** ②検索は既定で**除外**(検索の欄の隣の「システムのノートも含める」で入れられる)③バックアップにも**入れない**(渡した相手に環境の記録が漏れる)。入口は **左の列のいちばん下の帯の「メッセージ(未読 N)」**と、§3 の「保存領域」画面の「システムのノート」の一覧だけ。将来システム用ノートが増えても(点検の結果・使用量の記録など)、同じ場所に並ぶ |
| 1 件のメッセージ | textlog の節 = `## 2026-09-20 14:05:03` の見出し + 本文 1〜2 行。本文は**固定の日本語文**で、種類 / 出所 / 次にどこへ行くか(リンク)を持つ |
| 種類 | **結果**(操作が済んだ)/ **注意**(user がすることがある)/ **問題**(操作が通らなかった)/ **配信**(お知らせ)/ **処理**(ワーカー。いまの「処理(ワーカー)」をここへ統合) |
| 上限 | **最大 500 件**(古い節から落とす)。設定「通知」で 100 / 500 / 2,000 から選べる(user が選べる形を先に出す ── 2026-08-28) |
| 読み直し | 開けば普通のノートと同じ ── 本文の検索 / 別窓で開く / 印刷 が効く。**新しい面も新しい道具も作らない**(⚠ ただし置き場は上のとおり user のノートと別) |
| 取り出し | 普通のノートと同じ ── 情報ペインの「書き出す」/ 本文をコピー。**バグ報告にはこのノートを貼る**。起動のたびに 1 節「版 / 保存先の種類 / フラグ / ブラウザ / 画面の幅」を書くので、報告に要る環境が同じノートに揃う |
| 中身を漏らさない | **書く口を 1 つ**(`postMessage(kind, source, text, detail)`)にし、`text` は固定文の表からしか引けない型にする。`detail` は件数 / 文字数 / lid / 分類名だけ。ノートの本文・題名・添付名・入力欄の字・検索語は**型で入らない**。生の例外文字列は分類名へ落とし、原文は `detail.raw` に **80 字まで**(切り分けに要る) |
| sqlite に書けないとき | 保存が止まっている / 空きが無いときは **IndexedDB の控え(`pkc3-messages-spool`)**へ積み、書けるようになった時点で節として流し込む。起動時に DB が読めなければ、控えをそのまま画面に出す |
| 未読 | ノートを開いたら 0。**`state.error` を 8 か所で消す規則は廃止** ── 「ノートを選ぶと知らせが消える」は構造から消える |
| ステータスバー | **いま起きていること**の 1 行に戻す:保存中 / 本体タブ経由 / **未読 N 件**。要対応の最新 1 件だけ短く出し、**既読になるまで消えない**。押すと「メッセージ」ノートが開く(普通のノートと同じ開き方 ── 別窓で開きたければ Ctrl+クリック) |

⚠ **代案 B(1 稿目の「ログ」)**:別の入れ物 + 専用の一覧の面 +「ログを保存」ボタン。
やらない理由:面と道具(一覧・絞り込み・書き出し・別窓)を**一式作り直す**ことになり、思想①②に反する。
ノートにすれば**既に在る道具が全部そのまま効く**。

⚠ v2 は「左の一覧に居る」形だったが、裁定で **user のディレクトリと明確に分ける**ことが条件になった(上の表の 🔴 の行)。

## 3. 設定画面の秩序 ── 軸を「何に効くか」にする

### 3.1 いま(全数目録 2026-09-20)

見出しは h3 が 10、h4 が 6。「表示」(17 項目)に h4 は 0、「書き出しと片づけ」に h4 が 5。
「壊れて直らないときの、最後の手」の下に**不可逆操作 2 つが常設**。
`.pkc3.zip` を書く関数は `writeArchive` 1 つなのに、押し口は**バックアップ / 書き出す / フォルダを書き出す /
拾って、戻せる形で書き出す** の 4 名 + 名乗らない 1 経路(中身を残して、作り直す)。

### 3.2 案 ── 先に「対象」を分け、入り口はそこから導く

🔴 裁定(2026-09-20):**「設定」という名前に合っていない中身がある。入り口の名前を見直せ** →
v3 の「データ」に対して **前段の抽象化が足りない。再考しろ**。
⚠ v3 は「取り込む / バックアップ / 書き出し / 使用量 / 保存領域 / システムのノート / Office の一式」を 1 つの袋に入れて名前だけ聞いた。
**入り口は 1 つの対象に対応する**べきで、袋にしか付けられない名前(データ / 管理 / その他)が出た時点で分け方が終わっていない。

#### アプリが扱う「対象」は 4 つ(PKC の思想から)

| 対象 | 何か | 思想 |
|---|---|---|
| **コレクション** | user の資産 ── ノート・添付・つながり・履歴の全部(container) | ② container が正本 |
| **保存領域** | コレクションを置いている**この端末の入れ物**(OPFS の sqlite + IndexedDB) | ② / #971 |
| **好み・許可** | この端末での**振る舞い**(見た目・編集・通知・外と繋がる許可) | ③ 業務画面 |
| **アプリ自身** | PKC3 が user に言うこと・user が PKC3 について知ること(メッセージ / お知らせ / ヘルプ / フラグ / 版) | ⑥ messaging の node |

#### いまの項目を、対象ごとに置き直す

| 対象 | 操作 | 置き場 | いま在る所 |
|---|---|---|---|
| コレクション | **取り込む** / **バックアップ**(頻度が高い) | 左の列のいちばん下の帯(いまのまま) | 同じ |
| コレクション | 閲覧用 HTML / 持ち歩ける 1 枚 / Markdown / 構成をコピー / 整理案を適用(頻度が低い) | 🔑 **右の情報ペインの「何も選んでいないとき」** ── いまは「左の一覧から選ぶと、ここに情報が出ます。」の 1 文だけが常設の幅を占めている(#582 R2 実測:1280×800 で中身 14%)。**何も選んでいない = コレクションそのものを選んでいる**ので、そこにコレクションの情報(件数 / 添付の量)と、コレクションへの操作を出す。⚠ 1 件選ぶと右は「そのノートへの操作」になる ── **右の列は常に「いま選んでいる物への操作」**という 1 つの規則で読める(思想③) | 設定 →「書き出しと片づけ」 |
| 保存領域 | **使用量** / **点検** / **作り直す** / **初期化する** / 片づけ(使っていない添付を消す / 最近開いた記録を消す)/ **Office の一式**(端末に置く・消す) | 左の帯の新しい入り口 **「保存領域」** | 設定 →「書き出しと片づけ」「最近開いたノートの記録」「Office 表示」 |
| 好み・許可 | 表示 / 編集(編集の仕方・開いたときの状態・貼り付け・電話番号・ショートカットキー)/ 通知 / 連携(外部の画像・zip を開く場所・アプリの開き方・許したアプリ・目次を見せているアプリ)/ 設定の持ち出し | **「設定」**(残るのは全部この端末の好みか許可) | 設定 |
| アプリ自身 | メッセージ(§2)/ お知らせ / ヘルプ / フラグ / 版 | **「メッセージ(未読 N)」** + **「ヘルプ」**(お知らせと版はいまもヘルプの中)+ **「フラグ」** | 同じ(メッセージだけ新) |

左の帯(いま → 案):取り込む / バックアップ / 操作を探す / 集計 / 設定 / フラグ / ヘルプ →
**取り込む / バックアップ / メッセージ(未読 N) / 集計 / 保存領域 / 設定 / フラグ / ヘルプ / 操作を探す**(+1 −0。「操作を探す」は裁定でいまのまま)。

⚠ **user 指示 2026-08-17(頻度の低いボタンは設定画面へ)との折り合い**:頻度で分けることは変えない。
変えるのは**逃がす先**である ── 頻度の低い**コレクションへの操作**は「設定」ではなく**右の情報ペイン(コレクションを選んでいるとき)**へ、
**保存領域への操作**は「保存領域」へ。「設定」には好みと許可だけが残る。
⚠ 「処理(ワーカー)」は §2 ③で「メッセージ」へ統合し、節を消す。
⚠ 「保存領域」の **作り直す / 初期化する** は「詳しい操作」として畳んだ中に置き、**点検で問題が出たときだけ開いた状態で出す**。

🔑 **検算**:各入り口の下に並ぶ物が**1 つの対象**を指すか ── 「設定」= 好み・許可だけ / 「保存領域」= この端末の入れ物だけ /
右の情報ペイン(何も選んでいないとき)= コレクションだけ。機械の門:`SETTINGS_COMMANDS` に書き出し・修復の id が居たら落ちる。

### 3.3 バックアップ ── 名前を 1 つにするだけでは足りない。**中身を見せる**

🔴 裁定(2026-09-20):**中身が何のバックアップかも分かるようにせよ。添付が入っているかで user にとって意味が変わる。添付も含めて資産である。**

いまの `.pkc3.zip` は押し口ごとに中身が違うのに、それが**押す前にも、落ちた file にも書いていない**:

| 押し口 | ノート | 添付 | つながり | 履歴 | 落ちる file 名 |
|---|---|---|---|---|---|
| バックアップ(左の帯) | 全部 | ✅ | ✅ | ✅ | `<題名>-<日付>.pkc3.zip` |
| 書き出す(情報ペイン、1 件) | 1 件 | ✅(そのノートの分) | ❌ | ❌ | `<ノート名>-<日付>.pkc3.zip` |
| フォルダを書き出す | そのフォルダの中 | ✅ | フォルダ内のみ | ❌ | `<フォルダ名>-<日付>.pkc3.zip` |
| 拾って、戻せる形で書き出す(問題があるとき) | 読めた分 | ✅ | ❌ | ❌ | `<題名>-<日付>.pkc3.zip`(⚠ 全部入りと**同じ名前**) |

案 ── **3 か所で中身を言う**:

| どこで | どう見せるか |
|---|---|

ボタン名(いま → 案):

| いま | 案 | 根拠 |
|---|---|---|
| バックアップ(左の帯) | **バックアップ** + 下の 1 行「ノート・添付・つながり・履歴 を全部」 | 名前は 1 つ、中身は説明で |
| 書き出す(情報ペイン、1 件) | **このノートをバックアップ** + 「本文と添付」 | 同じ形式に同じ名前。label と説明文(「バックアップ形式で保存」)の不一致を直す |
| フォルダを書き出す | **このフォルダをバックアップ** + 「中のノートと添付」 | 同上 |
| 拾って、戻せる形で書き出す | **無くす** ── バックアップが問題のあるときは読めた分を自動で集め、`.pkc3-part.zip` で落とし、メッセージに「つながりと履歴は入っていません」と書く | 押し分けを user にさせない。中身は名前と file 名で分かる |
| 拾って、読める形で書き出す | **無くす** ── 右の情報ペイン(コレクション)の Markdown が同じ経路を使う | 同上 |

点検の結果文(§2.3 の規則で):「問題は見つかりませんでした」/「索引に問題が見つかりました(N 件)。中身は無事の見込みです → 作り直すと直ります」/
「本文の保存に問題が見つかりました(N 件)。読める分を戻せます → バックアップを取ってから、作り直す」。
書込を止めるときの文(`CORRUPT_REFUSAL`)は「保存を止めました。読むことはできます。保存領域 → 作り直す へ」の 1 行にし、
手順の本文は「メッセージ」の節とマニュアルが持つ。

## 4. 「操作を探す」── 何の物か、なぜ外そうとしたか、そして残す

🔴 裁定(2026-09-20):**外すな。在ったほうがよい物ではないのか。なぜ外そうと思ったのかが伝わってこない。**
⚠ v2 の私は、2 巡目の「それは必要なものなの?」を**否定**と読み替え、こちらが足した物の後始末として「外す」案を出した。
問いは**その物を知らない人の問い**だった ── 先に「何の物か」を画面の言葉で書くべきだった。

### 4.1 何の物か(画面で起きること)

左の列のいちばん下の「**操作を探す**」を押す(または `Ctrl+Shift+P`)と、画面の真ん中に**小さな入力欄**が開く。
そこに操作の名前を打つ(「ルビ」「履歴」「段組み」)と、**名前が合う操作が下に並び**、Enter で実行される。
いま押せない操作は**灰色で理由つき**で出る。並ぶのは名前を持つ操作 **65 件**(ショートカットの表と同じ物)。
🔑 **ボタンの場所もショートカットの綴りも覚えていなくても、名前で呼べる**のがこの物の価値である
── 思想①「利便性最大」に沿う。とくに**ボタンを持たない書式 5 件**(ルビ / ハイライト / 圏点 / 打ち消し / コピーした物の履歴)は、
**Ctrl や Alt の無い端末(スマホ)ではこれが唯一の入口**である。

## 5. 名前の規則と用語集

### 5.1 規則(6 条)

1. **技術の標準語・形式名は英語かカタカナのまま**:Markdown / HTML / PDF / Word / PowerPoint / zip / CSV / SQL / JSON / URL / バックアップ / メッセージ / ステータスバー / パネル / タブ / メニュー / ボタン / ダイアログ / ショートカット / テンプレート / フォルダ / タグ / リンク
2. **対象は見出しが持ち、ボタンは動作だけ**:節「保存領域」の下なら「点検する / 作り直す / 初期化する」。⚠ 見出しから切り離して読める場所(左の列)では対象を付ける(「バックアップ(このノート)」)
3. **動詞句(「〜して、〜する」)をボタン名にしない**。説明は下の 1 行と確認の窓へ
4. **造語を使わない**:面 → パネル / 画面、口・器・印・札・検め → 使わない、区画 → 読み込めなかった箇所、小窓 → 別ウィンドウ、雛形 → テンプレート、紙面 → ページ設定、居場所 → フォルダ、解放 → 編集を終える
5. **同じ物は 1 つの名前**(`.pkc3.zip` = バックアップ)。**名前を付ける前に、その字が画面の他の場所に在るか grep する**
6. **評価語・脅し語を使わない**(§2.3)。内部の英語文字列を画面に出さない

### 5.2 用語集の持ち方

- 正本は **`src/features/ui-terms.ts`**(標準語 / 使わない語 / 例 の 1 表)。マニュアルの「言葉の意味」はここから生成する ── **説明する表ではなく、使わない語の表**にする
- 門(test):①画面の字(`label` / `textContent` / `OP_FAILED` の文 / メッセージの固定文)に**使わない語**が出たら落ちる(既知の残りは等値 pin で burn-down)②ボタンの `label` に「て、」を含む動詞句を禁止 ③`state.error` / メッセージの文に英語の識別子を禁止
- `manual-style` 規約 11 の「⛔ 用語集がまだ無い」を、この表で解く
