### 1.2 設計

**ログの 1 行**

| 欄 | 中身 | 例 |
|---|---|---|
| 時刻 | ISO | `2026-09-20T14:05:03Z` |
| 種類 | `info` / `warn` / `error` | `error` |
| 出所 | 操作の id(`data-pkc-action` と同じ綴り)または `boot` / `save` / `check` | `db-check` |
| 文 | **固定の日本語文**。ノート由来の値は入れない | `保存されている中身の一部が壊れています(目次 1 件)` |
| 補足 | 構造だけ:件数 / 文字数 / lid / エラーの分類名 | `{ lid: 'k7', chars: 1240, code: 'SQLITE_CORRUPT' }` |

**何を書く / 書かない**

| 書く | 書かない(🔴 構造で守る ── 書く口に scrub を置く) |
|---|---|
| 上の 7 系統すべて(お知らせは除く) | ノートの本文 / 題名 / 見出し / 添付の名前 / 入力欄に打った字 / 検索語 |
| 起動時の版・保存先の種類・フラグの名前 / 画面の幅 / ブラウザ名 | 生の例外文字列(**分類名に落とす**。落とせない物は先頭 80 字で切り、`raw: true` の印を付ける) |
| 起動時の自動チェックの結果 / 保存の失敗 / ワーカーの失敗 | |

🔑 PKC2 の debug 設計(`debug-privacy-philosophy.md`)の **4 原則**を踏襲する:①端末から出る経路を作らない(送信しない)②既定は構造だけ ③中身を含める切替は**作らない**(PKC2 は別 flag で opt-in にしたが、PKC3 では flag 予算を食うので**最初は無し**)④形式に版番号を持つ。

**置き場**:IndexedDB の専用 DB `pkc3-log`(`asset-blob-store.ts` と同型、メインスレッド)。
上限 **2,000 件 / 1 MB**(古い順に落とす)。⚠ **バックアップ zip には入れない**(渡した相手にログが漏れる ── `notice-store.ts` と同じ判断)。

**画面**

| どこ | 何が出るか |
|---|---|
| **設定 →「ログ」** | 新しい順の一覧(種類で絞れる)。いまの「処理(ワーカー)」のジョブ記録も**この中の 1 種類**にする(別の表を 2 つ持たない) |

## 2. 用語と名前の規則

### 2.1 いま(実測)

| 症状 | 数 |
|---|---|
| 同じ物を 3 通りで呼ぶ:「面」「ペイン」「欄」(`keymap.ts` の「2 ペインの面へ」に同居) | 「面」444 か所 / 「ペイン」/ 「欄」 |
| こちらの造語が画面に出る | 印 241 / 口 87 / 札 40 / 器 100 / 検め 6 / 区画 4 / 紙面 11 / 居場所 5 / 解放 2 / 小窓 9 |
| 動詞句のボタン | 「拾って、戻せる形で書き出す」「拾って、読める形で書き出す」「中身を残して、作り直す」「壊れていないか調べる」「中身を捨てる」 |
| 同じ物に 2 つの名前 | 「バックアップ」と「拾って、戻せる形で書き出す」= **同じ `.pkc3.zip`** |
| 英語の内部文字列が画面へ | 7 件(`⚠ エラー: entry row missing` 等) |
| 用語集 | マニュアルに 15 語の表が在るが、**造語を説明する表**になっている(`manual-style` 規約 11 は「⛔ 用語集がまだ無い」) |

### 2.2 規則(5 条)

1. **技術の標準語・形式名・固有名詞は英語かカタカナのまま。** Markdown / HTML / PDF / Word / PowerPoint / zip / CSV / SQL / JSON / URL / ログ / バックアップ / ステータスバー / パネル / タブ / メニュー / ボタン / ダイアログ / ショートカット / テンプレート / フォルダ / タグ / リンク / エラー / インポート・エクスポート(⚠ 「取り込む」「書き出す」は**動詞として**残してよい ── 名詞は「バックアップ」「エクスポート」)
2. **動作は日本語の動詞 1 語(2〜4 字)。** 開く / 保存 / 削除 / 検索 / コピー / 移動 / 印刷 / 修復 / 初期化 / チェック。**動詞句(「〜して、〜する」)をボタン名にしない** ── 説明は tooltip と 1 行の説明文へ
3. **造語を廃止し、標準語へ寄せる。** 面 → **パネル**(左 / 中央 / 右)または **画面**(設定・ヘルプのような切替先)/ 口・器・印・札・検め → 使わない(それぞれ「入口」「枠」「マーク」「タグ」「チェック」か、言わずに済む文へ)/ 区画 → 「読み込めなかった箇所」/ 小窓 → 別ウィンドウ / 雛形 → テンプレート / 紙面 → ページ設定 / 居場所 → フォルダ / 解放 → 編集を終える(ロック解除)
4. **同じ物は 1 つの名前。** zip は「バックアップ」1 語。壊れているときも同じボタンで、中の経路だけ壊れに強い方へ切り替える
5. **内部の文字列を画面に出さない。** 英語の識別子・例外文字列は分類名に落として日本語の固定文で出す

### 2.3 用語集の持ち方

- 正本は **`src/features/ui-terms.ts`**(1 表:標準語 / 使わない語 / 例)。マニュアルの「言葉の意味」はそこから生成する
- 門(test):①画面の字(`label` / `textContent` / `OP_FAILED` の文)に**使わない語**が出たら落ちる ── 既知の残りは等値 pin して burn-down ②ボタンの `label` は 8 字以内・動詞句(「て、」を含む)禁止 ③`state.error` の文は日本語を含む
- `manual-style` 規約 11 の「⛔ 用語集がまだ無い」を、この表で解く

### 2.4 例:壊れたときのボタン(設定 →「データの修復」)

| いま | 案 |
|---|---|
| 壊れていないか調べる | **チェック** |
| 拾って、戻せる形で書き出す | (無くす)→ **バックアップ**が壊れに強い経路を自動で使う |
| 拾って、読める形で書き出す | **テキストで書き出す**(書き出しの一覧へ移す) |

## 4. #1007 段② ── 説明の書き直し

**何をするか**:ノートを保存するたびに、その本文のコピーを **sqlite とは別の場所(IndexedDB)にも残す**。sqlite が壊れた日に、**最近の編集分はそこから戻せる**。

**画面に増える物**:設定に 1 行「**復元用のコピー:N 件**」だけ。ボタンは増えない。

**上限**:新しい順に **500 件まで / 合計 8 MB まで**(1 件 1 MB を超える本文は残さない)。古い物から落ちる。

**やらないこと**:全ノートを定期的に走査しない(重くなる)/ 消したノートを勝手に戻さない。

- **ログ**:IndexedDB が使えない端末(私用ウィンドウ)で「ログを保存」が空になる ── その場合は**メモリ内の分だけ**を落とす(空の file を作らない)

- **修復ボタン**:「バックアップ」1 本化で、壊れていないときの経路(関係・履歴も入る)と壊れているときの経路(本文だけ)の**中身が違う**ことが user に見えないなら、2 本に戻す
