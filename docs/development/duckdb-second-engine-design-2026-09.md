## 2. 画面で何が起きるか

1. SQL の面に **「どのエンジンで引くか」** が 1 つ増える(既定は **いまの sqlite**)
2. **DuckDB** を選ぶと、初めての 1 回だけ「**取ってきて入れますか**」と出る(約 **35MB**)
3. 入れた後は、同じ欄に SQL を打って **DuckDB の文法**で引ける
4. しばらく使わなければ**そっと畳まれ**、記憶を返す(次に押せばまた起きる)

⚠ **いまの引き方は 1 ドットも変わりません** ── 選ばなければ、これまでどおりです。

## 4. 🔴 parquet を「外へ取りに行かせない」── 自前で配る

⚠ duckdb-wasm は parquet を**実行時に外の CDN から**取りに行きます。
🔴 これは **PKC3 の柱と正面から当たる**ので、そのままでは入れられません。

🔑 **手当ては既に在る形で足ります** ── **Office 一式と同じ**(`office-pack-*`):

| | どうする |
|---|---|
| 置き場 | **IDB の Blob**(取ってきたものを端末に置く) |
| 取りに行く先 | 🔑 **同一オリジン**(PKC3 が自分で配る)── 外の CDN を見に行かせない |
| いつ取るか | **user が押したときだけ**(勝手に通信しない。2026-08-10 の裁定) |
| 取れなかったら | **理由を 1 行出す**(黙って失敗しない) |

⚠ **Office の仕組みをそのまま呼べません** ── `pkc3-office-pack` という **DB 名**も、
必須 file の一覧も、文言も **Office 名で固定**されています(5 file / 1118 行)。
🔑 **構造は写せる**(取得 → 設置 → パネルの分離)が、**名前の所だけ**を
引数にする小さな一般化が要ります。

## 5. 🔴 スレッド版を選びません(測って決めた)

⚠ 起票時のコメント(2026-09-09)は「**threads 版の前提は既に揃っている**」と書いており、
それ自体は正しい(`crossOriginIsolated` も `SharedArrayBuffer` も真)。
🔴 **ですが「使える」と「使うべき」は別でした** ── §1 の②のとおり、
10 万行では**遅く・重く・壊れやすい**ほうでした。

🔑 **素の版(eh)を既定にします。** これで得るものが 3 つ:

- **常駐が 1/3 以下**(+182.5MB 対 +501.8MB)── 不可侵指示「効くのは定常」に沿う
- **落ちない**(取りに行けなかったときに**ページごと死なない**)
- 🔑 **`crossOriginIsolated` に依存しない** ── 将来この前提を外しても、ここは壊れない

⚠ **スレッド版を永久に捨てるのではありません** ── ②(大きい集計)を**測った上で**
勝つなら、そのとき**選べるようにする**(⚠ ただし落ち方の非対称は残るので、
**既定にはしない**)。

## 6. 作る物 ── 🔴 **engine を選べる継ぎ目は 0 件**

実地調査(2026-09-14)で数えた結果:

| | いま |
|---|---|
| SQL の面 | `src/adapter/ui/render/sql.ts`(**408 行**)。押し所は `run-sql` / `sql-to-note` / `set-sql-source` / `set-sql-text` |
| 走らせる鎖 | 押す → `RUN_SQL` → 字の門(`sql-guard.ts`)→ `REQUEST_SQL_RUN` → `runReadOnlySql` → **storage worker** |
| 🔴 engine の抽象 | **在りません** ── 安全装置(`PRAGMA query_only` / 歩数の門 / 字の白名簿)が**全部 sqlite の API に直結** |
| worker | storage worker は **`worker-lease` の対象外**(DB の錠を握るので常駐が要る) |

🔑 **だから DuckDB は別のワーカーにします**(storage worker に相乗りさせない)。
そして**使い捨ての規律**(遅延起動 / 溜め / アイドルで解放)に乗せる ──
⚠ **+182.5MB を常駐させない**ためです(実測で、畳むと **114.1MB 返ってきます**。
⚠ ただし **68.4MB は残りました** ── §10)。

### 🔴 安全装置は「写す」のではなく「作り直す」

⚠ sqlite 側の 3 つ(`PRAGMA query_only` / 歩数の門 / 字の白名簿)は
**sqlite 固有の API**なので、そのままでは効きません。DuckDB 側で同じ 3 つを
**別に作る**必要があります ── ⚠ ここを飛ばすと「**読むだけ**」の約束が破れます。

### ⚠ 組み合わせの矛盾を作らない

「相手 × engine」の 2 軸にすると、**成り立たない組み合わせ**が出ます
(例:添付の `.sqlite` を DuckDB で開く)。
🔑 **選べる engine を、選んだ相手で絞る** ── 矛盾を**画面から消します**
(user に「押せるのに効かない」を見せない)。

## 9. ⏸ 残っている 1 問 ──「**DuckDB を選ぶ口を、どこに出すか**」

⚠ ここは**画面の見え方**なので、こちらでは決めません。

| | 画面で何が出るか |
|---|---|
| **A**(推薦) | SQL の面の「調べる相手」の**隣に、「どのエンジンで引くか」が 1 つ増える**。既定は いまの sqlite |
| **B** | **DuckDB 専用のタイル**(別のアプリ)にする ── アプリの一覧に 1 枚増える |
| **C** | 選ぶ口を**出さない** ── 大きい集計のときだけ、こちらで勝手に切り替える |

### 🔑 推薦:**A**

- **同じ場所に在る**(#300 の「主の作業領域を奪わない」と、業務画面の「同じものが同じ場所に」)
- 🔴 **C は「分かち合いたい」と正面から逆**です ── 隠すと、user は
  **DuckDB を使っていることに気づけません**(動機そのものが消える)
- **B は入れ物が 1 つ増える**(§7「3 系統目を作らない」の向きと合わない)。
  ⚠ ただし **DuckDB を主役として見せたい**なら B が勝ちます ── そこはお好みです

🔑 **これが分かったら覆ります**:実際に使って「**毎回エンジンを選ぶのが煩わしい**」と
なれば、**憶える**(前に選んだものを既定にする)側へ倒します。

## 11. 🔴 裁定 2026-09-15 ── **配り先は「PKC3 自身の Pages」**

⚠ **§9 の「A」とは別の問いです。** §9(エンジンを選ぶ欄を画面のどこに出すか)は
**まだ ⏸ のまま**です。ここで決まったのは **35MB の実体をどこから取ってくるか**だけ。

### ① user が何を求めていたのか

DuckDB も、sqlite や Office と同じように **オフラインで使えること**。
そのうえで PKC3 の柱(**勝手に外へ出ない**)を崩さないこと。

### ② そのとき何が問題だったのか

duckdb-wasm の素の姿は **実行時に外の CDN へ取りに行く**(parquet は
`https://extensions.duckdb.org/…`)── **オフラインで死ぬ**と**外へ出る**の
**両方**に当たる。

そして手本になる形が 2 つあり、**どちらから配るかで user に見える差が出た** ──
Office は**別 repo の Pages**(`sm06224/office-pack`)から配っているので、
そこへ相乗りすると **Office が使えない環境では DuckDB も道連れ**になる。

### ③ だから何を決めたか ── **PKC3 自身が配る**

| | どうする |
|---|---|
| 取りに行く先 | **PKC3 と同じオリジン**(`/dev/` を見ているなら `/dev/` の中) |
| 押す所 | **設定 → Office 表示 の隣に「DuckDB」**(Office と同じ見た目・同じ操作) |
| 置き場 | **IDB の Blob** |
| いつ取るか | **user が押したときだけ**(勝手に通信しない) |
| 取れなかったら | **理由を 1 行出す**(黙って失敗しない) |

🔑 **要点は「Office と配信経路を分けたこと」** ── 片方が落ちても、もう片方は生きる。

### 🔴 この裁定が連れてくる門 ── 先に書いておく

⚠ **35MB は `dist/` に置くが、precache には載せない。**
そのままだと `scripts/dist-inspect.mjs` が
**「precache に載っていない生成物がある」**で落ちる ── 2026-08-29 に
`portable-template.html` で**本番配布を実際に止めた**のと同じ形である。

🔑 **前例どおりにやる**:名指しで除外し、⚠ **外したぶんの門を置き直す**
── 除外した瞬間、その file は **0 バイトでも 100MB でも通る**ようになる
(tripwire を 1 つ撤廃したのと同じ)。別立ての予算を置き、
⚠ **その予算が渡っていなければ鳴らす**(optional にすると、呼び側が
渡し忘れた日に門ごと消える)。

### ⚠ 測って分かったこと(2026-09-15)

| | 値 | 引いた所 |
|---|---|---|
| npm の `@duckdb/duckdb-wasm` を展開した量 | 🔴 **142.5 MiB** | `npm view … dist.unpackedSize` = 149,377,663 |
| そのうち**配る**のは | **約 35 MiB**(素の版 `eh` だけ) | §1 の実測 |
| いま precache に載っている量(対照) | **137 file / 8.2 MiB** | `dist/precache.json` を実測 |

🔑 **だから同梱(precache)は採らない** ── 8.2 MiB が 43 MiB になり、
**DuckDB を選ばない user が 5.2 倍を払う**。
⚠ 「配る量は気にしない」(不可侵指示 2026-08-03)は生きているが、それは
**全 user が使う物**についての話であって、**選んだ人だけが使う物**を
全員へ配ってよい理由にはならない。

### ⚠ 段の切り方への影響(§7)

🔴 **段① から「precache に載せない形」で作る。** 普通に束ねると 35MB が
precache に入り、**後で外すときに上の門を踏む**。
🔑 段③(取ってきて入れる)は、その上に **IDB と opt-in の小窓**を足すだけになる。
