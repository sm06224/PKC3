## 経緯 ── 何を間違え、どう分かったか

### 1. 「docx が開かない」の引き金は画像ではなく **DrawingML** だった

入れ物だけ変えた 6 通りで割れた。⚠ **LO 自身が書いた DrawingML も開かない**ので、
「PKC の書き方が悪い」ではない。`mc:AlternateContent` の代替も効かない
(`mc:Choice` を採って落ちる)── **VML のみ**が通る。表は #238 に残した。

### 2. LibreOffice に SVG→EMF させる線は死んでいた

**箱が真っ黒・文字が消える。** クラスを素朴にインライン化してから渡しても同じ。
結局**自前の変換器**(`features/export/` に 4 file)を書いた ── mermaid は色を
CSS のカスケードで決めるので、**小さな CSS カスケードごと解決**しないと色が出ない。

⚠ ここで**矢印の向きが逆に見えた**が、EMF のバイトを解いたら **5 本とも正しかった**。
私の python デコーダが `POLYBEZIERTO` を無視しており、辺の path が 3 点の「三角形」に
見えていただけである。🔑 **道具の側を疑う**(→ CLAUDE.md §4)。

### 3. **実ブラウザ smoke を書いて、前から在った穴が出た**(#252 の主役はこちら)

貼付そのものより大きい話。**読む面だけ**が `hydrateAssetRefs` を呼んでおり、
**2 列のプレビューと 1 面のライブエディタは呼んでいなかった** ── 本文に
`![…](asset:…)` と書いても、**書いている間は何も出ない枠**だった。
さらに 1 面は**行を閉じるときに塊を作り直す**ので、画像の行を開いて閉じると
`src` が消えた(本文は変わらないので描き直しも来ない)。

🔑 **貼付を実装しなければ、この穴は誰も踏まなかった** ── 新機能が既存の穴を
照らすことがある。⚠ そして**それを見つけたのは unit ではなく smoke** である。

### 4. 着地前レビュー(サブエージェント)が 6 件当てた

⚠ うち **2 件は既に直っていた**(レビュー中に作業ツリーが動いた分)── **鵜呑みに
せず HEAD へ当て直す**。当たっていたものの型:

- **fake が本物より寛容**だったので、**マニュアルに成り立たない主張**を書いていた
  (「編集中に落とした画像以外は添付になる」── 本物の `attachFiles` は編集中を断る)
- **`onInserted` を optional にしていた** ── 配線を落としても誰も鳴らない
- **裏返した検査に `codeOnly` を通し忘れ**、受け口を**コメントアウトしても緑**だった

### 5. 変異試験で 8 件が生き延び、その 1 件が**設計の誤り**を教えた

「どこかのタブが編集中か」を **2 か所で別々に数えていた**(自分が聞かれたとき /
follower に聞かれたとき)。片方を壊す変異は **unit で落ちるのに smoke が素通り**した
── smoke が通るのは follower の経路で、**そちらは別の式が答えていた**からである。

🔑 **SURVIVED を「test が弱い」と読む前に、「答えている場所が別かもしれない」を疑う。**
この件の正解は test を足すことではなく、**判定を 1 つの関数へ寄せる**ことだった。

### 6. 変異の「印」自体が消える 2 つの顔(新しい罠)

smoke に変異を当てるには build が要る(既知)。⚠ その先で 2 回踏んだ ──

どちらも「dist に届いていない」と出るが、**変異自体は効いている**(= 偽の NOT-APPLIED)。
🔑 印は**実行時の代入**にする。手順は `.claude/skills/mutation-testing/SKILL.md`。
