## 1. 画面で何が起きるか(案)

PKC の画面で開いた PDF の窓(設定「PDF を PKC の画面で開く」を入にした人だけ)で:

1. 上のバーの「ノートへ引用する」の**隣**に「ハイライト」と色のボタンが並ぶ。どちらも**字を選んだときだけ押せる**
   (いまの「ノートへ引用する」と同じ。同じ選びから、引用もハイライトもできる)
2. 字を選んで「ハイライト」を押すと、選んだ字に**蛍光ペンの色が付く**(保存の前から画面に出る)。
   複数行・ページの向きが回っている PDF でも、選んだとおりの範囲に付く
3. 色は 4 色から選ぶ(黄・緑・青・ピンク。既定は黄。最後に選んだ色を、窓を閉じるまで覚える)
4. 付いたハイライトを押すと、「ハイライトを外す」が出る。**他のアプリで付けたハイライトも外せる**。
   コメント・図形など他の種類の注釈には触らない(残す)
5. 何か変えると、②-1b と同じバーの **「別の PDF として保存」** が押せる。**ページの並べ替え・回す・外すと、
   ハイライトの付け外しは、同じ 1 回の保存で新しい添付 1 つになる**。元の PDF はそのまま残る
   (名前は ②-1b と同じ `元の名前 (編集).pdf`)
6. 保存しないまま窓を閉じようとすると、②-1b と同じブラウザの確認が出る

⚠ ハイライトを付けても**字は隠れない**(下の実測:文字の画素の数が付ける前と同じ)。
⚠ 字の層が無い PDF(スキャンした画像だけのもの)は、字が選べないのでハイライトは使えない
(この段では、四角を描いて付ける道は作らない)。

## 2. 実測(2026-10-11)

手元の箱で、自作の小さな PDF(pdf-lib で作成。Helvetica 12pt、400×800)に対して、
pdf.js 6.4.299 と pdf-lib 1.17.1 を実際に動かした。実ブラウザは headless の Chromium(`headless_shell` 1194)。
測りの script は repo に入れていない(scratchpad)。⚠ 字は半角の英字だけ ── 日本語・縦書きの実測は下の表の「未測定」。

### 2.1 選んだ字の位置から、ハイライトの座標を作れるか

**作れる。ただし材料は pdf.js の textContent の座標ではなく、窓の字の層で選んだ範囲の長方形がよい。**

| 測ったこと | 結果 |
|---|---|
| textContent の `transform` / `width` / `height` | ページの向き(`/Rotate`)の**前**の座標で出る(`/Rotate 90` のページでも、向きが無いページと同じ値)。字そのものが回っている場合は `transform` の行列に出る。ただし**選んだ範囲の中の 1 字ごとの位置は出ない**(1 つの塊の幅だけ) → 範囲の途中から始まる選びは、字幅を自前で配るしかなく、フォントによってずれる |
| 字の層で選んだ範囲の長方形(`Range.getClientRects`)を、`viewport.convertToPdfPoint` で PDF の座標へ直す | 🟢 **横の位置:本当の位置との差 0.05pt 以内**(基準:Helvetica の幅から計算した "world" の 102.67〜131.40)。拡大(0.8 倍 / 1.5 倍)で変わらない |
| 同じ方法を、`/Rotate 90` のページ | 🟢 同じ値(長方形が縦に出るが、PDF の座標に直すと元と同じ範囲) |
| 同じ方法を、**字そのものが 90° 回って並ぶ**ページ(縦書きの代用) | 🟢 範囲の縦位置の差 0.05pt 以内。字の高さの側は基準線から字の向きの反対へ |
| 複数行にまたがる選び(1 行目の途中〜3 行目の途中) | 🟢 行ごとの長方形が出る。3 ページ(通常 / `/Rotate 90` / 字が回っている)とも同じ形。🔴 ⚠ ただし **行の長方形のほかに、span 全体の長方形が重なって出る**(1 行ごとに同じ範囲が 2 つ)→ 重なりを除く処理が要る |
| 長方形の高さ | 12pt の字に対し 13.3pt(基準線の 2.8pt 下〜10.5pt 上 = 字の大きさの約 1.11 倍)。蛍光ペンの見た目として足りる |
| **真の縦書き**(日本語の縦組みなど、フォント側が縦書きの指定を持つ PDF) | ⚪ **未測定**(この箱に日本語フォントが無く、縦書きの PDF を作れなかった)。上の「字が回っている」で代用した値は、縦書きの実物の保証ではない |
| 日本語・複数のフォントが混じる行 | ⚪ **未測定**(上と同じ理由) |
| 別のページにまたがる選び | ⚪ **未測定**。段①の引用は選びの開始ページしか持たない(`reader.js` の `lastSel`)ので、ハイライトは**ページごとに分けて**付ける必要がある |

### 2.2 pdf-lib で足した注釈を、pdf.js が読んで描くか

注釈 = `/Subtype /Highlight`、`/QuadPoints`(1 行 1 つ、TL・TR・BL・BR の順 = Adobe 系の並び)、`/C` `/CA`、`/F 4`。

| 測ったこと | 結果 |
|---|---|
| **外観(`/AP`)なしで足す** | 🟢 pdf.js が自分で黄色を描いた(3 ページとも。`/Rotate 90` と字が回っているページも)。`hasAppearance` は false |
| **外観(`/AP`)つきで足す**(Form XObject、乗算で重ねる) | 🟢 同じに描かれた |
| QuadPoints の並びを仕様どおり(左下・右下・右上・左上)にした | 🟢 pdf.js ではどちらの並びでも同じに描かれた |
| 字が隠れるか | 🟢 隠れない。ハイライトの範囲の中の暗い画素の数が、付ける前と同じ(292 / 294 / 286 → 292 / 294 / 286) |
| ハイライトを描かない設定(`annotationMode: DISABLE`) | 描かれない。⚠ 窓がページを絵にするときの設定は既定(描く)なので、**保存済みのハイライトは窓の絵に入る**。保存前に付けた分は、窓が重ねて見せる必要がある |
| pdf.js の `getAnnotations()` | 🟢 `id`(`14R` = PDF の 14 0 R)・種類(9 = ハイライト)・`rect`・`color`・`quadPoints` が読める。⚠ `id` は**保存すると番号が振り直される**ので、保存後に窓が開き直したものから読む |
| **pdf.js 以外のビューア**(Acrobat・プレビュー・ブラウザ組み込み) | ⚪ **未測定**。外観(`/AP`)が無いと描かない実装があると知られている ── 測っていないので、**外観を必ず書く**(足す費用が小さい。下の 2.4) |
| `/P`(注釈が属するページへの参照) | 付けない。省略してよい項目で、pdf.js は読める(上の `/AP` なし・ありとも `/P` なしで測った)。付けると 2.3 の問題に当たる |

### 2.3 ②-1 の最後の門との衝突

最後の門 = ②-1 の `verify`(出力を読み直し、ページの辞書がちょうど残す数 + どこからも辿れない物が 0)。

| 測ったこと | 結果 |
|---|---|
| `/P` を付けない注釈つきの PDF を、並べ替え・抜き出しで作る | 🟢 通る。注釈は残すページに付いたまま写る。外したページの注釈の本文(目印の字を入れて測った)は**出力に 0 件**(対照:元の file には在る) |
| ページ編集で出来た PDF に、**あとから**注釈を足して保存し、`verify` に掛ける | 🟢 通る |
| 注釈を外す:ページの注釈の並びから**抜くだけ** | 🔴 `verify` が `leaked` で断る(門が止めた)。⚠ しかも抜いただけの file には、**外したはずの注釈の本文が残る**(目印の字で確認) |
| 注釈を外す:並びから抜き、注釈・外観・その中の stream を**文書から捨てて**保存 | 🟢 `verify` を通り、本文も残らない |
| 🔴 **`/P` が自分のページを指す注釈**(Acrobat・プレビュー・pdf.js など**他のアプリが付けるハイライトの標準の形**)を持つ PDF を、②-1 の `build` に掛ける | 🔴 **`leaked` で断られる**(外観あり・なし両方)。`/P` を消すと通る。原因の読み:`copyPages` が `/P` をたどって元のページを**もう 1 枚写す**(②-1 で直したリンクの行き先と同じ型) |

🔴 **最後の行は、②-2 の前から在る欠陥である。** いまの ②-1b/c は、他のアプリでハイライトやコメントを付けた PDF
(`/P` を持つ注釈が 1 つでも在るもの)を**ページ編集できない形として断る**可能性が高い(測ったのはハイライトのみ。
他の種類の注釈も `/P` を持つので同じ型と読むが、未測定)。②-2 が「他のアプリで付けたハイライトも外せる」と言うには、
先にこれを直す必要がある(→ 4 の ②-2a)。ここでは直さない(doc のみ)。

### 2.4 そこから決まる作り方

- **座標**:字の層の選び範囲の長方形 → 重なりを除く → PDF の座標へ → `QuadPoints`(1 行 1 組)と `Rect`(全体を囲む)
- **注釈の中身**:`/Highlight`、`/C`(色)、`/CA`、`/F 4`、**`/P` は付けない**、**外観(`/AP`)を書く**
  (1 つの Form XObject に、行ごとの長方形を乗算で塗る)
- **足す場所**:`build` の中で、`copyPages` で写した**出力のページ**に足す(元の文書の上ではない)。
  ページを外した・並べ替えたに関わらず、**出力ページを基準にすれば追従する**(窓は元のページ番号で持ち、
  `build` が出力の位置へ直す)。足した後の剪定・最後の門は同じ道を通る → 門が注釈も守る
- **外す場所**:同じ。注釈の並びから抜くだけでなく、**注釈・外観・外観の stream を文書から捨てる**(上の 2 つの行)
- **外せる物**:`/Subtype /Highlight` だけ。他の種類は触らない(⚠ ハイライトに付く吹き出し `/Popup` が在る形は**未測定** ──
  外すときに一緒に捨てるか、②-2b の着地前に実物で確かめる)

## 3. 保存の形(推薦 1 つ)

**②-1 の裁定どおり、保存すると新しい添付が増え、元は残る。ページ編集とハイライトは同じ保存にまとめる。**

| | 内容 |
|---|---|
| 推薦 | 保存ボタンは「別の PDF として保存」の **1 つのまま**。ページの変更もハイライトの付け外しも、その 1 回で 1 つの新しい添付になる。「元を上書き」は**作らない** |
| 理由 | ① ②-1 で裁定済み(元を書き換えない。#683 / #952 と同じ向き)② ボタンが 2 つ(上書き / 別名)になると、押す前に「どちらか」を考えさせる ③ ページ編集の保存と別のボタンにすると、ページを入れ替えた後のハイライトの置き場が 2 通りになる ④ 上書きしたい人は、新しい方を残して元を消せば同じことになる(消すのは既存の操作) |
| 覆る条件 | 「元を置き換えたい」という声が実際に多い場合 ── 保存の横に「元と置き換える」を足す(確認つき、押すと元の添付が消える旨を画面で言う)。⚠ その場合も既定は新しい添付 |

## 4. 常駐メモリとワーカー

- **同じ worker に載る**。②-1b の `edit-worker.js` は `{ op, bytes, job }` の封筒で動いている。`build` の依頼 `job` に
  `highlights`(付ける物)と `removals`(外す物)を足すだけで、起動・依頼のバッファ・アイドルで畳むは窓の側がそのまま使う。
  bytes は窓の Blob から 1 度だけ取って transfer(ゼロコピー)で渡し、結果も transfer で返す
- 窓の側(字の層から長方形を作る・重なりを除く)は、**選んだ範囲の長方形を数える程度**でメインスレッドに十分軽い
  (worker に出すほどではない)
- 測れた値(node、worker の外):100 ページ・19.6MB の自作 PDF に 300 個のハイライト(外観つき)を足す ──
  読み込み 68ms / 足す 12ms / 保存 196ms / 出力 19.7MB。実ブラウザの worker の中の値・常駐(Pss)・long task は
  ⚪ **未測定**。②-1b の「測ること」(`pdf-page-ops-design-2026-10.md` §3.4)と**同じ 100 ページの自作 PDF で、
  ハイライトを足した場合を ②-2a の着地前に測る**
- 画面に出すハイライト:保存した分は窓が焼いた絵に入る(上の 2.2)。**保存前に付けた分と、外すために押せる印は、
  窓が字の層の上に透明な長方形を重ねる**(絵は焼き直さない ── 焼き直しは常駐も応答も食う)。ページが畳まれたら一緒に捨てる

## 6. 決めてもらうこと(見え方が変わるもの)

#1163 にそのまま貼れる形(以下、各問いの「画面で何が起きるか」と推薦・理由・覆る条件)。

**問 1.ハイライトのボタンは、どこに出ますか。**
PDF を開いたウィンドウの上のバーの、いまの「ノートへ引用する」の**隣**に「ハイライト」(と色)のボタンを置きます。
字を選ぶと両方が押せるようになり、押すとどちらも選んだ字に効きます。
- 推薦:上のバーの隣。理由:同じ物が常に同じ場所にあること(業務画面の方針)と、字を選んだ後にマウスをほとんど動かさずに済むこと。
- 覆る条件:字を選んだその場所に小さなメニュー(ハイライト・引用)が出るほうが使いやすい、と思う場合。

**問 2.色は何色から選べますか。**
黄・緑・青・ピンクの 4 色から選びます。最初は黄で、最後に選んだ色をウィンドウを閉じるまで覚えます。
- 推薦:4 色。理由:蛍光ペンで普通に使う色が足りて、色を選ぶ画面を増やさずに済む。
- 覆る条件:好きな色を自由に選びたい場合(色を選ぶ画面が 1 つ増えます)/ 1 色で十分な場合(色のボタンが無くなります)。

**問 3.保存すると、どうなりますか。**
「別の PDF として保存」を押すと、**新しい添付が 1 つ増えます**。名前は `元の名前 (編集).pdf`。元の PDF はそのまま残ります。
ページの並べ替えなどとハイライトは、同じ 1 回の保存にまとまります。「元の PDF を置き換える」ボタンは付けません。
- 推薦:新しい添付が増える(元は残る)。理由:ページの編集で既に決めた動きと同じにする。置き換えると、押し間違えたとき元に戻せない。
  置き換えたい人は、新しい方を残して元を消せば同じことになります。
- 覆る条件:「元を置き換えたい」が多い場合 ── 保存の横に「元と置き換える」を足します(押すと元の添付が消える、と確認の画面で言います)。

**問 4.付いているハイライトを外せる範囲はどこまでですか。**
ハイライトを押すと「ハイライトを外す」が出て、外して保存すると新しい添付からは消えます。
他のアプリで付けたハイライトも外せます。コメントや図形などの他の注釈は、触らずにそのまま残します。
- 推薦:ハイライトだけ外せる。理由:この段で作るのがハイライトだけで、他の注釈は見え方も外し方も確かめていないため。
- 覆る条件:コメントなども外したい場合 ── 種類ごとに足します。

**問 5.他のアプリで注釈が付いた PDF を、今までページ編集できなかった件。**
他のアプリでハイライトやコメントを付けた PDF は、いまのページ編集(並べ替え・回す・外す・抜き出す)が「ページを編集できない形です」と断る可能性が高いことが
分かりました(ハイライトで確認。他の種類は同じ原因と読んでいますが、確かめていません)。ハイライトを付ける段の前に、先にこれを直して、断らずに編集できるようにします。
- 推薦:先に直す(単独で着地)。理由:ハイライトを付けた PDF は、まさに「他のアプリで注釈が付いた PDF」になるので、直さないと自分で付けた PDF が次にページ編集できなくなる。
- 覆る条件:なし(確認のお知らせです。反対があれば止めます)。

## 7. 確かめられなかったこと(要約)

- 真の縦書き・日本語の字・複数のフォントが混じる行での座標(自作の英字の PDF だけで測った)
- pdf.js 以外のビューア(Acrobat・プレビュー・ブラウザ組み込み)での見え方
- 別のページにまたがる選びを、ページごとに分けた座標
- ハイライトに付く `/Popup` を持つ形、`/P` を持つほかの種類の注釈(ハイライト以外)で、②-1 の `build` が断るか
- 実ブラウザの worker の中での時間・常駐(Pss)・long task
- 字の層が無い PDF(スキャン)では選べない ── 作りから言えることで、実物では測っていない
