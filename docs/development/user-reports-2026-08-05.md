## 0. 全体像 ── 共通の根が 3 つある

個別の 37 件を並べる前に、**同じ根から出ているもの**を先に書く。ここを直さないと
同型の欠陥がまた生える。

### 根 A: 「renderer だけ移植して stylesheet を持ってこなかった」が残っている

markdown の**生成 HTML は健全**である ── 161 ケースを PKC3 と PKC2 の
`renderMarkdown` に通して A/B した結果、**154/161 が byte 一致**(差分 7 件はすべて
意図的:task の `disabled` 化と `asset:` の新扱い)。壊れているのは **CSS** で、
markdown が実際に吐く **19 個の class に規則が 1 行も無い**。

user 報告①「レンダリングができていない」の主因はここである。

### 根 B: 検査が「実際の出力」ではなく「ソースの書き方」を見ている

`markdown-css-parity.test.ts` は上の 19 class を見逃したまま **green**。
`emitted()` が `markdown-render.ts` 1 ファイルの `class="…"` リテラルしか拾わないため、
`attrJoin` / テンプレート合成 / 別ファイル / `data-pkc-*` 属性セレクタが視野の外にある。

同型が他にもある ── `markdown-golden.test.ts` は PKC2 から採った golden で
**脚注漏出のバグを「正」として pin** しており、直すと落ちる関係になっている。

### 根 C: 「読む側」だけ作って「書く側」を配線していない

フォルダは木の解決もファイラ面も完成しているのに、**structural relation を作る・消す・
付け替える経路が action・reducer・effect のどこにも無い**。書込 op
(`bulkUpsertRelations`)は storage 層に在るが、配線されているのは import だけ。
同じ形が launch(受け口は張れているが着地点が無い)にも出ている。

### 1-4. ノートをフォルダへ入れる/出す導線が皆無 ── M

### 1-5. フォルダの中に新規ノートを作れない ── S

`CREATE_ENTRY`(`app-state.ts:239-247`)が親を受けず、`:1009-1011` で root 直下に置く。

### 1-6. OS から md を開いても、その md が画面に出ない ── S

manifest / `launchQueue` 受け口 / 取込は**実際に動いている**(実 Chromium で
`setConsumer` 1 回、ファイルは entry になる)。壊れているのは**着地点**で、
`import-markdown.ts:90-97` が `SELECT_ENTRY` を一度も dispatch しない。新 entry は

「取込完了: 1 件」だけ。

🔴 反証役の追加(**所見より悪い**):取込は「新しいファイルを出さない」だけでなく、
**いま読んでいたノートを閉じる**。`reload-snapshot.ts:40` が `SYS_BOOTED` を投げ、
reducer が `selectedLid: null` にリセットする ── md を開くと**画面から中身が 1 つ減る**。

### 1-7. ランチャー:アプリ内のページ内アンカーでアプリが消える ── L

外殻が `srcdoc` + `<base>` なので、アプリ内の `<a href="#sec">` を押しただけで iframe が
`/pkc3-app/#sec` へ抜け、そこは SPA fallback で **PKC3 自身の index.html**。不透明 origin
では起動できず真っ白になる。**JS を 1 行も使わないアプリでも起きる。**

同根で **hash router が動かない**(相対 `#…` の `pushState`/`replaceState` が SecurityError)。
⚠ `app-shell.ts:44-47` は「`<base>` があれば hash router は無改造で動く」と書いており、
smoke はその主張を**唯一通る書き方(絶対 URL)で pin していて空振り**している。

🔴 反証役の重要な訂正:**`<base>` は「相対 URL が全滅」を直したのではなく、沈黙を
アプリ消滅に格上げした**。base 無しならアンカーのクリックは拒否されるだけで
**アプリは生きたまま**、base ありだと**アプリが消える**。

🔴 反証役の追加:**素のまま(same-origin)起動では、アプリの相対 fetch が HTTP 200 +
PKC3 の index.html を受け取る** ── エラーではなく「成功した嘘のデータ」。
`/pkc3-app/app.js` も `/pkc3-app/data.json` も 200 / `text/html` で返る。

#### ▶ 実装した形(2026-08-05、user 指示「しっかり推奨で直してみてください」)

|---|---|---|

| 元へ返す | handle を保持 | **同じ**(handle を保持して「書き戻す」) |

  書き戻しで**別のファイルを壊す**。`isSameEntry` の無いブラウザでは
  「別物」に倒す(取り違えるより増えるほうが安全側)
- 序でに **2-13(同じ md を 2 回開くと増える)**も閉じた ── handle を持った時点で
  「もう開いている」が判定できる

⚠ **残した論点**: 「取り込まずに**見るだけ**」は入れていない(案 B 相当の縮小)。
蔵書に入れたくない md を眺めたいという要求があるなら、そこで初めて一時 entry の
議論に戻る ── いまの形は「取り込む + 元へ返せる」で user 報告を満たしている。
