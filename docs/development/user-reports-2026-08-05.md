## 8. 🔴 設計の裁定が要るもの

### 8-1. ランチャーを作り直すか(1-7)

いまの `srcdoc` + `<base>` は**アンカー 1 個でアプリが消える**うえ、素のまま起動では
相対 fetch が **PKC3 の index.html を 200 で返す**(成功した嘘のデータ)。

- **案 A(推奨)**: `srcdoc` をやめ、**SW が持つ専用スコープ**(`pkc3-app/` 配下)から
  添付 bytes を返し、iframe の `src` にその URL を指す。document URL と base が一致するので
  アンカーも hash router も**素の意味論**で動く。隔離は CSP の `sandbox` ヘッダで掛ける
- **案 B**: いまの形を維持し、**動かないことを正直に書く**(コメントの嘘を直し、
  詳細画面に「囲いの中では hash router / IndexedDB は使えません」と出す)
- ⚠ どちらでも、**アプリが死んだことを外殻が言う**(prelude で `onerror` を拾って
  `postMessage`)は入れる価値がある ── 実測で pageerror は在るのに誰も拾っていない

### 8-2. 「その場閲覧 / スポット編集プレビュー」の形(2-12)

正本 doc §9 は「開いた md は**取込 or その場閲覧**」と書いているが、後者は未実装で、
`FileSystemFileHandle` を受け口で捨てている(`createWritable` は src に 0 件)。

- **案 A**: launch の既定を「**一時ノートとして開いて表示**」にし、明示操作で
  『蔵書に取り込む』/『元ファイルに書き戻す』へ分岐(handle を保持する)
- **案 B**: 取込のみに寄せ、正本 doc §9 の「その場閲覧」を**取り下げる**

⚠ 案 A は「container に書かない一時 entry」という**新しい状態**を持ち込む。
プライム・ディレクティブ(新機能を盛り込みすぎない)との兼ね合いで user 裁定が要る。

#### ▶ 実装した形(2026-08-05、user 指示「しっかり推奨で直してみてください」)

**案 A から「一時 entry」を落とした版**を入れた。user の求めは「開いた md を
その場で見て・直して・元へ返す」であり、**新しい状態は要らない**と判断した:

| | 案 A(doc 原案) | 実装した形 |
|---|---|---|
| 開いた md | container に書かない**一時 entry** | 従来どおり**普通のノート**として取り込む |
| 見る / 直す | 一時 entry 専用の面が要る | 既存の詳細・編集がそのまま使える(新しい面ゼロ) |
| 元へ返す | handle を保持 | **同じ**(handle を保持して「書き戻す」) |
| 新しい state | 一時 entry(container 外) | `linkedFiles`(lid → **ファイル名だけ**) |

- 取込は**原文のまま**書いている(`import-markdown.ts` の規律)ので、
  **frontmatter を含めて往復する**(組み立て直さない)
- 紐づけは**このセッションだけ**。handle を保存すると「昔どこかで開いたファイル」への
  書込権をアプリが黙って持ち続ける ── 読み直したら消えるのが正直な寿命である
  (素のまま起動の許可を session 限りにしたのと同じ判断)
- 同一判定は `isSameEntry`(**名前ではない**)。同名の別ファイルを同じと見ると、
  書き戻しで**別のファイルを壊す**。`isSameEntry` の無いブラウザでは
  「別物」に倒す(取り違えるより増えるほうが安全側)
- 序でに **2-13(同じ md を 2 回開くと増える)**も閉じた ── handle を持った時点で
  「もう開いている」が判定できる

⚠ **残した論点**: 「取り込まずに**見るだけ**」は入れていない(案 B 相当の縮小)。
蔵書に入れたくない md を眺めたいという要求があるなら、そこで初めて一時 entry の
議論に戻る ── いまの形は「取り込む + 元へ返せる」で user 報告を満たしている。
