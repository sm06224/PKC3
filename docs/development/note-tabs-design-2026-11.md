## 3. 棲み分けの整理

### 3.1 いまの「複数ノートを扱う道」が担う役割

| 道 | 担う役割（user の動線） | 時間の長さ |
|---|---|---|
| 戻る・進む | 「さっき見たノートへ戻る」。直線の履歴 | 数手前まで |
| 分割枠 / スタック | 「**並べて同時に**読む・突き合わせる」。同時表示が目的 | 作業中（セッション限り） |
| 2 ペイン | 「**整理する**（コピー・移動・改名）」。読む場ではない | 整理の間 |
| 別ウィンドウ | 「別のモニター・位置に置く」。本体と並走 | 作業中 |
| ピン留め | 「**毎日開く定番**を 1 押しで」 | 長期（保存される） |
| 左ペインの探し方タブ | 「どう探すか」の切替。ノートを持たない | 随時 |
| **ノートのタブ（新設）** | 「**いま作業中の数件を、1 つずつ全幅で読み・書き、素早く切り替える**」 | 数分〜数時間 |

### 3.2 重なりと矛盾

1. **タブと分割枠**: どちらも複数ノートを開いている状態。違いは**同時表示か切替か**。両方が主の枠（`selectedLid`）に関わる。固定枠は一覧を押しても動かない（性質が逆）ので、「タブは主の枠の入れ替え先」と決めないと曖昧になる。
2. **タブとスタック**: スタックは分割枠そのもの。さらに保存したスタック（フレーバー `stack`）は「ノートのまとまり」で、タブセットの保存と用途が重なる。
3. **タブと戻る・進む**: 履歴は「選択の列」、タブは「開いているものの集合」。ブラウザと同じく両立できる。ただし「新しく選ぶと進む側を捨てる」「同じ物は積まない」とタブ切替の相互作用の決めが要る（案 A で規定）。
4. **タブとピン留め**: 「常に出しておく」が重なる。PKC3 は左ペイン最上段の固定エリアで既に担っている。タブ側にピン機能を作ると同じ概念が 2 か所になる（§2-10「同じものは常に同じ場所」に反する）。
5. **タブと左ペインの探し方タブ**: 見た目が同じ「タブ」でも意味が違う（探し方 / ノート）。`tabs-a11y.ts` は既にタブ列が 2 つと明記している。3 つ目は読み上げ名で区別する。
6. **タブと 2 ペイン**: 2 ペインは中央を丸ごと別ビューにする。この間タブ列を出すか隠すかが論点（配置をモードで変えないことと、ファイラはノートを読まないことの綱引き）。
7. **タブと別ウィンドウ**: 別ウィンドウに出したノートをタブにも残すか。残すと 2 か所で編集でき、衝突の説明が要る。
8. **タブと 1 画面の原則**: 中央の本文を奪わないこと。タブ列は高さ 1 行（約 32px）だけ。スマホ幅ではそれも重い。

## 4. 案

### 案 A: 中央ペイン上のタブ列（開いたノートの作業セット）

**画面で何が起きるか**
- 中央ペインの本文の上に細いタブ列を出す。ノートを開くと、そのノートのタブが増える（既にあれば切り替え）。タブを押すとそのノートが主の枠に入る。
- 一覧の通常クリックは**今までどおり「いまのタブの中身を差し替える」**。Ctrl（Mac は Cmd）+クリック、ミドルクリック、一覧の右クリック「新しいタブで開く」で追加。
- タブは × で閉じる（片道にしない）。閉じたタブは右クリックの「最近閉じたタブ」から戻せる（上限 10）。
- 編集中のタブには `●`。未保存の編集があるタブを閉じるときは既存の編集の確認を通す。
- 削除・ゴミ箱へ移したノートのタブは自動で消える。ピン留めしたノートは常にタブ列の先頭に出す（ピン留め側が正で、タブ側にピン機能は作らない）。
- **タブが 1 枚のときはタブ列を出さない**（何もしていない user の画面は 1 バイトも変わらない）。

**状態とデータ**
- `AppState.openTabs: readonly string[]`（lid の並び）。主の枠は今までどおり `selectedLid`。**セッション限り**で始める（再起動で戻る要望が出たら端末の記憶へ。コンテナには入れない。ノートの内容ではなく見え方のため）。
- 履歴（`selectionHistory`）は共有。タブ切替も「選択」なので履歴に積まれる（ブラウザと同じ）。

**キーボード**: Ctrl+Tab / Ctrl+W はブラウザに奪われる。代わりに Alt+PageUp / Alt+PageDown（仮）で前後のタブ、Alt+1〜9 で位置指定（Alt+←/→ は戻る・進むで使用済み）。コマンドパレットにも「次のタブ」「前のタブ」「タブを閉じる」「閉じたタブを戻す」を載せる。

**スマホ幅**: 列を出さず、題名の横の「開いているノート ▾」メニュー 1 つに畳む（高さを増やさない）。

**既存機能への影響**
- 分割枠 / スタック: 変更なし。固定枠は主の枠と別。タブの右クリックにも「分割枠に出す」を置くが、判定は `PIN_SPLIT_ENTRY` の 1 か所。
- 2 ペイン: 2 ペイン表示中もタブ列は同じ場所に灰色で出し、押すと通常ビューへ戻ってそのノートを開く（配置を変えない）。
- 戻る・進む / ピン留め: そのまま。
- 別ウィンドウ: 別ウィンドウに出したノートのタブは「別ウィンドウで開いています」と表示し、押すとそのウィンドウへ移る。

**規模**: M〜L（タブ列、state、キー、メニュー、スマホ、a11y。`selectedLid` を動かす 6 つの case `app-state.ts:4776` との整合）。
**リスク**: 中央の高さを 1 行使う。タブが増えすぎる（上限で対処）。`selectedLid` の更新経路すべてでタブの追加・差し替えを正しく行う必要がある。

### 案 B: 「開いているノート」一覧（左ペインのタブ。履歴とスタックを統合）

**画面で何が起きるか**
- 左ペインの「探し方」タブの並びに「開いているノート」を足す。一覧は上から「ピン留め」「作業中のノート（新しい順）」「分割枠に載せているノート」。各行に ×（閉じる）と「分割枠へ」。
- 中央ペインは今までどおり 1 つだけ。切替は一覧の行を押す。履歴（`past`）を元にし、戻る・進むの別の見え方にもなる。

**状態とデータ**: 新しい state はほぼ不要（`selectionHistory.past` の重複除去 + 作業中の記録）。セッション限り。

**キーボード**: 一覧のフォーカス移動（既存）。専用キーなし。
**スマホ幅**: 左ペインの既存の動きに乗る。追加対応は少ない。

**既存機能への影響**
- 中央の高さを使わない（§2-10 の「中央の本文を奪わない」に最も忠実）。
- ただし**切替が 2 手**（左へ視線 + 行を押す）で、タブに期待される 1 押しの速度は出ない。
- 探し方のタブに「状態の一覧」が混ざり、`shell.ts:362` の前提（探し方は探し方、中央は常に開いているノート）が崩れる。タブ列が 2 種のうえに意味の違う 3 つ目が入る。

**規模**: S〜M。
**リスク**: user が求める「タブ」の体験にならない可能性が高い（#1982 の趣旨は切り替えの速さ）。

### 案 C: タブは作らず、既存の 2 列表示・スタックの入口を強める

**画面で何が起きるか**
- 一覧の右クリックと情報ペインに「スタックへ載せる」を常用の位置へ出す。スタックの状態（載せている数）を常に見せる。
- 分割枠が 2 つ以上のとき、枠のタイトルバーに「この枠を全幅にする / 戻す」を持たせ、実質タブのように使えるようにする。

**状態とデータ**: `splitLids` のみ。セッション限り（スタックを保存すれば永続）。

**既存機能への影響**: 新しい概念はゼロ。ただし分割枠は同時表示が前提で、**1 つを全幅で見て素早く切り替える**使い方に合わない（幅を分け合う、固定枠は一覧を押しても動かない）。

**規模**: S。
**リスク**: user の「タブ」の要望そのものを満たさない。段 5 の趣旨と食い違う。

## 5. 推薦

**案 A を、次の限定つきで推薦する。**

1. **役割を 1 行ずつ固定する**:
   - タブ = 主の枠に切り替えて出す作業セット
   - 分割枠 / スタック = 同時に並べるもの
   - ピン留め = 毎日開く定番（永続）
   - 2 ペイン = 整理
   - 戻る・進む = 直前の履歴
2. **ピン機能はタブに作らない**（#1377 が正）。ピン留めしたノートはタブ列の先頭に出す。
3. **既定は差し替え**。追加は Ctrl+クリック・ミドルクリック・右クリック。タブが 1 枚のときは列を出さない。
4. **保存はセッション限り**から始める。
5. スマホ幅は列を出さず「開いているノート ▾」メニューに畳む。

理由:
- 「複数ノートを開いて切り替える」要望に 1 押しで応える唯一の案（B は 2 手、C は要望を満たさない）。
- 既存の機能を壊さず、**役割で分けられる**（§3.1）。「同時表示」と「切替」は別の動線で、記法 1 つ = 動線 1 つ（§2-9）に当たる。
- 「1 枚のときは出さない」で、中央を奪わない・何もしなければ変わらない、を守れる。

## 6. 裁定してほしい点（推薦つき）

1. **タブを作るか**: 案 A（推薦）/ 案 B / 案 C。A なら、ノートを 2 つ開くと本文の上に細いタブ列が現れ、押すと切り替わる。
2. **一覧の通常クリックの意味**: タブを**差し替える**（推薦。今の画面と同じ）か、常に新しいタブで開くか。後者は 1 日でタブが数十枚になりやすい。
3. **タブの上限と溢れたとき**: 上限 12。超えたら、ピン留めと編集中を除く**いちばん古いタブを自動で閉じて「最近閉じたタブ」へ入れる**（推薦）。
4. **再起動後にタブを復元するか**: しない（推薦、セッション限り）/ する（端末に記憶）。
5. **別ウィンドウへ出したノートのタブ**: 残して「別ウィンドウで開いています」と出す（推薦）/ タブから外す。
6. **2 ペイン表示中のタブ列**: 灰色で出し、押すと通常ビューへ戻る（推薦）/ 隠す。
7. **キー**: Ctrl+Tab / Ctrl+W は使えないので、Alt+PageUp / PageDown と Alt+1〜9 でよいか（推薦）。
8. **保存したスタックをタブセットとしても使うか**: 今回はしない（推薦）。将来要望が出たら、スタックのフレーバーを再利用して「タブセットの保存」を足す。
