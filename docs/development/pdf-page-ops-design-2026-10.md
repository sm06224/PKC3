## 1. 画面で何が起きるか(案)

PKC の画面で開いた PDF の窓(段①の窓。設定「PDF を PKC の画面で開く」を入にした人だけ)に、
**ページの一覧**を足す。

1. 窓の左に、ページの小さな絵が縦に並ぶ(押すとそのページへ飛ぶ ── 読むときにも使える)
2. 絵を**ドラッグして並べ替える**。絵の上の **↻**(右へ 90° 回す)と **×**(このページを外す)
3. 何か変えると、上のバーに **「別の PDF として保存」** が出る
4. 押すと、**新しい添付が 1 つ増える**(名前は `元の名前 (編集).pdf`)。**元の PDF はそのまま残る**
5. ページを選んで **「選んだページを抜き出す」** ── 選んだページだけの新しい添付が 1 つ増える

⚠ **元を書き換えない**のは、#683(録音の切り出し)と #952 の規律
「元の録音・録画を書き換えない ── 加工したものは別に作る」と同じ向き。
上書きしたい人は、新しい方を残して元を消せばよい(消すのは既存の操作でできる)。

## 2. 🔴 いちばん大きい発見 ── 「外したページ」が file に残る道がある(2026-10-10 実測)

書く部品は **pdf-lib**(MIT。段①の比較表のとおり、頁操作ができて静的に焼ける唯一の候補。
mupdf は AGPL なので避ける)。pdf-lib にはページを消す道が 2 つあり、**結果が違う**:

| やり方 | 消したページの中身(文字の流れ) | しおり・フォームなど文書全体の設定 |
|---|---|---|
| **A. 開いた文書の中で外す**(`removePage` → `save`) | 🔴 **file に残る** | 残る |
| **B. 新しい文書へ、残すページだけ写す**(`copyPages`) | 🟢 **消える** | 🔴 **落ちる** |

実測(pdf-lib 1.17.1、自作 3 ページ・各ページに別の字):A で 2 ページ目を外して保存し、
全部の stream を展開すると **2 ページ目の字がそのまま在った**。B では無かった。
B は文書全体の設定(`/PageMode` で確認)を写さない。

🔴 **だから A は使わない。** user は「外した」ページが**消えた**と思って人に渡す ──
中身が残っていれば、その人の手元で取り出せる(画面で見えないだけ)。
⚠ これは user に見えない形で起きるので、気づく機会が無い。

🔑 **B を使い、落ちる物を画面で言う**(置き換えの作法 §10:相手が黙ってやっていたことを数える):

| B で落ちる物 | 扱い |
|---|---|
| しおり(目次) | 落ちる。保存の前に「しおりは引き継がれません」と 1 行出す(元に在るときだけ) |
| 入力欄(フォーム) | 落ちる(欄の見た目は残ることがある)。同じく 1 行 |
| 電子署名 | 書き換えた時点で必ず無効になる(どのやり方でも)。同じく 1 行 |
| 文書の題名・作成者 | 写し直す(pdf-lib の `setTitle` などで足りる) |

⚠ 並べ替えと回すだけなら A でも中身は残らないが、**道を 2 本にしない**(どちらの道を通ったかで
落ちる物が変わると、user から見て規則が読めない)。B 1 本にする。
覆る条件:しおりを落とさないことが、消した中身が残らないことより大事だと分かったら、
「並べ替えと回すだけのときは A」を足す(そのときも、外す・抜き出すは B のまま)。

## 3. 作り

### 3.1 どこで計算するか

- 窓の中の**使い捨ての worker**(`worker-lease.ts` の 3 規律:遅延起動 / 依頼のバッファ / アイドルで畳む)
  で pdf-lib を動かす。窓が閉じれば worker ごと還る(段①の pdf.js worker と同じ寿命)
- 渡すのは**ページ番号の並びと回す角度だけ**(`{ order: [3, 1, 2], rotate: { 3: 90 } }`)。
  bytes は窓が既に握っている Blob から `arrayBuffer()` で 1 度だけ取り、worker へ **transfer**(ゼロコピー)

### 3.2 本体への渡し方

- 段①の Office と同じ鎖:窓が **OPFS の棚**へ結果を置き、放送で「置いた」と言う → 本体が棚から読んで
  **新しい添付を作る**(書くのは writer lease を持つ本体だけ)
- 新しい添付の置き場:元の PDF の添付ノートと**同じフォルダ**、元と**同じつながり**は張らない
  (つながりは user のもの ── 勝手に増やさない)。作った後も**いま読んでいるノートの画面は動かさない**
  (#683 の「切り出したら読んでいたノートが消えた」の教訓)

### 3.3 断る形

| 形 | 画面に出す字(案) |
|---|---|
| パスワード付き(暗号化)の PDF | 「パスワードで守られた PDF は、ページを編集できません」── 一覧は出す(読むのはできる) |
| pdf-lib が読めない PDF | 「この PDF はページを編集できない形です」── 読む画面はそのまま |
| ページを全部外した | 保存ボタンを押せなくする(0 ページの PDF は作らない) |

⚠ 断っても、**読む・引用する**(段①)は今までどおり使える。

### 3.4 測ること(着地前)

- 常駐:窓のプロセス木の Pss(#114)── 100 ページ・20MB の自作 PDF で、保存の前後と、worker が畳まれた後
- 応答:ドラッグ中に窓のメインスレッドが止まらないか(long task)
- 中身が残らないこと:外したページの字が、出力の全 stream を展開しても 0 件(上の実測を unit に)

## 5. 決めてもらうこと(見え方が変わるもの)

1. **保存は新しい添付にする(元は残す)** でよいか ── 推薦:はい(上の §1)。
   覆る条件:「元を置き換えたい」が多いなら、保存の横に「元と置き換える」を足す(確認つき)
2. **ページの一覧を窓の左に常に出す** か、**ボタンで出し入れ**するか ── 推薦:ボタンで出し入れ・既定は出す
   (読むときに幅を取られたくない人がいる)
3. しおりなどが落ちることを、**保存の前に 1 行で言う**でよいか(§2 の表)── 推薦:はい
