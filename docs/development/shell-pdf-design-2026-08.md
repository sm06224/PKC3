## 第 1 部: コマンドシェル(#274)

### 全案が一致した骨格(裁定不要 ── 実装読みで決まった)

1. **語彙の正本は `KEY_COMMANDS` 1 本のまま拡張する**(`keymap.ts`)。
   `KeyCommand` に optional の `args?: readonly ArgSpec[]` と `dangerous?: true` を足す。
   args を持たない既存 52 件は 1 バイトも変わらない。
   ⚠ シェル専用の別配列を作らない ── `palette-rows.ts:10-14` / `keymap.ts:363-373` の
   「一覧を新しく作らない」規律は、この形でしか守れない(鍵・ヘルプ・パレット・シェルの
   4 面が同じ表を読む)。
2. **引数は「命令を選んだ後に聞く」**。`pickDateInApp` / `pickEntryInApp` /
   `pickSnippetInApp`(`binder.ts:2577-2676`)の連鎖が現物で、ダイアログは
   enqueue で直列化済み(`app-dialog.ts:403, 474`)。新設は `pickTextInApp`(自由文)と
   危険命令の確認行だけ。
3. **実行の径路は §7「口を 2 つにしない」を守る**: args 無しの既存命令は
   SHORTCUT_BUTTON click 委譲のまま(変更ゼロ)。args 有りは**新命令**として表に足し、
   features の executor が返す Dispatchable を直 dispatch(ボタンという既存の口が
   無いから 1 命令 1 口が保たれる)。既存ボタン命令への引数後付けはしない。
4. **1 行文法(`写す 会議メモ`)とパイプは段②**。実測で 5 か所の契約変更
   (戻り値 id→id+args / 字句化 / payload / ready 判定 / 型)が要ると分かっているので
   段①と混ぜない。パイプは作らない(「探す → 番号で次の命令」で足りる)──
   覆る条件: 実際に使って「つなげたい」が出たら段を足す。
5. **危険操作(消す・上書き)は確認必須 / eval の口は構造的に無い**(語彙は閉じた表)。
6. **#241(ファイラの命令行)と同じ層を叩く** ── 層は 1 つ、口は 2 つ。

  Dispatchable を返す)+ 確認行 + 履歴(settings 側 ── flag 枠を食わない)。
  語彙 × 引数の全数表を test に(「表に載っている件数は誰かが数えた分」)。

- **段③**: 1 行文法。契約変更 5 点はここで一括。

## 第 2 部: PDF エディタ(#275)

### 推薦: 段階案(#275 コメントで提示済み)

- **段①「読む + ノートへ引く」= pdf.js**(裁定不要のライセンス)。
  専用外殻の別窓(Office 型 host ページ ── index.html を開かないので #281 の
  「丸ごと」未決を再燃させない)。頁描画 / 頁送り / 拡大 / 文書内検索 /
  テキスト選択 / **「ノートへ引く」**(出典の頁番号つきで親ノートへ追記)。
  - 入口は既存の view-asset「別の窓で見る」の中身差し替え(ボタンを増やさない)。
    ⚠ 見え方が変わるので user へ 1 問提示済み。parse 失敗は現行の
    `<object type="application/pdf">` へ自動退避。
  - 描画の規律: 可視頁 ±2 を PNG `<img>` で(「描いたら焼く」)、LRU から外れたら
    即 revoke(2026-07-27 不可侵)。worker は viewer 窓の中 ── 窓の生死 = worker の生死。
  - 抽出の受け渡し: text は放送(64KB 上限)、超過は OPFS 棚。書くのは
    writer lease を持つ本体側だけ。
- **段②「書く」(注釈・頁操作)は別の設計 doc** ── pdf.js は頁操作 API を持たないので
  ここで初めてエンジン再審査(mupdf の AGPL 設問 or 注釈だけ pdf.js 先行)。
  外殻⇔本体の契約(放送・棚の鍵・頁ラスタ規律)は**エンジン非依存に切る** ──
  段②で乗り換えても外殻とノート側は変えない。
- 保存戻しは Office が完成させた鎖(replaceAsset → OFFICE_ASSET_SAVED →
  REQUEST_ASSET_REPLACE + OPFS 棚)をそのまま使う。

### 覆る条件

- 「読めるだけでは足りない、注釈と頁操作を最初から」→ mupdf 1 本案へ切替
  (その場合は AGPL の 1 問を先に通す ── 案の生死がそこで決まる)。
- 「描いたら焼く」の原文脈は文書内 mermaid のスクロール追従 ── 専用窓の PDF に
  同じ適用が要るかは canvas 直表示との比較実測を挟んで検算する(既定で焼く側に
  倒したのはこちらの読み)。

### 検証の計画(両部共通)

- 自作 fixture のみ(機密資料は使わない ── 2026-08-15 不可侵)
- 実物 A と実物 B を繋ぐ parity test(封筒を test に組ませない)
- 常駐はプロセス木 Pss(#114 ── worker の wasm は performance.memory に出ない)
- 命令実行は async ── 呼ぶ test の await を数え上げ、対照群を同じ it に(#299)
