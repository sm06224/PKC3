5. **危険操作(消す・上書き)は確認必須 / eval の口は構造的に無い**(語彙は閉じた表)。

#### 段①の中身(実装済み)

- **一覧の中身は `paletteRows` 1 本** ── 絞り込み・並び・押せない理由は操作のパレットと同じ

- **相手が要る操作**は `KeyCommand.needs: 'entry'` の宣言で表す。宣言のある操作を選ぶと

  2026-10-01 時点で**宣言のある操作は 0 件**(既存の「移す」系は実行の中で行き先を自分で聞く)。
  欄と配線だけ用意し、宣言と実体が 1:1 であることを test が全数で見る。
- 履歴(打った物をもう一度)は**この段では作らない**(別段)。
- #1172 の検索語の記録(datalist)は `>` で始まる字を憶えない(操作の名前は検索語ではない)。

### 推薦: 段階案(#275 コメントで提示済み)

- **段①「読む + ノートへ引く」= pdf.js**(裁定不要のライセンス)。
  専用外殻の別窓(Office 型 host ページ ── index.html を開かないので #281 の
  「丸ごと」未決を再燃させない)。頁描画 / 頁送り / 拡大 / 文書内検索 /
  テキスト選択 / **「ノートへ引く」**(出典の頁番号つきで親ノートへ追記)。
  - 入口は既存の view-asset「別の窓で見る」の中身差し替え(ボタンを増やさない)。
    ⚠ 見え方が変わるので user へ 1 問提示済み。parse 失敗は現行の
    `<object type="application/pdf">` へ自動退避。
  - 描画の規律: 可視頁 ±2 を PNG `<img>` で(「描いたら焼く」)、LRU から外れたら
    即 revoke(2026-07-27 不可侵)。worker は viewer 窓の中 ── 窓の生死 = worker の生死。
  - 抽出の受け渡し: text は放送(64KB 上限)、超過は OPFS 棚。書くのは
    writer lease を持つ本体側だけ。
- **段②「書く」(注釈・頁操作)は別の設計 doc** ── pdf.js は頁操作 API を持たないので
  ここで初めてエンジン再審査(mupdf の AGPL 設問 or 注釈だけ pdf.js 先行)。
  外殻⇔本体の契約(放送・棚の鍵・頁ラスタ規律)は**エンジン非依存に切る** ──
  段②で乗り換えても外殻とノート側は変えない。
- 保存戻しは Office が完成させた鎖(replaceAsset → OFFICE_ASSET_SAVED →
  REQUEST_ASSET_REPLACE + OPFS 棚)をそのまま使う。

### 段①の実装で決まったこと(2026-10-02。Gemini の答え = 設定で選んだ人だけ・既定はブラウザ内蔵の表示)

読む側の決まりではなく、**実装して初めて分かった / 選んだ**ことだけを残す:

- **入口は設定の 1 つ**(「PDF を PKC の画面で開く」。flag ではなく設定・既定は切)。ボタンは増やさず、既存の
  「別のウィンドウで見る」の**中身だけ**が替わる。切のままなら今までの `<object>` の窓が開く(対照群を test が持つ)。
- **窓は `noopener` で開き、放送で話す**(Office の窓と同じ。閉じた瞬間に process ごと還る)。窓が自分で `hello` と
  言い、本体は貸した ObjectURL の**字だけ**を返す ── bytes は放送に載せず、窓が `fetch` で Blob を握った瞬間
  (`loaded`)に本体が URL を返す(窓の寿命まで握らない)。`hello` が 5 秒来なければ「窓が開かなかった」と読んで
  その場で捨てる(`noopener` は null を返すので、開けたかは窓の名乗りでしか分からない)。
- **pdf.js は `legacy/` の版を配る**。素の版は `Map.prototype.getOrInsertComputed`(新しい ES の機能)をそのまま
  呼ぶので、持たないブラウザでは**頁が 1 枚も描けない**(手元の Chromium 141 で実測)。増えるのは +110 KB。
  🔑 **覆る条件**: 対象のブラウザが全部その機能を持つと言えるなら、素の版へ戻してよい(−110 KB)。
- **重い実体(`pdf/lib/`)は precache に載せない**(別立ての予算で見る。DuckDB と同じ)。窓の小さな HTML / JS
  (`pdf/` 直下の 4 file)は**載せる** ── 載せないと、オフラインで窓を開いたとき service worker が `index.html` へ
  退避して PKC をもう 1 枚開く。載せておけば窓は開き、本体が取れなければ**内蔵の表示へ退避**する。
  ⚠ オフラインで初めて読む人は内蔵の表示になる(IDB へ置く案は段②の前に判断する。段①では割り切った)。
- **引く先は「結びついたノート(意味 / 分類 / 時系列 / 出典の関係で、追記できる種類)→ 無ければ添付自身」**。
  書くのは本体側の既存の追記(`APPEND_TO_ENTRY`)で、窓は字と頁番号しか送らない(添付の lid は本体が窓を開くときに控える ── 窓の言い分で引く先を決めない)。
- 解析(pdf.js の worker)は窓の中で動き、頁の描画だけが窓のメインスレッドで走る(pdf.js はそこで canvas へ描く)。
  `noopener` の窓は本体と別の browsing context group なので、本体の入力と描画を窓の描画が止めにくい(実測は未了 ── 段①では測っていない)。
