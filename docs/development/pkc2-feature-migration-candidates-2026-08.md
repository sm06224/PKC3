## A. 探す・見る

- [ ] **A-1. 本文の全文検索**(PKC2 03 章)── **S〜M**
  いま PKC3 の絞り込みは**題名だけ**(`src/features/filter/title-filter.ts`。本文は常駐していない
  ので、そもそも主スレッドに探す材料が無い)。sqlite 側で引けば解ける ── 正本 doc §4 が
  **FTS5 の拡張点を予約済み**なので、そこを開ける判断でもある。
  🔑 これは「PKC2 に在ったから」ではなく、**ノートが増えると題名だけでは辿れなくなる**話。
  他のどれよりも先に効くと私は見ています
- [ ] **A-2. タグ**(PKC2 03 章の「タグ絞り込み」)── **M**
  PKC2 は record に `tags?: string[]` を持っていた。PKC3 には無い(entries 表に列が無い)。
  ⚠ ただし PKC3 は **frontmatter が本文の中にある**ので、`tags: [x, y]` を書けば
  「抽出列を 1 本足す」だけで済む ── **新しい概念を足さずに**実現できる形が既にある
- [ ] **A-3. 並べ替え**(更新順 / 題名順 / 種類順)── **S**
  いまは固定順(`entry_order`)のみ。索引は既にある
- [ ] **A-4. Inventory / Bases 風の query view**(PKC2 10.4)── **L**
  frontmatter で group by して表にする面。PKC2 では「著者ごと」等で使っていた。
  ⚠ **A-1 / A-2 が入っていないと空振り**(引く材料が無い)ので、順番は A-1 → A-2 → A-4
- [ ] **A-5. Filer の subset 切替**(Explorer / Book / Video / Novel / Contact sheet)(PKC2 10.1.3, 10.1.4)── **M**
  ⚠ 正直に言うと**これは薦めません**。PKC2 で「用途ごとの見た目」を 4 つ作った結果、
  どれも中途半端になった ── 封印した todo / form と**同じ壊れ方**に見えます。
  A-4 が入れば「query で作る 1 つの面」で足りるはず
- [ ] **A-6. 関係グラフ**(PKC2 10.2。別ウィンドウで関係性可視化)── **L**
  relations は PKC3 の表に在り、取込・書き出しも通っている。**しかし作る UI も見る UI も無い**
  ── いまの PKC3 で relations は「取り込んだら保持されるが、user からは触れない」状態。
  ⚠ グラフより先に **A-7(関係を作る・見る導線)** が要る
- [ ] **A-7. 関係の作成・閲覧の導線**(PKC2 03 章「関連付け」)── **M**
  上記のとおり、**PKC3 で唯一「データはあるのに user が触れない」機能**。
  A-6 を選ぶなら必ずこちらが先

## B. 書く

- [ ] **B-1. chart フェンス(chart.js)**(PKC2 の描画フェンス)── **M**
  PKC3 が render するフェンスは `html / mermaid / csv / tsv / psv` の 5 つで、**chart は無い**。
  🔑 **user は PKC2 で「chart.js は keep・むしろ強化対象」と判断しています**
  (PKC2 `CLAUDE.md`、2026-07-01)── PKC3 で落ちているのは移植漏れであって、
  方針転換ではないはずです。ここは確認したい点
- [ ] **B-2. テンプレートコマンド集**(PKC2 14 章)── **M**
  ⚠ **スニペット(P8 段⑧)と同じ領域**。あちらは「text blaze はフューチャーで一旦保留」で
  止まっている(裁定待ち 2)。両方を別々に作ると PKC2 の「同じ操作が 4 面に散る」を再演するので、
  **どちらか 1 つに寄せる**べき。設計は `p8-authoring-aids-design-2026-08.md` §4 に在る
- [ ] **B-3. TEXTLOG のログ行検索・置換**(PKC2 05 章)── **S**
  ログが伸びると要る。PKC3 の textlog は markdown の節なので、置換は本文操作で書ける
- [ ] **B-4. 入力補助のキーボード近道の拡充**(PKC2 06 章)── **S**
  いま PKC3 に在るのは `Ctrl+B/I/K`(書式)/ `Ctrl+S`・`Ctrl+Enter`(確定)/ `Esc`。
  PKC2 に在って PKC3 に無いのは **選択履歴の戻る・進む / ペインの開閉 / ヘルプ**。
  🔑 user 指示「マウスだけで完結し、キーボードは近道」に沿う ── **近道が無いのは方針未達**
- [ ] **B-5. PKC hint 機構**(PKC2 15 章)── **M**
  ⚠ 中身を確認したうえで薦めません。PKC2 の hint は `?pkc-debug=` で出す**開発者向けの面**で、
  user 向けの機能ではありませんでした

## C. 出す(書き出し・連携)

## 既に PKC3 に在るもの(**再移植しない**)

蒸し返しを防ぐため明記します。以下は実装を確認済み:

- text / textlog / spreadsheet(表)/ folder / attachment の 5 種類 + 追記欄
- PKC-Markdown の拡張記法 ── ルビ・圏点・整列(`||` `|>`)・区切り(`+++`)・コメント(`%%`)・
  図表番号(`:::figure` / `[@id]`)・変数(`{{vars.x}}`)・条件(`:::if`)・脚注・目次・
  見出し自動採番・コードの色分け
- mermaid(**PNG へ焼いてキャッシュ**、書き出しのみベクタ)/ csv・tsv・psv 表 / html サンドボックス
- 書式パネル(`Ctrl+B/I/K`)、Split View プレビュー
- 履歴 100 版 + ゴミ箱 + 復元
- 取込: PKC2 の全形式(単一 HTML 2 種 / pkc2-package / bundle 5 系統 / 素の .md)+ PKC3 の `.pkc3.zip`
- 書き出し: 閲覧用 HTML / バックアップ(`.pkc3.zip`)/ Markdown ZIP
- アプリランチャー(タイル・グループ・目印・専用 localStorage 2MB)
- フォルダ面(filer)、9 テーマ、PWA / オフライン / 更新の通知、ワーカー計器

## 現況の要約(選ぶときの材料)

| 領域 | PKC2 | PKC3 | 落差 |
|---|---|---|---|
| 書く(markdown) | 拡張記法 15 章ぶん | ほぼ移植済み | **小**(chart のみ) |
| 探す | 全文検索・タグ・並べ替え・query view | 題名の絞り込みのみ | **大** |
| 出す | HTML / ZIP / **Word / PPT / PDF / Pandoc** | HTML / ZIP / md | **大** |
| つなぐ | 埋め込み / pkc-ext / bookmarklet / グラフ | なし(relations は表だけ) | **大** |
| 保存 | IDB / OPFS / 実フォルダ | sqlite(OPFS)+ IDB Blob | **PKC3 が上**(裁定済み) |

## 私の推薦(参考。選ぶのは user です)

1 つだけ選ぶなら **A-1(全文検索)**。理由は「PKC2 に在ったから」ではなく、
**いまの PKC3 は題名しか探せず、ノートが増えた時点で使えなくなる**からです ──
北極星の「必要十分」に届いていない唯一の欠けだと思っています。

2 つ選べるなら **C-1(Office 書き出し)**。user が PKC2 で 2 度 keep と判断したものが、
PKC3 では黙って落ちています(移植漏れの疑い)。

⚠ 逆に **A-5(Filer subset)** と **B-5(hint)** は薦めません。理由は各項目に書きました。
