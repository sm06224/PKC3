## 1. 図 1 枚の焼き時間(ms)

**計器**: `commit-edit` を押した瞬間(`click` の capture)から、その本文の**全部の図の器が
`data-pkc-mermaid-state="ready"` になる**まで(PNG が焼けて `<img>` に載る)。**画素の読み込みは数えない**。
画面に出る面の実時間であって、`mermaid.render` 単体ではない(描画の予約・焼き・器の更新を含む)。

- 図は**毎回違う原文**(ラベルに回数を付ける)にして、**キャッシュに当たらない**ようにした(鍵が原文を含むため)
- 手順: ページの暖機 1 枚(`graph TD`、捨てる)→ 種類ごとに **cold 1 回**(その種類の最初の 1 枚。
  遅延 chunk の読込を含む)→ **warm 5 回**
- これを **3 セッション × 各版**(= warm は版ごとに **15 回**)。表は warm の**中央値(n=15)**。
  括弧は 3 セッションそれぞれの中央値(**セッション間のぶれ**を見るために残す)

| 種類(マニュアルの 22 種のうち) | 11 warm 中央値 | 12 warm 中央値 | 11 cold 中央値(n=3) | 12 cold 中央値(n=3) | 図の寸法 11 → 12(px) |
|---|---|---|---|---|---|
| flowchart (`graph TD`) | **78.4**(83.6 / 77.7 / 76.9) | **103.3**(102.2 / 90.4 / 136.3) | 87.6 | 111.7 | 122×257 → 168×220 |
| `sequenceDiagram` | **69.0**(84.5 / 67.1 / 65.3) | **81.9**(81.9 / 67.8 / 102.8) | 90.6 | 95.2 | 450×267 → 450×317 |
| `stateDiagram-v2` | **96.5**(110.6 / 96.5 / 90.6) | **131.6**(131.6 / 98.2 / 145.0) | 115.8 | **312.3** | 95×260 → 152×230 |
| `classDiagram` | **107.4**(99.3 / 107.4 / 108.6) | **118.9**(165.4 / 110.8 / 111.8) | 124.8 | 184.5 | 116×255 → 116×245 |

🔑 **読み方**:
- **warm(同じ種類の 2 枚目以降)は 12 のほうが 1 割〜6 割遅い**(+10〜+45 ms。いずれも **150 ms 未満**の中央値)。
  ただし 12 側は**セッション間のぶれが大きい**(例: flowchart 90〜136 ms)ので、**向きだけ**読む(倍率は書かない)。
- **cold(その種類の最初の 1 枚)は 12 で目立って遅い種類がある**: `stateDiagram-v2` と `erDiagram` が
  **約 3 倍**(116 → 312 ms / 86 → 305 ms)。ほかは +5〜+60 ms。**どれも 1 回きり**(その種類を初めて描くときだけ)。
- **寸法は一部の種類で変わる**(flowchart / state は縦横が変わり、sequence は縦が伸びる)。
  gantt / er は寸法が同じ。⚠ 全 22 種は測っていない(下)。

⚠ **この計器が支配されているもの**: 焼き時間の大半は **mermaid の描画 + PNG 化**で、
入力 → commit の待ちは含まない。実測のばらつき(同じ版・同じ種類で ±30% 程度)があるので、
**±20 ms 以内の差は読まない**。

## 3. 何を測っていないか(正直に)

- **22 種のうち 6 種だけ**(flowchart / sequence / state / class / er / gantt)。残り 16 種(`mindmap` / `sankey-beta` /
  `architecture-beta` 等)の焼き時間と寸法は測っていない。⚠ **全 22 種が PNG まで焼けることは別の検査**
  (`tests/smoke/mermaid-all.smoke.spec.ts`)で見ている ── 計測の代わりにはならない。
- **常駐は「ノート 4 件の flowchart を開いて回す」定常**。図の**種類を変えながら回す定常**は測っていない
  (12 は種類ごとに chunk を読むので、種類を広げると増分が出る可能性がある)。
- **大きな図**(数百ノード)は測っていない。elk は大きな図で時間・メモリの差が広がる可能性がある。
- **ブラウザは 1 つ**(`/opt/pw-browsers/chromium`)。headless_shell・実機の GPU 合成は測っていない。
- 焼き時間は**マウスで commit を押した直後から**の実時間で、**スクロール追従・先読み**(`visible-watch`)の
  効きは測っていない。
- 配る量(参考): アプリ本体 **9288.9 → 10991.7 KB**(+1702.8 KB)。主因は 12 の既定配置 `elk` の chunk
  (1,456 KB / gzip 453 KB)。**手違いの検出**(`scripts/check-dist.mjs`)の cap は 11500 KB へ上げた
  (残量 508.3 KB / 4.4%)。配る量そのものは判断理由にしない(user 指示 2026-08-03)。

## 4. 手順(再現用)

1. 11: `git archive <main の sha> | tar -x -C <別の場所>`、`node_modules` は 11.17.2 のもの、`npm run build`。
2. 12: 本 branch で `npm ci` → `npm run build`。
3. 焼き時間: 一時の smoke spec(`commit-edit` の click から `data-pkc-mermaid-state="ready"` まで)を
   **版ごとに 3 セッション**交互に実行。
4. 常駐: `node tests/bench/run-app-session.mjs --port=<port> --rounds=40 --attachments=6 --attachMb=2` を
   **版ごとに 6 回**交互に実行(preview はそれぞれ別 port、profile は別 path)。
