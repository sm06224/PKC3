## 1. 実地調査で分かった事実

### 1-1. 🔴 A-6 は「移植の穴」ではなく **新規設計**

台帳 #180 は A-6 を「PKC2 に在って PKC3 に無いもの」として並べていますが、**正確ではありません**。

| 主張 | 実態 |
|---|---|
| PKC2 の本体にグラフがある | ❌ **無い**。`AppState.viewMode` に `graph` は無く(PKC2 `src/adapter/state/app-state.ts:375`)、製品内グラフは PKC2 issue #790 で**撤去済み** |
| 撤去されたコードを読める | ❌ **読めない**(PKC2 の clone は shallow。`graph-canvas.ts` の履歴が無い)。残っているのは doc の記述だけ |
| いま PKC2 に在るもの | ✅ **独立した拡張アプリ** `PKC2-Extensions/graph/`(TS 1,640 行)。**Cytoscape.js + fcose + edgehandles / canvas 描画 / 別ウィンドウ(sandbox iframe)/ postMessage 越し** |

⚠ **「別ウィンドウで」という user の明示指示は PKC2 側に見つかりませんでした。**
別窓は「core から撤去して外部で再実装する」(PKC2 user direction 2026-06-10)という
**構造上の決定の帰結**です。#186 の題の「別ウィンドウ」を要件として扱う根拠はありません。

### 1-2. PKC2 の拡張でできたこと(参考。全数)

4 ビュー(探索 / フォルダ整理 / つながり / 時系列)× 5 色分け軸(種別 / カラータグ / タグ /
フォルダ深さ / クラスタ)、検索ハイライト(**レイアウトを動かさない**)、内部・外部リンクのトグル、
添付と Todo の集約、**ドラッグでフォルダへ移動**、**線を引いて関係を作る**、ミニマップ、凡例、
ダブルタップで本体に開く(シングルは選択だけ ── 誤操作で面が飛ぶのを潰した形)。

### 1-3. 🔴 PKC2 に**性能の実測は 1 件もありません**

`bench-results/` にグラフのシナリオが無く、唯一の数値目標「1000+ node で 60fps」は
doc 自身が「**実機検証が必要**」と書いたまま凍結。
⚠ したがって「PKC2 では N 件まで軽かった」と**語れる根拠はありません**。測るなら新規に組みます。

### 1-4. PKC2 から持ち込んではいけない作り(コードで確認)

## 3. 道は 3 本

### (a) cytoscape で**操作できるグラフ**を描く(canvas)

- ✅ **依存が増えない**(mermaid が既に持ち込み済み)。レイアウト(fcose)を自前で書かない
- ✅ **押せる**(ノードを押す → 本体の選択が動く)。PKC2 の実績と**踏んだ罠が分かっている**
- ✅ **canvas なので「SVG を画面に置く」不可侵指示に触れない**(GPU 合成に乗る)
- ⚠ canvas は **DOM から中が見えない** ── 観測点は「数を属性で外に出す」形になる
  (PKC2 の smoke が実際にそうしている)
- ⚠ 常駐メモリは要素数に比例。**窓/面を閉じたら `destroy()`** を落とすと static に漏れる

### (b) mermaid の原文を作って **PNG に焼く**

- ✅ 既存の産出器・キャッシュ・テーマ追従・ObjectURL の寿命管理が**ただで付く**
  (`DiagramKind` を 1 つ足すだけ。chart の実装は 17 行)
- 🔴 **押せない。** しかも土台が無い ── `usemap` / `elementFromPoint` は **src に 0 件**、
  さらに **`renderToPng` は SVG を内部で捨て、キャッシュに当たると `produce` を呼ばない**
  ので、**2 回目以降はノードの座標を取る機会がありません**(当たり判定を持つなら
  キャッシュ行に領域表を足す設計が要る)
- 🔴 **mermaid はメインスレッドで 1 枚ずつ**(DOM を要求するのでワーカーに逃がせない)。
  大きなグラフは long task に直結
- 🔴 **焼く倍率に頭打ち**(面積 4M px)── 大きなグラフは**ぼける**(120 節の chain で実測済みの型)
- 🔴 **題名のエスケープ規則が無い**(`"` `[` `]` `-->` 等を含む題名で図が丸ごと出ない)

### (c) 自前で SVG / canvas を描く

- ✅ 依存 0・当たり判定も自由
- 🔴 力学配置を自前で持つ = **PKC2 が撤去した `graph-canvas.ts` の再演**。
  しかもその実装は**読めない**(shallow clone)ので、根拠なしの車輪の再発明になる

## 4. 🔴 裁定を仰ぎたい 5 点

| # | 決めたいこと | 推薦 | 覆る条件 |
|---|---|---|---|
| **A** | **描き方**((a) cytoscape / (b) 焼いた PNG / (c) 自前) | **(a)** ── 依存が増えず、押せて、canvas なので「描いたら焼く」とも衝突しない | 「押せなくてよいから最小で」なら (b)。ただし**押せない図は動線が 1 つ減る** |
| **B** | **出す場所**(中央の面 / 別ウィンドウ) | **中央の面**(ViewMode を 1 語) ── 「同じものが常に同じ場所にある」業務画面方針 | 「**本文と並べて**見たい」が主目的なら別窓。⚠ 別窓は編集中でも開ける利点がある(中央の面は編集中は開けない) |
| **C** | **色分けの軸** | **種別 / 関係の種類 / フォルダ深さ**(常駐 state だけで引ける) | **タグで色分け**したいなら §1-6 のとおり**索引の新設**が要る(別 issue) |
| **D** | **描く範囲** | **既定は選択中から 2 ホップ**、全体表示は**上限つき**(達したら件数を出す ── 黙って切らない) | 「常に全体」なら既定を反転。⚠ PKC2 は上限なしで、**実測も無い** |
| **E** | **編集(ドラッグで移動 / 線を引く)** | **段① では入れない**(読むだけ)。段③ で足す | 「作れないグラフは意味が無い」なら段① に入れる |

### ついでに決まること(A/B が決まれば従属)

- **`structural`(居場所)をグラフに出すか** ── 情報ペインは「居場所は上の行が出すので関係の欄には出さない。
  同じものを 2 か所に出すと『消したのに片方に残る』に見える」と明記(`inspector.ts:171-176`)。
  グラフは**面が違う**ので出してよいと考えますが、**出すなら凡例にも出す**(§1-4e)。
- **ゴミ箱の辺** ── `listRelations` は端点が居ない辺を返します(復元のために消さない設計)。
  情報ペインは「(見つかりません)」と出す側を選んでいる ── **グラフも同じ答えにする**
  (判定を 2 か所に散らさない)。

## 5. 推薦(1 本)

> **(a) cytoscape で、中央の面に、読むだけのグラフを 1 本目として出す。**
> 色は常駐 state で引ける 3 軸、既定は選択中から 2 ホップ、編集は後段。

理由:

1. **依存が増えない** ── cytoscape / fcose は mermaid が既に持ち込んでいます
   (`package.json` に明示的に足しますが、配る量は実質変わりません)
2. **PKC3 のほうが土台が良い** ── relations が常駐し、親と種類の正本が 1 つずつ在るので、
   PKC2 の最大の負荷源(§1-4a)と最大の不整合(§1-4d)を**構造ごと回避**できます。
   **新しい storage op は 0 個**
3. **押せる**(動線が死なない)── (b) は土台が無いうえ、キャッシュの作り上
   **座標を取る機会が消える**ため、後から足すのが難しい
4. **1 本目を小さく畳める** ── 読むだけなら「面の器 + 純関数 + 描画器」。
   編集と索引は性質が違うので分けます(「1 job = 1 主張」の PR 版)

### 段階

| 段 | 中身 |
|---|---|
| ① | **読むだけ**(2 ホップ / 3 軸の色 / ズーム・パン / 押すと選択が動く / 件数を属性で出す / 描けないときは面に理由を出す) |
| ② | フォルダの箱・ビュー切替・検索ハイライト(**レイアウトを動かさない**)・本体→グラフの追従 |
| ③ | 編集(ドラッグで移動 = `setEntryParent` / 線を引く = `upsertRelation`)── 既存の経路をそのまま使う |
| ④ | **常駐と応答の実測**(対照群 = 同じ件数の一覧表示)。⚠ PKC2 に実測は無いので新規に組む |
| ⑤(別 issue) | **タグの索引**(全 body を舐める新経路 → worker)── これだけ性質が違う |

### 検証の型(PKC2 の轍を避ける)

- 🔴 **canvas は DOM から見えない** ── ノード数 / 辺数 / **落とした件数**を属性で外に出す。
  それが唯一の観測点になる
- 🔴 **面を閉じたら `destroy()` と購読解除**(常駐が漏れる型)
- 🔴 **凡例と実線の非対称を作らない**(PKC2 は `temporal` / `provenance` が凡例だけに出ていた)
- 🔴 **親は `resolveCanonicalParents` を呼ぶ**(自前で決めない)
- 🔴 **ゴミ箱の辺の答えを情報ペインと揃える**

## 6. 危険な所(先に名指ししておく)

1. 🔴 **常駐メモリ** ── cytoscape の Core は要素数に比例。面を開きっぱなしにする使い方が
   想定されるので、`destroy()` と購読解除を落とすと漏れます。⚠ ミニマップを**2 個目の Core**で
   作らない(PKC2 の作り)
2. 🔴 **更新のたびの再構築** ── PKC3 は relations が常駐するぶん更新の頻度が上がりえます。
   **差分適用**を最初から設計に入れる(PKC2 は辺を毎回全消し)
3. 🔴 **件数の上限と scope を先に決める** ── PKC2 は上限なし・実測なし。
   「全件を描いてから測る」は user 指示(もっさりが嫌)に正面から当たります
4. ⚠ **面を 1 つ増やすとは、将来畳むときの負債も 1 つ増やすこと** ──
   かつて封印していた kanban / calendar が「導線を外しただけでは戻らない」状態でした
   (`sealed.ts` の `SEAL_REASON`)。⚠ **2026-08-19 に 2 つとも解き**(#276 / #277)、
   **2026-08-23 に左の列の「予定」タブへ引っ越した**(#292 段⑤)ので、
   **`SEALED_VIEWS` はいま空**です ── それでも教訓は変わりません。
   **畳む条件**をこの doc に書いておきます:
   **「3 か月後に一度も開かれない実測が取れたら、導線を外して封印する」**
5. ⚠ **deep link をクエリで足さない**(URL クエリの切替はフラグ ── 不可侵指示 2026-08-07)。
   足すなら 15 枠(いま 2 使用)+ `foldWhen` + フラグ画面
6. ⚠ **書き出しの面** ── 閲覧用 HTML は図を焼かず原文のまま出し、Markdown ZIP は relations を
   落として警告します。「関係図を本文に貼る」方向へ広げるなら、この 2 面の扱いを先に決めます
