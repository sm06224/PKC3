# 保存していない編集の復元(#1376)

出どころ:#1376。Gemini が user の委任(#1163 のコメント)で裁定した ──
**編集中にタブが死んだら、次に開いたとき、保存していない字を戻すかどうか 1 行で聞く。**
画面に増えるのは**その 1 行(戻す / 消す)だけ**で、字は端末の外へ出さない
(CLAUDE.md 6 巡目の検算 ⑧「見える概念を増やさない」の範囲内)。

## 1. 何が起きていたか

編集中の字は画面の状態(`AppState.openBody`)にしか無い。保存の経路は `COMMIT_EDIT` だけで、
`beforeunload` で書く経路も無い(`main.ts` の `writeBackFile` の注記も「下書きは AppState にしか無い」と言っている)。
タブがクラッシュする・ブラウザが再起動する・電源が切れると、保存していない字は戻らない。

## 2. 作り

| 部品 | 場所 | 役目 |
|---|---|---|
| 判断(純関数) | `src/features/draft/draft-recovery.ts` | 上限・指紋・戻せるかの判定・1 行の字・控える頻度 |
| 置き場 | `src/adapter/platform/draft-store.ts` | IndexedDB `pkc3-drafts`(端末ごと)。生きているタブの印(Web Locks) |
| 控える側 | `src/adapter/platform/draft-writer.ts` | 状態を見て、いつ控え・いつ消すか |
| 聞く側 | `src/adapter/ui/render/draft-offer.ts` + `shell.ts` の `draft-offer` | 起動のとき 1 行を出し、戻す / 消すを受ける |
| 戻して入る | `app-state.ts` の `START_EDIT { restoreBody }` | 本文だけ差し替えて編集に入る(基準は disk のまま。**書かない**) |

### 置き場を IndexedDB にした理由
本文は最大 2 MB あり、localStorage(合計 5 MB 前後)では 2 件で尽きる。`copy-history-store.ts` は
localStorage だが、あちらは 20 件 × 小さい字である。**container・書き出し・バックアップ・履歴・メッセージには入れない**
(`notice-store.ts` / `copy-history-store.ts` と同じ判断。確定していない字を端末の外へ出さない)。

### 控える頻度
打鍵が止まって **1 秒**で書く。打ち続けていても最初の打鍵から **5 秒**で必ず書く(`DraftThrottle`)。
ページを隠す・離れる(`visibilitychange` / `pagehide`)ときは待っている分をすぐ書く(IndexedDB が書き終える保証は無い ── 保険である)。
題名の欄(`editor-title`)は確定まで state に写らないので、`input` を document で拾い、控えるときに欄の値を読む。

### 消す条件
- **保存(確定)**:確定した瞬間ではなく、**disk に届いたとき**(`openBody.persisted` が確定した本文になったとき)に消す。
  確定の直後に消すと、書込が落ちた回に字がどこにも残らない。届く前に別のノートへ移るなど、届いたことを見られなかった回は
  控えが残り、次の起動で「保存されている本文と同じ」と判定されて黙って片付く。
- **取り消し**:消す。ただし**戻して入った回の取り消しは消さない**(「やめる」を押しただけで戻した字を二度と戻せなくしない)。
  このとき起動の 1 行がまた出る。
- 別のノートへ移った / 打って消して編集前の本文と同じになった / 2 MB を超えた(古い控えを残すと、戻したときに新しい字が失われて見える)。
- どれも**自分が書いた控えだけ**。ただし戻して入った回は、起動で聞いた別タブ(死んだタブ)の控えを引き取っているので、保存の到着では誰の控えでも消す。
- 中身を消してまっさらにする / 建て直し(`forgetLocal`)は**全部**消す(`clearAll`)。新しい入れ物は別の cid で、古い控えは一覧に出ないまま端末に本文が残り続けるため。

### 起動のとき
本体の窓だけが聞く(付箋・別窓は聞かない。同じ控えを 2 つの窓が聞くと、片方で戻したのにもう片方に残る)。
コレクションの控えを新しい順に読み、保存されている本文と比べる(`judgeDraft`):

| 結果 | 扱い |
|---|---|
| ノートが無い(`gone`)/ 控えと同じ本文・題名(`same`) | 聞かずに黙って片付ける |
| 編集に入ったときのまま(`plain`) | 「保存していない編集が残っています(題名)」 |
| 編集に入ったあとで保存されている本文が変わった(`moved`) | 「…(題名)。別の場所で更新されています。戻して保存すると、その更新は履歴に残ります」 |
| 本文は同じで**題名だけ**違う | 聞く(`same` は本文と題名の**両方**が同じときだけ。題名だけ直した控えを黙って片付けない) |
| 別のタブが今まさに編集している控え | 聞かない(Web Locks の印。取れない端末は 30 秒より新しい控えを生きていると見る) |

複数あるときは**新しい順に 1 件ずつ**聞き、「ほか N 件」を添える(一覧や選択の画面は作らない ── 見える概念を増やさない)。

- **戻す**:そのノートを選び(本文が届くのを待って)編集に入り、控えの本文と題名を入れる。**保存を押すまで disk は 1 バイトも動かない。**
  `moved` のときも同じ ── 保存を押すと、そのときの disk の本文(別の場所で更新された版)が履歴に積まれる
  (`COMMIT_EDIT` の checkpoint。`draft-recovery.test.ts` が、戻した控えを新しい disk の上へ保存して checkpoint が立つことを見る)。
  🔴 **控えは、編集に入れても消さない。** 入れなかった回(ロックが取れない・追記の書込中・本文が届かない ── 10 秒で畳む)は
  何も失わず、1 行を戻して理由を言う。入れた回は「保存を押すまでノートは変わりません」と 1 度だけ言う。
  編集中は 1 行を隠す(押しても断られるだけ)。終わったらまた出す(読み直して判定し直す)。
- **まだ答えていない控えがあるノートは、書き手が上書きしない**(1 行を無視してそのノートを打つと、1 秒後に古い控えが新しい字で置き換わるため)。
- **消す**:控えを消す。


### 複数のタブ
鍵は「コレクション × ノート」。2 枚のタブが同じノートを編集したら**後に書いたほうが残る**(last-writer-wins。控えは保険であり、
タブごとに別々に持つと「どれを戻すか」を user に聞くことになり、見える概念が増える)。**消すのは自分が書いた控えだけ**
(控えの `tab` が自分のときだけ)── 別のタブの編集中の控えを、こちらの保存で消さない。

### 上限(超えたときに起きること)
- 1 件 2 MB(本文 + 題名の UTF-8)。超える間は**控えない**(編集はそのまま続く。そのノートだけ、タブが落ちたときに戻せない)。
- 全体で 20 件。超えたら**古い控えから**消える(書くときの同じ transaction の中で)。
  ⚠ 全コレクション・全タブ通しなので、**別のタブが編集中の控えのうち古いものを押し出しうる**
  (押し出されたタブは次の打鍵で書き直す)。実ブラウザで 21 件目を書いて 20 件に収まること・最古が落ちることを見ている(smoke)。

## 3. 範囲外(やらなかったこと)
- **章の欄・コード枠の欄**(`sectionDraft` / `codeDraft`)の控え:全文編集の `openBody` と別の入れ物で、今回の主題(ノートの全文編集)の外。
  壊れたときの戻し方が必要なら別の issue で。
- ステータスバー・メッセージ・ログへの出力:控えの中身(字)は一切出さない。

## 4. これが分かったら覆る
- 打鍵ごとの IndexedDB 書込が体感を落とす(long task が出る)→ 頻度を下げる(`DRAFT_QUIET_MS` / `DRAFT_MAX_WAIT_MS`)。
  書込は非同期でメインスレッドを塞がない前提だが、計測はしていない。
- 「戻す」を押す前に消えてほしい人が居る(プライバシー)→ 「消す」を押さないまま放置すると控えは残り続ける。
  上限 20 件で頭打ちだが、期限で消す案がある(今回は入れない ── 見える概念を増やさない)。
