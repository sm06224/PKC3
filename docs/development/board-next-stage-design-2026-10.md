## 1. user の身に起きること(画面の言葉で)

いまの板(付箋と線)の事実:**付箋の字の大きさは全部同じ**(読む画面の標準)/ **付箋は必ず水平**/
**付箋は 1 枚ずつしか動かせない**。PowerPoint から取り込んだ図でグループになっていた物は、
**「取り込めなかった物」として数えられ、板には出ない**。

### 1.1 字を大きく / 小さくする

| 場面 | 何が起きるか |
|---|---|
| 付箋の上で右クリック | 色の項目(「塗りの色…」など)の並びに **「文字を大きくする」「文字を小さくする」** が出る |
| 「文字を大きくする」を 1 回押す | その付箋の字だけが標準 → 大 に変わる。もう 1 回で 大 → 特大。**特大では「大きくする」は出ない** |
| 「文字を小さくする」を押す | 標準 → 小。**小では「小さくする」は出ない** |
| 戻したいとき | 字の大きさを変えた付箋にだけ **「文字の大きさを標準に戻す」** が出る(置けるなら外せる)。押すと本文の札が消える |
| 見た目 | 付箋の中の見出し・箇条書きも**同じ比率で**大きくなる。付箋の枠(`w=` `h=`)は変わらない。収まらなければ今までどおり付箋の中で送れる |
| 設定の「文字の大きさ」を変えた | 標準も変わるので、大・特大・小も**一緒に追従**する(絶対値で持たない) |

### 1.2 付箋・枠を回す

| 場面 | 何が起きるか |
|---|---|
| 付箋の上で右クリック | **「右へ回す(15°)」「左へ回す(15°)」** が出る。回した付箋にだけ **「回転をなくす」** が出る |
| 押すと | 付箋が**中心を軸に**回る。字・枠・形(ひし形など)・掴む口が一緒に回る |
| 回した付箋を動かす | 今までどおり ⠿ をドラッグ。**位置の座標は回す前の四角の左上**のまま(回しても `x=` `y=` は変わらない) |
| 回した付箋に線がつながっている | 付箋の辺ごと一緒に回る。**右辺に付けた線は、付箋を 90° 回すと下側から出る**(PowerPoint と同じ動き。§5 で選択肢を示す) |
| 角を伸縮する | 付箋の向きに沿って伸び縮みする(画面の右下ではなく**付箋の右下の角**を掴む) |

### 1.3 いくつかの付箋を 1 つとして動かす

| 場面 | 何が起きるか |
|---|---|
| まとめる | 付箋の上で右クリック →**「グループにする…」**。窓が開き、板の付箋が**最初の 1 行**と一緒に一覧で出る。右クリックした付箋にチェックが付いていて、まとめたい付箋にチェックを足して「決める」 |
| 名前 | 自動で `グループ1` `グループ2` …(使われていない最小の番号)。名前は本文を直せば変えられる |
| 動かす | グループの**どれか 1 枚の ⠿ をドラッグ**すると、同じグループの全部が同じだけ動く。離したとき**1 回の書込**で全員の位置が本文に書かれる(途中で一部だけ動いた状態にならない) |
| 1 枚だけ動かしたい | 右クリック →**「グループから外す」**。外した付箋は今の位置のまま、ほかのメンバーは残る |
| 全部ばらす | 右クリック →**「グループを解除」**。全員の札が消える |
| 線 | 線はグループとは関係なく、**つながった付箋に追従する**(今までと同じ)。グループの中どうしの線も、動かせば追従 |
| 大きさ・色・文字の大きさ・回転 | **1 枚ずつ**(グループにまとめて効かせない)。まとめて効かせたい要望が出たら次の段 |
| 見分け | グループの付箋には**印は出さない**(地は無彩色、色は情報にだけ)。右クリックの項目に「グループから外す」が出るので分かる。 ⚠ 見た目の印が要るかは §7 の設問に含めない(使ってみて言われたら足す) |

## 2. 記法

### 2.1 いまの並び(事実、`place-notation.ts` / `place-color.ts` / `place-shape.ts`)

`:::format{#名前 .pkc-place x= y= w= h= z= shape= fill= stroke=}`。**どの札も 1 つずつ独立して読まれ、書換は札ごと**
(`setToken` / `setStyleToken`)。**知らない札は描画が `data-pkc-<札>` としてそのまま焼く**
(`markdown-render.ts` の format 塊の「その他 kvs」)。**書き換える側は自分の札の字しか触らない**ので、
知らない札は壊れない。値の読めない札は**描くときに無視し、本文は消さない**(段④の `fill=javascript:` がその前例)。

### 2.2 案の比較

#### 文字の大きさ

| | 案 | 例 | 長所 | 短所 |
|---|---|---|---|---|
| **A(推薦)** | **名前の 3 段階**:`size=small` / `large` / `xlarge`(無い = 標準) | `size=large` | ①**設定の文字の大きさに追従**する ②PowerPoint の `sz` へ**丸い数**で写せる(14 / 27 / 40 pt、標準 18 pt)③形(`shape=`)と同じ**閉じた集合**で、綴りの検査が簡単 | 13 px 固定のような**細かい指定はできない** |
| B | 数(px):`size=20` | `size=20` | 細かく書ける | ①設定の文字の大きさを変えても追従しない ②PowerPoint の `sz` との換算が要る(標準が画面 13 px / スライド 24 px と**元から合っていない**)③「右クリックの 3 つ」と**数の範囲**が食い違う |

→ **A**。覆る条件:「15 px にしたい」のような**細かい指定の要望**が出たら、`size=` に**数も受ける**(名前と数の両方。段④の `width=` が
右クリックは 3 つ・記法は 1〜16 を受けるのと同じ形)。名前は消さない。

読む規則(1 か所): `parsePlaceSize(raw): 'small'|'large'|'xlarge'|null`(読めない = 無視 = 標準)。画面・PowerPoint 書き出し・取り込みの全部が**この 1 本**を読む(§7 の型)。

#### 回転

| | 案 | 例 | 長所 | 短所 |
|---|---|---|---|---|
| **A(推薦)** | **`rotate=度`**(右回り、0〜359 の整数。負・小数・単位つきは読めない = 無視) | `rotate=15` | ①CSS の `rotate(deg)` と PowerPoint の `rot`(60000 分の 1 度)の**向きが同じ**(どちらも時計回り)。換算は ×60000 だけ ②`x=` `w=` と同じ「数だけ」の作法 | 小数の度は書けない |
| B | 4 つの向きだけ:`rotate=right` | | 綴りが閉じる | 15° 刻みが書けない。PowerPoint で斜めの付箋が取り込めない |

→ **A**。⚠ 負の値(`rotate=-15`)は**書かない**(読めない = 無視)── 0〜359 に正規化して書く。取り込みは `rot` を mod 360 に直す。

#### グループ

| | 案 | 例 | 評価 |
|---|---|---|---|
| **A(推薦)** | **付箋ごとの名前の札**:`group=名前` | `:::format{.pkc-place x=40 y=40 group=見積}` | 本文は**平らなまま**(塊の入れ子が無い)。1 枚を外す = その札を消すだけ。**名前を指す作法は線の `from=` / タグと同じ**(2026-08-19 の裁定:名前で指す。id を本文に書くと静かに壊れる) |
| B | **囲む塊**:`:::format{.pkc-group}` の中に付箋の塊を入れる | | 🔴 **採らない**。実装の事実が 3 つ当たる:①入れ子の `::::format`(4 コロン)は**描画されない**(`place-notation.ts` 冒頭の注記)②塊の行番号・`blockSpanAt`・消す範囲・掴んで書く行番号が**全部「平らな塊」前提**で、囲むと**既存の付箋の開き行の意味が変わる**(「既存の本文の意味を変えない」に反する)③古い版で開くと内側の `:::` が閉じとして読まれて**壊れる** |
| C | 囲まず、グループ側に名簿:`:::format{.pkc-group members=a,b,c}` | | 採らない。**名前の無い付箋をグループに入れられない**(名簿は名前で指すので、`connectPlaces` のように勝手に `#板N` を足すことになる)/ 付箋を消したとき名簿が**黙って腐る** |

→ **A**。既存の読み手との衝突を調べた:`data-pkc-group` は launcher / 右クリックの入れ物 / 右の列が使っているが、
**すべて `data-pkc-action` を持つ要素に限って読む**か書く側で、属性セレクタで拾う所は `src` に 0 件(grep)。
板の付箋に付いても**どの読み手にも当たらない**。⚠ ただし将来誰かが `closest('[data-pkc-group]')` を書くと当たるので、
`tests` に「板の付箋の `data-pkc-group` を読む口は 0 件」を 1 本置く(実装の段で)。
覆る条件:衝突が見つかったら札の名前を `together=` のように替える(記法は新しいので、配る前なら 1 語の直しで済む)。

値は **名前**(`NAME_RE` = 線の `#名前` と同じ。日本語可)。読めない綴り(空白・記号)は**無視し、本文は消さない**。
**1 枚の付箋は 1 グループにだけ入る**(札が 1 つなので構造から)。入れ子のグループは**作らない**(§4.3)。

### 2.3 既存の本文の意味を変えないこと(確かめた)

| 書き方 | 今の版が描く物 | この設計の後 |
|---|---|---|
| 3 つの札が**どれも無い**付箋 | 標準の大きさ・水平・単独 | **同じ**(読む札が無ければ何も足さない。PowerPoint の書き出しも `sz="1800"` `rot` 無し `grpSp` 無しで**今と 1 バイトも変わらない**) |
| 手で `size=` / `rotate=` / `group=` を別の意味で書いていた本文 | 札は読まれず `data-pkc-size` などとして焼かれ、どの読み手も拾わない | 読める綴りなら**効き始める**。⚠ これは意味の変更に見えるが、**今まで効いていなかった札が効く**だけで、そんな本文は壊れない(読めない綴りは無視)。🔎 実在する本文の数は**測れない**(user のデータ) |
| `size=` と `fill=` の併用 | | 札は独立。順序に意味は無い |

### 2.4 古い PKC3 で開いたとき(実装を読んだ結果)

- **描画**:`size=` `rotate=` `group=` は format 塊の「その他 kvs」として `data-pkc-size` などになり、**CSS も JS も読まない** →
  **標準の大きさ・水平・ばらばらの付箋として出る。壊れない**
- **古い版で付箋を動かしたり大きさを変えたとき**:書換は `x=` `y=` `w=` `h=` `z=` `shape=`(と `fill=` `stroke=` `width=`)の**自分の札だけ**を
  差し替える(`spliceTokens` / `spliceStyleLine`)ので、**新しい札は残る**(1 バイトも触らない)。
  ⚠ 1 つだけ癖:`:::.pkc-place` のような**括弧の無い Tier 1 形**は、書換で括弧つき形へ整えられる。
  新しい札は括弧の中にしか書けないので、新しい版が書いた付箋は**必ず括弧つき**になり、この癖には当たらない
- **古い版で開いて保存**しても、本文は書き換わらない(描画だけの話)
- **古い版が `.pptx` を書き出す**:`rot` `sz` `grpSp` は出ない(札を知らない)。**新しい版で書き出し直せば出る**
- **古い版の取り込み**:`rot` `sz` は読まれず、`grpSp` は「取り込めなかった物」に数えられて**中の付箋も板に出ない**(今の挙動)

## 3. PowerPoint との往復

書き出しは `src/features/export/pptx.ts`(`textBox` / `boardShapes` / `connectorXml` / `boardBounds`)、
取り込みは `src/features/import/pptx-board.ts`(`readShape` / `readPptxSlide`)。
⚠ 取り込みの対応表は**書き出しの表から引く**作法(`PRST_OF` 等)なので、新しい対応も**書き出しの側に正本を 1 つ置く**。

### 3.1 文字の大きさ(`sz`)

| | 書き出し | 取り込み |
|---|---|---|
| 今 | 全部 `sz="1800"`(`SZ.body`)で固定。付箋の字の大きさは**運べない** | `sz` を**読まない**(全部標準になる) |
| 後 | `size=small/large/xlarge` → **`1400` / `2700` / `4000`**。無ければ今の 1800(`runXml` に渡す `sz` を付箋ごとに替えるだけ) | 付箋の**字数でいちばん多い `sz`**を採り、標準(1800)との比で**いちばん近い段**へ丸める。`normAutofit` の `fontScale` があれば掛けてから丸める |

- 見出しの太字・箇条書きの深さは**今までどおり**(`h` は `bold` になるだけで大きさは変わらない)。`size=` は付箋の中の**全部の行に同じ**
- ⚠ **丸めは失われる情報**:PowerPoint の 20 pt は「標準」に、24 pt は「大」に丸まり、**1 枚の中で行ごとに違う大きさ**は**最多の 1 つ**に揃う。
  黙らない ── 取り込みの結果に **「近い大きさに丸めた付箋 N 枚」**を足し、user へ言う(今の「戻せなかった物 N 件」と同じ置き場)。
  🔑 丸めなかった(段と一致した)付箋は数えない
- 🔴 **「標準」は PowerPoint の 18 pt で、画面の標準は設定で動く(13 px 既定)**。両者は**元から換算していない**
  (書き出しは常に 18 pt)。この設計は**換算を作らない**:段(小・標準・大・特大)の**番号**を運び、画面の何 px かは画面が決める

### 3.2 回転(`rot`)

| | 書き出し | 取り込み |
|---|---|---|
| 今 | `<a:xfrm>` に `rot` を書かない | `rot` を読まない(回った図形が**水平に起き上がる**) |
| 後 | `<a:xfrm rot="度×60000">`。`off` / `ext` は**回す前の四角**(CSS の `transform: rotate` と**同じ約束**。画面の `x=` `y=` `w=` `h=` をそのまま使える) | `rot` を ÷60000 して mod 360、整数に丸めて `rotate=`。0 なら書かない |

- ⚠ **枠に収める縮尺は、回した後の外接四角で決める**(`boardBounds` は今 `x+w` `y+h` だけを見ている)。見ないと、回した付箋が**スライドの外へはみ出す**
- ⚠ **取り込み側の「書き出しの枠から原点を逆算する」**(`originFromExport`)は**右端・下端が回さない四角**であることを前提にしている。
  回した付箋が 1 枚でもあると、書き出した側が**回した後の外接四角**で枠を取るので逆算が外れ、**相対位置に倒れる**(正しい位置関係は保つが、
  スライド内の絶対位置は失う)。→ 取り込みも回転を考えて外接四角で逆算する(同じ関数を共有する)
- `flipH` / `flipV`(反転)は**今も読まない**。この設計でも扱わない(対称な形では見た目が同じ。非対称な矢印は反転した向きが失われる)── 取り込みの丸めの数に足す
- 線(`<p:cxnSp>`)の接続点番号(`idx`)は**付箋の中の向き**で決まるので**変わらない**(PowerPoint は回した図形の接続点も一緒に回す)。**変わるのは線の両端の座標**(§5)

### 3.3 グループ(`grpSp`)

| | 書き出し | 取り込み |
|---|---|---|
| 今 | グループは**出さない**(付箋は全部ばらの `p:sp`) | `p:grpSp` を見つけると **`dropped` に数えて中身も捨てる**(板に出ない) |
| 後 | 同じ `group=` の付箋を **1 つの `<p:grpSp>`** にまとめて出す。座標は**子の座標系を恒等**にする(`chOff = off` / `chExt = ext` = 外接四角)。名前は `cNvPr name` に入れる | `p:grpSp` を**開いて**、中の `p:sp` を**平らに**取り込み、同じ `group=グループN` を付ける。子の座標は `off + (子 − chOff) × ext/chExt` で戻す |

- **取り込めなかった物の数は減る**(グループは「取り込めた」側へ)。今の `dropped` が減る分は、**取り込みの結果の文を直す**必要がある(件数の言い方が変わる)
- **入れ子のグループ**:内側だけを残す(`group=` は 1 枚に 1 つ)。外側の名前は失われる → 丸めの数に足す
- **回したグループ**:`grpSp` の `rot` は**子の位置と向きに合成**して平らにする(子の中心を群の中心の周りに回し、子の `rot` に群の `rot` を足す)。**回転の段の後**に完成する
  (その前の段では回したグループの子を**回さずに取り込み、丸めの数に足す**)
- 線の `stCxn` / `endCxn` の `id` は**スライド内で一意**なので、グループの中の図形にもそのまま付く(`byId` の引き方は変わらない)
- ⚠ **重なりの順**:グループは `spTree` の中で**1 かたまり**として並ぶ。画面は付箋ごとの `z=` なので、**別のグループの付箋が間に挟まる板**では書き出しで順がずれる。
  → 同じグループの付箋は**書き出しで連続させる**(最小の `z=` の位置に寄せる)。画面と PowerPoint で重なりが違って見える板が残りうる(実測していない)
- 線(`cxnSp`)は**グループの外**に出す(今の「線は板より前 = 後ろに敷く」を保つ)

## 4. 描画(画面)── 回転で壊れる所

読んだ実装:`place-board.ts`(`rectOf` / `applyPlaceLayout` / `applyPlaceLines`)/ `place-drag.ts` / `place-connect.ts` / `place-handles.ts` / `place-line.ts` / `app.css` の `.pkc-place`。

### 4.1 文字の大きさ(壊れる所は無い)

`.pkc-place[data-pkc-size=…]` に `font-size` を **`calc(基準 × 係数)`** で当てるだけ。係数は PowerPoint の段と同じ(14/18・27/18・40/18)。
付箋の外形(`w=` `h=`)・線の端・掴む口は**字の大きさに依らない**。`overflow: auto` なので、大きくして収まらない分は付箋の中で送れる
(今の「中身で板を伸ばさない」と同じ向き)。**必要な作業は CSS 1 か所と、描画の控え(`BlockLayoutCache`)に `size` を足すこと**
(足さないと、`size=` だけ変えた再描画が**差分判定で飛ばされる**)。

### 4.2 回転で壊れる所(全数)

回し方は **CSS `transform: rotate(θ)`、`transform-origin: center`**(`left` `top` `width` `height` は変えない)。
✔ `rectOf` が使う `offsetWidth` / `offsetHeight` は **transform の影響を受けない**ので、`w` `h` は**回す前の四角のまま**取れる。壊れるのは次の 6 つ。

| # | 壊れる所 | 今の実装 | 何が起きるか | 直し方 |
|---|---|---|---|---|
| 1 | **線の端の座標** | `anchorPoint(rect, anchor)`(`place-line.ts`)が**回さない四角の辺**を返す | 回した付箋につないだ線が、**回す前の位置**で止まって**付箋から浮く** | `anchorPoint` に回転を渡し、**四角の中心の周りに回した座標**を返す。画面・ER 図・PowerPoint の書き出しが**同じ関数**を引く作法(§7)を保つ |
| 2 | **「いちばん近い辺」の自動選び** | `placeLineOf` が 4 辺 × 4 辺の端点間距離で選ぶ | 回した端点で比べないと、**つなぐ辺が現実と食い違う** | 1 と同じ関数を通せば自動で直る。**辺は付箋の中の向き**(§5 の推薦)なので、`right@1/4` は**回した付箋の右辺**を指す |
| 3 | **● ⊕ の位置と、乗せた辺の判定** | `connectHandles` / `nearestEdge`(`place-handles.ts`)と `makeHandle` が `rectOf` の**回さない四角**を使う | ● ⊕ が付箋から**浮く**。マウスを乗せた辺が**違う辺に判定される** | ● の位置は 1 の関数。乗せた位置は**付箋の中心の周りに逆に回してから** `nearestEdge` に渡す |
| 4 | **離した先の付箋の当たり** | `candidates()` が `rectOf` の**回さない四角**で「どの付箋の上か」を決める | 回した付箋の**角の外側**で離すと別の付箋に誤爆し、**角の内側**で離すと外れる | 離した位置を**逆に回して**から四角と比べる(付箋ごと) |
| 5 | **角の伸縮** | `place-drag.ts` の `size` モードが `dx` `dy`(画面の動き)をそのまま `w` `h` に足す | 90° 回した付箋では、**右へ引くと縦が伸びる**。向きの食い違い | `dx` `dy` を付箋の向きへ**逆に回して**から足す。⚠ **中心の周りで回っているので、`w` `h` だけ変えると反対側の角が動く**(PowerPoint は反対側の角を固定する)。→ 離したとき `x` `y` も一緒に書く(`setPlaceRect` が 4 つを 1 回で書ける。**新しい書換の口は要らない**。ただし伸縮の `RESIZE_PLACE` は `w` `h` だけなので、**`x` `y` も書く別の口が 1 つ要る**) |
| 6 | **板の高さの見積もり** | `applyPlaceLayout` が `bottom = y + h` で器の `min-height` を決める | 回した付箋の角が**器の外へはみ出す** | 回した外接四角の下端で見積もる |

- ✔ **動かす(⠿)は壊れない**:`left` / `top` を書くだけで、回転は中心の周りに追従する。掴む口は付箋の子で、一緒に回る
- ✔ **矢印キーで動かす**も壊れない(画面の座標で動くのは今と同じ)
- ✔ **形(ひし形・矢印)**は付箋の `::before` / `::after` で描いているので、`transform` で**一緒に回る**
- ✔ **前へ出す(`z=`)**は変わらない
- ⚠ **印刷**:`transform` は印刷に出る(測っていない)

### 4.3 グループで壊れる所

| # | 壊れる所 | 何が起きるか | 直し方 |
|---|---|---|---|
| 1 | **離したときの書込は 1 枚ぶんだけ** | `MOVE_PLACE` は 1 つの開き行しか書かない。メンバーの数だけ撃つと**1 回目で本文が変わり、2 回目以降の「掴んだ時点の開き行」が byte 不一致**で断られる(`setPlaceRect` の注記と同じ事故) | **複数の開き行を 1 回で書く口を足す**(`movePlaces`:全員を同じ門(`placeLinesAt`)に通し、**1 人でも門を通らなければ全体を断る**)。「一部だけ動いた」状態を作らない |
| 2 | **掴んでいる間の見た目** | 今は掴んだ 1 枚だけの `left` / `top` を動かす | 同じグループの全員の `left` / `top` を動かし、取りやめ(`restore`)も全員戻す |
| 3 | **メンバーの一部が別のノートの枠** | 板は 1 ノートの本文なので、グループもその中に閉じる(`entry=` で置いた**別ノート**は付箋の中身であって、グループの相手ではない) | 問題なし。同じ本文の中だけを探す |
| 4 | **グループ名が重なった・読めない** | | 読めない名前は**無視**(その付箋は単独)。同じ名前は**同じグループ** |
| 5 | **入れ子** | `group=` が 1 つなので表せない | 作らない。PowerPoint の入れ子は内側だけ残す(§3.3) |

> 付箋は**中心を軸に**回り、字・枠も一緒に回ります。**回した付箋につないだ線は、付箋の辺と一緒に動きます**
> (右の辺に付けた線は、付箋を 90° 回すと下側から出ます。PowerPoint も同じ動きです)。
> 角を引いて大きさを変えるときは、**付箋の向きに沿って**伸び縮みします。
> → **推薦:15° ずつ、右クリックから**。理由:PowerPoint で斜めの付箋を取り込めるようにするのが目的で、掴んで回す持ち手は
> 付箋の周りのつまみ(動かす・大きさ・線)をさらに増やすため、まず右クリックだけで始めたい。
> **これが分かったら覆る**:使ってみて「15° では細かく合わせられない」「掴んで回したい」と感じたら、掴んで回す持ち手を別に出します。
>
> **3. いくつかの付箋をひとまとまりにする(グループ)**
> 付箋を右クリック →「グループにする…」を押すと、板の付箋の一覧(各付箋の最初の 1 行つき)の窓が開き、まとめたい付箋に
> チェックを付けて「決める」と、同じグループになります。**グループのどれか 1 枚を動かすと、全員が一緒に動きます**
> (離したとき、全員の位置が本文に 1 回で書かれます)。1 枚だけ動かしたいときは、右クリック →「グループから外す」で外してから動かします。

> (いまは「取り込めなかった物」になり、板に出ません)。

> 範囲を選ぶ操作は本文を読む画面の「文字を選ぶ」ドラッグと競合するため。
> **これが分かったら覆る**:「窓でチェックは手間」と感じられたら、付箋を順にクリックして選ぶ形(選んだ付箋に印が出る)を別の設問で出します。
>
> 回す・字を大きくする・グループ化は**1 枚ずつ**の操作です(グループ全員の字を一度に大きくする、は次の段で出します)。
>
> 📌 順番は「字の大きさ → グループ → 回す」で進めます(回すのが一番、線や角の動きに触るため)。
