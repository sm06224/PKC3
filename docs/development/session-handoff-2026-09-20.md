## 測って「問題なし」と分かったこと(再調査させないために)

| 測ったこと | 結果 |
|---|---|
| **添付は sqlite の破損を生き延びるか** | 🟢 **生き延びる**。`wipeStorage` の後も IndexedDB の鍵と中身は無傷(2 回) |
| 🔴 **`wipeStorage` は OPFS の Access Handle を返すか** | 🔴 **返さない**。同じ worker で `init` し直すと**黙って `vfs: memory` へ落ちる**(`fallbackReason: NoModificationAllowedError`)。**古い worker を terminate してから**開き直すと `opfs-sahpool` / `fallbackReason: null` |
| 門をどちらに置くか | 🔴 **`fallbackReason` で見る。`vfs === 'memory'` では見ない** ── 持ち歩ける 1 枚は**自分で memory を選ぶ**ので、そちらだと正常な形まで弾く |
| cid を引き継ぐ理由 | **速さではなく正しさ** ── cid が変わると `strayBlobKeys`(`src/adapter/platform/storage/asset-gc.ts:50-57`)が添付を**迷子と判定**し、`pkc://<cid>/entry/<lid>` の栞も切れる |
| `announceWiped()` の位置 | 🔴 **書き戻しの後**。先に言うと、別のタブが**空の `containers`** を見て**別の cid を切る** |

## やらないと決めたこと(理由つき)

- 🔴 **SQLite そのものを差し替えない(いまは)** ── ⚠ 「やらない」ではなく
  **「この順番ではない」**。① 原因が未特定 ② 2 大破損経路(多重書き手 / flush が効かない)は
  **既に塞がっている** ③ 🔴 **engine を替えても同じ穴が残る**(1 か所に全部置いていれば、
  そこが壊れたら終わり)。覆る条件は #1007 に 3 つ書いてある
- **#1007 段② を「添付の DB に相乗り」でやらない** ── `deleteEntry` は**本当に行を消す**
  ので、控えが lid で 1 枚持つだけだと **user が自分で消したノートが黙って戻る**
- **周期ごとに全ノートを走査して控える形にしない** ── それは **#212 そのもの**
  (⚠ **`grep -rln "#212" src/` で 7 file** ── 設計 doc は「6 か所」と書いているが、
  それは別の数え方である。数えるときは**何を数えたか**まで書くこと)
