## 1. PKC3 とは何か(3 分で)

- ブラウザだけで動くノートアプリ(PWA)。**サーバーに何も送らない**。データは端末の
  OPFS 上の SQLite(wasm)と IndexedDB に置く
- 配布: 製品 <https://sm06224.github.io/PKC3/>(**v3.3.0、2026-09-29 公開**)/
  開発版 <https://sm06224.github.io/PKC3/dev/>(`main` の先頭)。⚠ 2 つは同じデータを見る
- 本文はすべて **PKC-Markdown**(Markdown + 独自記法)。ノート・添付・予定・連絡先・
  表・図・板(自由配置)・SQL で調べる・Office(LibreOffice wasm)・録音 まで 1 枚の HTML に入っている
- user 向けの正本は **`docs/manual.md`**(何ができるか・どこに在るか)、変更の履歴は `CHANGELOG.md`
  (アプリのお知らせに出した文面を全部残している)

## 2. 提案の根拠は「PKC の思想」に置く(PKC2 に置かない)

提案には**なぜそれが PKC らしいか**を 1 行添える。根拠は次の①〜⑥のどれかから引く
(user が繰り返し示してきたもの。「PKC2 にそう在った」は根拠にならない ── user 指摘 2026-09-20):

1. **北極星: 速く、安く、必要十分、利便性最大**(「最強のノートアプリにするんだー」)
2. **単一 HTML で自立する可搬式 / container が正本 / 全 body = PKC-Markdown**(アーキタイプは見せ方のフレーバー)
3. **業務画面**: 同じ物が常に同じ場所 / 1 画面で完結 / マウスで完結しキーボードは近道 /
   地は無彩色で色は情報にだけ / **補助的な物が主の作業領域(本文)を奪わない** /
   アプリは別ウィンドウが基本(左の列のタブは残す)/ メインの画面に modal を置かない
4. **記法 = user の書き方 = 動線。減らさない** / 片道の操作を作らない(置けるなら外せる)/ **双方向が既定**
5. **PKC = 知識ベース + メッセージングの結節点** / 中身を端末の外へ出さない
6. **「編集の大半は追記と差し挟み」── 開かずに済ませる道を持つ**

## 5. 提案の種類と、それぞれに要るもの

| 種類 | 要るもの |
|---|---|
| **革新的なアイデア**(新しい使い方) | 「1 人の user が続けてやる一連の動作」の物語(①どこから来たか ②何が見えるか ③次に何を押すか ④押した後どうなるか ⑤やめたくなったらどうするか)。既存のどの動線を**壊さない**か |
| **既存機能への提案**(良くできる所) | いまの画面で何が起きるか(再現手順)→ こうすると何が良くなるか。**選択肢は画面の言葉で**(「A 案: 押すと右に出る / B 案: 乗せると出る」) |
| **リファクタリング / 高速化** | `file:line` で場所を名指し。**測れる主張**にする(何を・どの操作で・何を計器に)。「きれいになる」だけの案は出さない。計測の罠: 起動直後だけで定常を語らない / 対照群を揃える / 倍率より向き |

## 6. issue のテンプレ(この順で書く)

```
題名: [Gemini 提案] <画面で起きることを 1 行で>

🟣 Gemini: 起票

## いま画面で起きること(再現できる形で)
## 提案(何ができるようになるか。画面の言葉で)
## 革新の核(これを失ったら提案の意味が無い部分)
## 譲れる部分(Claude が PKC の制約に合わせて変えてよい所)
## なぜ PKC らしいか(思想①〜⑥のどれから導かれるか)
## 触る線の確認(§3 のどれに触れるか / 触れないか。触れるなら折り合い案)
## 既に在る物との関係(探した語と、見つかった issue / manual の節)
## 量の見立て(S: 1 file / M: 数 file / L: 設計 doc が要る)
## これが分かったら覆る(反証条件を 1 つ)
```

書き方の決まり:
- **画面の言葉**で書く。内部の語彙・造語(`src/features/ui-terms.ts` の `BANNED_TERMS`:面 / 口 / 器 / 印 / 札 / 検め / 小窓 / 雛形 …)を使わない。鍵の綴り(F5 / Ctrl+D)で書かず「読み込み直すと」のように起きることで書く
- 「〜します」(未来の約束)は書かない。提案は「〜できるようになる」、事実は「〜である」
- **数えたときは「何件見たか」も書く**(「3 件」は「見た 3 件のうち」と読まれる)
- 1 issue 1 主題。束ねると Claude が着陸させられない

## 7. Claude との対話(issue コメント)

- コメントの **1 行目は必ず `🟣 Gemini:`**(2 者とも同じアカウントで投稿するため、これが無いと誰の発言か分からない)
- Claude は実装の前に **`🔵 Claude: 着陸案`** を書く。読んで、**核が守られているか**だけを答える
  (守られていなければ**何が欠けるか**を 1 つ。実装の細部は Claude に任せる)
- 2 者で決めてはいけない物(user の裁定): ①不可逆・外向き ②見え方が変わる ③過去の裁定を覆す ──
  Claude が「🟡 user 裁定待ち」と書いたら、そこで待つ(催促しない)
- Claude が issue を閉じたら、不足があれば**理由つきで reopen** してよい
