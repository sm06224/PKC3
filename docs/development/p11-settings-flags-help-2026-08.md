## 3. 設計

### 3.1 フラグ機構(新設)

```
src/features/flags.ts        ← 登記所(純宣言。test が名指しで予約済み)
  defineFlag('name', { default, foldWhen: '畳む条件', summary })
```

- **予算 15。`foldWhen` 必須。** 既に CI が見張っている(`tests/flag-budget.test.ts`)
- **保存先は localStorage 1 鍵**(`pkc3.flags`、JSON)を推す ── 理由は §5 の「三すくみ」
- **URL からの一時有効化**を持つ(`?pkc-flag=<name>`)

> 🔴 **訂正(user 指示 2026-08-07。不可侵)**
>
> 「**URL クエリパラメータ切り替えはフラグ扱いである / 起動前から必要なパラメータが
> ある場合、それはフラグ画面に出てきて、フラグ画面から再起動した際にパラメータありで
> 再起動する必要がある / クエリパラメータを抜け穴にしてはいけない / 本来は PKC 内部の
> パーマネントリンクやディープリンク以外にクエリパラメータを使用してはいけない**」
>
> ⚠ **本 doc は当初ここに「既存の逃がし口 3 つは枠を食わない計測用としてそのまま残す」
> と書いていた**(`detail.ts:61-63` の過去の裁定をそのまま引き継いだ)。
> **それが「抜け穴」そのもの**であり、user 指示で否定された。
>
> 確定:
>
> | | 確定した扱い |
> |---|---|
> | `?pkc-md-inline` / `?pkc-asset-inline` / `?pkc-live` | **すべて flag として宣言する**(15 枠に数える / `foldWhen` 必須 / フラグ画面に出す) |
> | 起動前に要る切替 | フラグ画面から **パラメータ付きで再起動**させる(user に URL を打たせない) |
> | クエリパラメータを読んでよい場所 | **flag の解決**と**パーマリンク / ディープリンク**だけ |
>
> 🔑 「計測用だから枠を食わない」という論法は**今後使わない** ── 切替である以上、
> 数え、条件を宣言し、画面に出す。

🔑 **「15 個を超えたら設定へ昇格」を機構にする** ── user 指示の核心。
`defineFlag` に `promoteTo?: 'settings'` は**持たせない**。昇格とは
「flag を消し、settings に項目を足す」ことであり、**コードの移動でしか表現できない**。
代わりに **`foldWhen` に「いつ畳むか」を書かせる**(= 既存の義務)ことで、
「畳む条件を書けない flag は作れない」を強制する。

### 12-2. 🔴 **Q5 を覆す** ── 編集中も設定 / フラグ / ヘルプを開ける

**当初の裁定は「開けないまま(骨格を変えない)」だった。** 覆した理由は意見ではなく、
**調べたら止めている理由が無かった**から:

| 確かめたこと | 根拠 |
|---|---|
| 面は `hidden` の付け外しで**生きたまま常駐**する | `center.ts` の `pane()` は 1 度だけ作り、`render` は非 active な面を描かない |

| だから **textarea も native の取り消し履歴も壊れない** | 上の 2 つの帰結。往復の test で pin する |

つまり「下書きを守るために止めている」という前提が**そもそも成り立っていない**。
一方で止めるコストは実在する ── 🔑 **「書きながらマニュアルを読む」はヘルプの
主目的**であり、P11 で無言の dead click が 1 個 → **3 個**に増えた。

**範囲は `isAsidePane` に限る**(設定 / フラグ / ヘルプ)。

```ts
if (state.phase === 'editing' && !isAsidePane(action.mode)) return { state, events: [] };
```

⚠ **一覧のノートを押す(`SELECT_ENTRY`)は、開けるようにしない。** こちらは
「下書きを守る」理由が実在する ── ただし**無言で断らない**(可視に断る)。
これは別主題として残す。
