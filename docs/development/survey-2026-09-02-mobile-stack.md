## 版面の全体像(`layout`)

### 要約

版面は `shell` の CSS Grid 1 枚(3 列 + 全幅 7 行)で、列は sidebar / gripl / center(detail+append) / gripr / inspector、面は CenterRouter が 6 枚(detail/query/dual/settings/flags/help)を hidden 排他で常駐させる(shell.ts:248-779、center.ts:117-131、app.css:64-96)。
幅で分岐するのは app.css の `@media` 3 本(≤1100px: 情報を下へ / ≤900px: 2 ペイン編集のプレビューを消す / ≤720px: 1 列)+ print 1 本、別窓のマニュアルに 760px が 1 本で、`@container` と `resize` listener は 0 件、代わりに ResizeObserver が本文の面(段組み・横並べ枠)と mermaid の親を見る(read-columns.ts:441-454、split-view.ts:151-157、mermaid-hydrate.ts:345-361)。
畳む機構は state ではなく localStorage `pkc3.panes` → shell の `data-pkc-hidden-panes` 属性 → CSS の grid 定義差し替え(pane-visibility.ts:17/77、app.css:128-173)で、幅は `pkc3.pane-sizes` → `--pkc-pane-{sidebar,inspector,append}` = `clamp(0px, Npx, 45vw|60vh)`(features/pane-size.ts:139-147)。畳む口は 7 か所(grep 実数)だが pane-visibility.ts:98 は「5 か所」と書く。
最小幅の明示は無い: ≤720px は `minmax(0,1fr)` の 1 列なので理論上どこまでも縮み、smoke が実際に当てている最狭は 480px(layout/pane-resize/timer)。3 列が成立する下限は 1101px(sidebar≥200 + inspector≥220 + 帯 16 + 隙間 4 → 本文 ≈661px)、本文の中身側は 1 段 448px(13px 時)・2 段 912px・横並べ 2 枠 929px と器の幅で決まる(features/read-columns.ts:84/141、split-frames.ts:74/155)。
doc と実装の食い違い: app.css:4657 は「中央が狭いとき」と書くが条件は窓幅 900px / p7b 設計 doc:73 は「2 ペイン + topbar」のまま / マニュアルの鍵表に `Alt+\`(追記欄)が無く、720px の 1 列化も書かれていない(operation-model-2026-08.md:196-207 が既にこの軸の混在を指摘済み)。

## 既に在る「まとめる」概念(`group`)

### 要約

PKC3 で「まとめる」概念は全数で 9 系統ある(タグ / スマートフォルダ / フォルダ+structural 関係 / 4 種の意味関係 / 板の entry= 札 / 本文リンク / 横に留めた枠 splitLids / 2 ペインの留めた場所 / 運転時のみの選択・履歴・タブ)。ほかに `workspaces` 表(未使用の座席)と設計 doc だけの `group:`(未実装)がある。
「順序あり・参照だけ・保存できる・先頭を主ノートの横に出す」を全部満たす既存概念は 1 つも無い ── 順序と横表示を持つのは **splitLids(横に留めた枠)** だけだが端末の localStorage に閉じ、無名で 1 本しか持てない。保存できて参照だけなのは **本文リンクの列(`[題名](entry:lid)`)と板の `entry=` 札**で、これは書いた順という順序も持つが「横に出す」配線が無い。
機構が最少で済むのは「**stack = 本文が `entry:` リンクの列であるノート**(新フレーバー or 既存 text)」+「**先頭リンクを既存の `PIN_SPLIT_ENTRY` に渡す**」の合成である(S〜M)。逆に relations に順序列を足す案は schema 変更で、whiteboard doc が名指しで危険(旧ビルドが黙って欠損)としている。
足りないのは ①並べ替えの口(本文リンクは編集で並べ替えるしかない ── row-swap は編集であって移動ではない)②横表示の正本が localStorage と本文の 2 つになる §7 の危険 ③消えた先の表示(描画時は印が付かず、押したときだけ「見つかりません」)④新 archetype 追加は「この 1 件」限定の裁定なので user の言葉が要る。
Issue #283 本文はこの箱から取れなかった(GitHub API が「access is not enabled」)ので、台帳の段(P1 所属の札 / P4 板)はコード内の参照から復元した。

## PKC2 のモバイル資産(read-only 参照)(`pkc2-mobile`)

### 要約

PKC2 にはモバイル資産が「在る」: (1) iPhone push/pop シェル(`pointer:coarse and max-width:640px` で desktop chrome を丸ごと差し替え、`data-pkc-mobile-page=list|detail|edit` で経路分岐、mobile header + ☰ ドロワー + スワイプ削除 + ⓘ meta スライドオーバー、base.css:11224-11746 の約 285 行 + renderer/action-binder)、(2) touch 全般(`pointer:coarse` 単独 @media 9 ブロック: 16px 入力 / 60vh エディタ / hover-reveal 常時表示 / コピー・トグル常時表示 / 44px chip / 書式パネル非表示 → 浮遊スニペット「✚」)、(3) device-class UI 倍率(0.9 / 0.95 / 1.0、flag `theme.scale` で上書き)、(4) viewport meta で pinch zoom 全面禁止。
「届いていた」のは (1)〜(4) 全部 ── flag ゲート無し(CSS media query のみ)で既定 ON、CHANGELOG v2.2.0 に iPhone 実機の user 修正指示が 2 件、action-binder に 2026-06-03「iPhone 側の導線ないね」の追記が在り、user が実際に iPhone で使っていた痕跡がある。ただし**マニュアルは iPhone シェル / ドロワー / スワイプ / スニペット / zoom 抑制を 1 行も書いていない**(書いてあるのは theme.scale の 3 段既定・touch の hover 常時表示・720px 2 列・「ネイティブアプリは無い」だけ)。
