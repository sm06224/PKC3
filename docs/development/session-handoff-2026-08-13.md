## 3. 🔴 やらないと決めたこと(理由つき)

```
❌ Office の一式を 2 つに分ける(Writer/Calc 用と Impress 用)
   → Impress の代金は 5 分後の常駐で +42MB(+4.7%)。一方、分けると
     両方を同時に開いた人はランタイム 2 つ = +900MB 級で 20 倍以上重い。
     さらに wasm の LO は動的読込が無効(configure.ac:3465)なので
     「Impress だけの小さな一式」は作れない ── 分ける = 完全な LO を 2 つ。

❌ 「大きいから Impress を入れない」
   → 上流が既定から外している理由は **debug ビルド**が大きすぎるためで、
     こちらは release。加えて不可侵指示により「重いから入れない」は禁じ手。

❌ SAFE_HEAP で #134 を追う
   → 実測で**効かなかった**(JS heap view の load/store しか見ない)。
     効いたのは `--profiling-funcs`(wasm に関数名を残す。実行は遅くならない)。
```

#### 確認 1 ── ダイアログを閉じても落ちないか(#134)

1. Office の窓で Writer を開き、適当に文字を入力
2. `Tools → Word Count` を開く → **`Escape`** で閉じる
3. 同じことを `Tools → Word Count` → **`Close` ボタン**でも
4. `Edit → Find & Replace` を開いて置換 → **`Close`**

- **「Office が停止しました」の面が出たか**(出たら停止です)
- 各操作の後、**文書がそのまま編集を続けられるか**
- ⚠ 出た場合は**何回目で出たか**(1 回目 / 2 回目…)

#### 確認 2 ── 表の挿入で固まらないか(#135)

1. Writer で **`Table → Insert Table…`**(`Ctrl+T`)
2. **ダイアログが開くか**

   ⚠ **ここが空でないこと**が今回の直しの本体です
4. 右側の**プレビューに見本の表**が描かれているか
5. `Insert` を押して**表が入るか**
