# SQL の面に ER を置く ── 図から押して `SELECT` を組む(#918 段⑤)

**status**: 設計。実装前。
**出どころ**: user 要望 2026-09-14 ──「**er でグラフィカルに取得する方法も欲しいな**」

---

## 1. 何を作るのか(画面の言葉で)

**表を四角で並べ、繋がりを線で見せ、押した所から `SELECT` を組む。**

- 四角 1 つ = **表(またはビュー)1 つ**。中に列の名前が並ぶ
- 四角どうしを結ぶ線 = **外部キー**(`売上.客id → 客.id` のような繋がり)
- **押すと、打つ欄に SQL が書かれる**(走らせはしない ── 手で直せる状態で置く)

| 押す所 | 打つ欄に何が書かれるか |
|---|---|
| **表の見出し** | `SELECT * FROM 売上` |
| **列の名前** | いまの `SELECT` の列に足す(`SELECT 客id, 金額 FROM 売上`) |
| **表と表を結ぶ線** | `JOIN` を足す(`... JOIN 客 ON 客.id = 売上.客id`) |

🔑 **これが「取得する」の中身である。** user の言葉は「見る」ではなく**「取得する」**なので、
**眺めて終わる図では要望を満たさない**。

## 2. 🔴 器は mermaid ではない ── `<button>` と 1 枚の `<svg>`

⚠ mermaid は不可侵指示(user 指示 2026-08-03「図は描いたら焼く」)どおり
**PNG の `<img>` 1 枚**で出すので、**押せない**。

🔑 前例が repo に在る:`src/adapter/ui/render/relation-map.ts` は**同じ理由で** mermaid を使わず、
**節点 = `<button>` / 辺 = 1 枚の `<svg>` の `<line>`** で組んでいる。その docstring には
「**形は見えるが辿れない図**」が不満そのものだと書いてある ── **そこに倣う**。

⚠ **辺の `<svg>` は 1 枚だけ**(線ごとに作らない)── 重ねると当たり判定が塞がる。
⚠ 層には **`pointer-events: none`** を当てる(#918 段②c/②d と #530 段③a で 2 度踏んだ)。

## 3. 🔑 材料はほぼ全部そろっている ── 作る物は 3 つだけ

| 要る物 | いまどこに在るか |
|---|---|
| 表・列・型・主キー | ✅ `features/query/schema-digest.ts` の `SCHEMA_COLUMNS_SQL` |
| 外部キー | ✅ 同 `SCHEMA_FK_SQL` |
| 行数 | ✅ 同 `countsSql()`(省略可) |
| **2 つの四角を、いちばん近い辺どうしで結ぶ線** | ✅ **`features/markdown/place-line.ts`**(#530 段③a、`543599a`)|
| 押せる節点 + 1 枚の `<svg>` の組み立て方 | ✅ 前例 `relation-map.ts` |

🔴 **だから新しく書くのは 3 つだけ**:

### ① `schemaModel()` を取り出す(pure)

⚠ いま `schema-digest.ts` が持っているのは **`renderSchemaDigest(input): string`**
= **markdown を作る口だけ**で、`byTable` / `kindOf` / `countOf` は関数の中に閉じている。

🔑 **構造そのものを値として返す口**を切り出し、**markdown も ER も同じ値から作る**:

```ts
export interface SchemaTable {
  readonly name: string;
  readonly kind: 'table' | 'view';
  readonly rows: number | null;          // ⚠ 採れなかった回は null(嘘を書かない)
  readonly columns: readonly SchemaColumn[];
}
export interface SchemaLink {               // 外部キー 1 本
  readonly from: string; readonly fromColumn: string;
  readonly to: string;   readonly toColumn: string;
}
export function schemaModel(input: SchemaDigestInput): {
  readonly tables: readonly SchemaTable[];
  readonly links: readonly SchemaLink[];
};
```

⚠ **`renderSchemaDigest` はこれを読む形へ直す**(中で 2 度組み立てない)──
§7「同じ問いに答える口が 2 つ」を作らないため。
🔑 **段① の出力が 1 バイトも変わらないことを test で pin する**(取り出しで壊さない)。

### ② `erLayout()`(pure)── どこに四角を置くか

**決めごと**:

- **並べ方は決定的**(同じ構造なら毎回同じ絵)── ⚠ 乱数を使わない。test が書けなくなる
- 順番は **①外部キーで指される数が多い順 ②行数が多い順 ③名前順**
  (🔑 「本体らしい表」が左上へ来る)
- 置き方は**格子**:1 行に `ceil(sqrt(N))` 個。四角の幅は**いちばん長い列名**で決まる
- ⚠ **列が多い表は畳む** ── 先頭 8 列 + 「ほか N 列」。全部見たい人は表の見出しを押す
  (`SELECT *` が入るので、答えの表で全部見える)

⚠ **自動整列だけにする。掴んで動かす道は作らない**(いまは)── #530 段③ が
「掴んで動かして本文へ書き戻す」を持っているが、ER は**本文を持たない**(DB の構造は
user が書いた物ではない)ので、**置き場所を保存する先が無い**。
🔑 保存先の無い操作を作らない ── 動かしても次に開くと戻る = 片道の操作になる。

### ③ `erSql()`(pure)── 押した所から SQL を組む

⚠ **いま打つ欄に在る字を読んで、足す**形にする(捨てて書き直さない)──
打ちかけの字を消すのは、user が**いちばん怒る**壊れ方である。

| いまの欄 | 押した所 | 後 |
|---|---|---|
| 空 | 表「売上」 | `SELECT * FROM 売上` |
| `SELECT * FROM 売上` | 列「金額」 | `SELECT 金額 FROM 売上`(⚠ `*` は退く) |
| `SELECT 金額 FROM 売上` | 列「客id」 | `SELECT 金額, 客id FROM 売上` |
| `SELECT ... FROM 売上` | 線(売上→客) | `SELECT ... FROM 売上 JOIN 客 ON 客.id = 売上.客id` |
| **読めない字が入っている** | 何か | 🔴 **足さない。**「いまの字は読めないので、足せませんでした」と 1 行出す |

🔴 **最後の行が肝である。** SQL を全部解釈する物は作らない(それは parser を書くこと)──
**こちらが組んだ形を保っている間だけ足せる**、と決める。
⚠ 読めないときに**黙って書き換える**のは、user の字を壊す。⚠ 黙って**何もしない**のも
無言の dead click(#530 段③a で同じ形を直したばかり)。**理由を言う。**

## 4. どこに出すか ── 🔵 **user に決めていただきたい 1 点**

SQL の面は**既に別窓**である(`view-window.ts`)。ER をどこへ置くかで、画面の見え方が変わる。

| 案 | 画面で何が起きるか |
|---|---|
| **A(推薦)** | **SQL の窓の中に、畳める欄として置く**。「構造を見る」を押すと打つ欄の上に開き、もう一度押すと畳む。⚠ 開いている間は答えの表が下へ押される |
| **B** | **もう 1 枚の別窓**で開く。SQL の窓は 1px も狭くならないが、**窓が 2 枚**になり、押した SQL が**別の窓の欄へ飛ぶ** |
| **C** | 打つ欄と**切り替え**にする(タブ)。狭くならないが、**図を見ながら打てない** |

🔑 **推薦は A** ── 理由は 3 つ:

1. **図を見ながら打てる**(C は見られない)── 押して組んだ SQL を、その場で直したい
2. **押した先が同じ窓の中に在る**(B は窓をまたぐので、「押したのにどこへ入ったか分からない」が起きる)
3. **畳めるので、要らない人の場所を奪わない**(#300「補助的な物が主の作業領域を奪わない」)

⚠ **A の弱点も書く**:開いている間は**答えの表が下へ押される**。狭い画面では窮屈になる。
🔑 そこは「**開いたら答えの表と半々**」にして、境目を掴んで変えられる形で吸収する。

## 6. これが分かったら覆る

- **上の置き場の裁定が B / C** なら、⑤b の描き先が変わる(層の組み立ては同じ)
- **`schemaModel()` の取り出しで段① の出力が 1 バイトでも変わる**なら、取り出し方が誤り ──
  pin が落ちるので、そこで気づける
- **`place-line.ts` が ER の四角で使えない**(四角が大きく、辺の真ん中どうしでは線が長すぎる)と
  実測で分かったら、接続点の採り方だけ差し替える(#530 段③b と同じ話になる)

## 7. やらないこと(いまは)

- **掴んで動かす**(保存先が無い ── §3②)
- **ER から表を作る / 直す**(SQL の面は**読むだけ**。`sql-guard.ts` が `select` 系しか通さない)
- **mermaid で出す**(押せない ── §2)
- **多対多の中間表を自動で畳む**(見た目は良くなるが、**押せる物が減る**)
