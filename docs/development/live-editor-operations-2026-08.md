# ライブエディタの操作体系と「既定 ON + 設定で 2 ペイン」への道筋(2026-08)

> Issue #104。実装 第 1 弾(操作の 5 項目)は同 PR で着地させる。
> 本 doc は **第 2 弾以降(既定の切替と 2 ペインの設定昇格)の設計**であり、裁定待ち。

## 0. user 裁定(2026-08-08。出典タグ付き = 不可侵)

> **ライブエディタを既定でONにする前に操作体系がきに食わん。カーソルキーで下に行くとか、
> 一旦全てプレーンテキストにして編集したいとかあるはず。マークダウンのテキストとしての
> コピーが欲しい場合とHTML書式ありのコピーがしたい場合ととかもある。操作体系が甘いんだわ。
> そこを前々から指摘されているのに何も改善していない。**
>
> **それと、既定でONかつ設定で2ペイン編集はできるようにするんだよね?
> 廃止しろなんて言った覚えないけど、、、**

## 1. 🔑 現況の確認(調査で判明。認識のずれを先に潰す)

**2 ペイン編集は廃止されていない。それどころか、いまの既定は 2 ペインである。**

| | 現在 |
|---|---|
| 既定の編集 UI | **2 ペイン**(`editor-split`: 左 = 全文 textarea、右 = 打鍵追従プレビュー)。`detail.ts:695-756` |
| ライブエディタ | flag `editor.live` = **既定 OFF**(`flags.ts:166-170`) |
| 切替 | フラグ画面のみ(恒久設定ではない) |

つまり user の心配(廃止)は起きていない。**目標形は「既定を入れ替え、2 ペインを設定で選べるようにする」**であり、機能を落とす話は一切含まれない。

⚠ ただし現状には本当の欠けが 2 つある:
- **恒久設定が無い** ── flag は「いつか畳む」宣言つきの開発者向け切替(`foldWhen` 必須)。
  founding の「flags と正規設定の分離」に従うなら、既定 ON にする時点で**設定へ昇格**が要る
- **汎用の設定ストアが無い** ── 設定は 1 項目 = 1 module + localStorage 1 鍵の個別実装
  (theme / external-images / notices の 3 系統)。4 つ目を同じ作法で足すことになる

## 2. 既定 ON の前提条件(更新)

旧: 「S8(塊を跨ぐ取消)が入るまで OFF」── **満たされた**(実装・変異試験済み)。
新(本裁定): **操作体系の改善が先**。内訳は §3。

## 3. 操作体系 ── 第 1 弾(同 PR で実装)と第 2 弾

### 第 1 弾(実装中)

| # | 何ができるようになるか |
|---|---|
| 1 | **カーソルキーで隣の塊へ** ── 入力欄の最終行で ↓、先頭行で ↑。末尾では新しい行を足す |
| 2 | **「全文を編集」ボタン** ── 全文を 1 つの入力欄にして素の markdown で編集(Ctrl+A と同じ動作の可視化) |
| 3 | **Ctrl+S の修理** ── いまブラウザの保存ダイアログが開く(素通り)。確定に割り当てる |
| 4 | **書式パネルの修理** ── ライブ面で書式ボタン・Ctrl+B/I/K が**無言で効かない**(dead click)のを直す |
| 5 | **コピー 2 系統** ── 「Markdown をコピー」/「書式付きでコピー」+ 選択範囲を原文でコピー |

⚠ 同時に、既知の未修理欠陥(**行数が変わる確定の直後は次の塊が開けない**)も直す ── 1 の実装が同じ場所を通るため。

### 第 2 弾(裁定後)

| # | 項目 | 規模 |
|---|---|---|
| 6 | **2 ペインを正規設定へ昇格** ── `pkc3.editor-mode`(`live` / `split`)の 1 鍵 + 設定画面「表示」節 + `detail.ts:691` の読み替え | M |
| 7 | **既定を `live` に切替** ── 6 と同時。flag `editor.live` は退役(定義は残し、設定へ道を譲る) | S |
| 8 | **編集中のモード切替**(任意) ── いまは編集開始時に 1 回だけ面を組むので、切替には面の作り直し + 入力内容の引き継ぎが要る | M |
| 9 | S5b: 貼り付け・取り込みで入る開放終端の塊を、閉じるまで生のまま見せる | M |

## 4. 推薦

**第 1 弾を着地 → 実機で触って確認 → 第 2 弾(6・7)を 1 PR** の順。8・9 は既定切替の必須条件にしない(8 は 2 ペインを設定で選べれば代替でき、9 は稀かつ可視の劣化)。

**覆る条件**: 第 1 弾を触って「まだ甘い」と判断された場合 ── その指摘を第 2 弾の前に消化する(既定切替を急がない)。

## 5. 裁定してほしい点

1. 設定の名前と選択肢の見せ方(例: 「編集の仕方」= **1 面で編集(ライブ)** / **2 ペイン(ソースとプレビュー)**)
2. 既定を `live` にする時期 ── 第 1 弾を触ってから決めるか、6・7 と同時に決めるか
3. flag `editor.live` の退役方法(設定へ昇格したら flag 枠を返す。15 枠のうち 3 → 2 になる)
