## 6. 測って「問題なし」と分かったこと(再調査しない)

- **編集中に面(設定 / フラグ / ヘルプ)を往復しても編集は壊れない** ──
  面は `hidden` で常駐し、`DetailRenderer.render` が「編集中かつ同じ lid」で早期 return する。
  textarea も打ちかけも native の取り消し履歴も残る(`pane-node-stability` が pin)
- **本文と マニュアルの id は衝突する。それでよい** ── document 順で detail が先に在るので
  `#slug` は本文の面に当たる。マニュアル側は文書内アンカーを 1 つも持たない(unit が pin)
- **`?raw` でマニュアルを同梱しても配る量は問題ない** ── +32 KB、cap 残量 11.1%

## 7. やらないと決めたこと(理由つき ── 蒸し返さない)

| ❌ | 理由 |
|---|---|
| お知らせの **automation ゲート** | PKC2 で spec が壊れたのは*ゲートが無かったから*ではなく**帯が本当に版面を押し下げるから**。ゲートは症状を隠すだけで、`navigator.webdriver` は「**観測すると挙動が変わるアプリ**」を作る |
| `entry:` の **href を剥がす** | 遷移は止まるが `<a>` が**フォーカスできなくなり**、キーボードの動線が落ちる。`<a href>` に限った `preventDefault` を採った |
| 本文のリンクで **fragment を解く** | `parseEntryRef` は 7 形を解くが、**飛び先が実在するのは 2 形だけ**(`log-` / `day-` の id を出す実装が src に 0 件)。断ると PKC2 由来の本文が無反応のままになるので、**lid まで開く**ことにした |
| 編集中に **別のノートへ移れるようにする** | 面の切替とは違い、**下書きを捨てることになる**。止めるのは正しく、無言なのが間違いだった(#98 で可視に断るようにした) |
