## 3. スライドの切れ方 ── **PKC2 と同じにする**

⚠ **新しい仕様を作らない。** user が PKC2 で書いた資料が**同じ切れ方**で出ることが要件である
(CLAUDE.md「記法を減らすことは user の動線を減らすこと」)。

PKC2 の `splitIntoSlides`(`src/features/ast/export-pptx.ts:644`)をそのまま写す:

| 本文 | どうなるか |
|---|---|
| **H1** | **扉スライド**を開始(章番号を 1 つ進める) |
| **H2** | 直前が扉で副題が空なら**その副題**。そうでなければ**新しい本文スライド** |
| **H3** | **新しい本文スライド** |
| **`+++` / `---`** | いまのスライドを閉じ、**題名の無い**新しいスライドを開始 |
| H4〜H6 / 段落 / 箇条書き / 表 / 図 | **いまのスライドの本文** |
| (1 枚も作られなかったとき) | ノートの題名で 1 枚だけ作る |

### 🔴 ⚠ マニュアルの字を信じない

PKC2 のマニュアル 12 章は「`+++ {role=cover}` は **role に応じて** slide separator に
マップ」と書いているが、**実装は `role` を見ていない**:

```ts
if (block.kind === 'break' && (block.breakKind === 'page' || block.breakKind === 'rule')) {
  current = { kind: 'content', title: '', lines: [], chapterNum: chapterCount };
  slides.push(current);   // ⚠ role は参照していない
}
```

`role` が使われているのは `:::section{role=X}` の**アイコン付き見出し行**で、別の話である。
⚠ 一度この字面の上に「pptx の芯は role を読むこと」と設計を書きかけた
(#187 のコメントで訂正済み)。**マニュアルは実装の代わりにならない。**

### PKC3 側の受け皿は既に在る

`markdown-render.ts:3646` が `:::break{kind=page role=cover}` → `+++ {role=cover}` を
受理し、`processSectionBreaks` へ渡している。⚠ **`role` を読んでいる出力は 1 つも無い**
(`docx.ts` に `role` は 0 件)── いまは受理するのに不可視である。
🔑 pptx でも **`role` は読まない**(PKC2 と同じ)。読ませたくなったら別の裁定として出す。

## 4. 入りきらない本文 ── **PowerPoint に縮めさせる**

PKC2 は pptxgenjs の `autoFit: true`(= PowerPoint の「はみ出す場合に文字を縮小」)に
任せ、**切り捨ても次スライドへの送りもしていない**。

🔑 手書き OOXML では、本文の箱の `<a:bodyPr>` に **`<a:normAutofit/>`** を書けば同じになる。
**依存 0**で、縮める計算は PowerPoint 側がする。

⚠ **切り捨てを実装しない**理由:user が書いた行が**黙って消える**のは、この機能で
いちばんやってはいけない失敗である(PKC2 の「画像が黙って落ちる」と同じ型)。

## 5. 置き方 ── pptx だけは「枠の表」を持つ

docx は**本文の流れ**に置くが、スライドは**箱の位置**が要る。PKC2 は EMU ではなくインチで
直書きしていた(題名の帯 `x:0.3 y:0.3 w:12.7 h:0.8` / 扉の題名 44pt / 本文 28pt)。

🔑 PKC3 は **1 か所の表**にまとめ、docx 側と混ぜない:

| 枠 | 用途 |
|---|---|
| 扉の題名 / 副題 | H1 / H2 |
| 本文の題名帯 | H2・H3 の題 |
| 本文の箱 | 段落・箇条書き・表・図 |
| 脚(章番号・ページ) | 走り |

⚠ **単位は EMU**(1 インチ = 914,400)。⚠ 既定は **16:9**(12192000 × 6858000 EMU)。

## 6. 生成物の骨格 ── 最小 14 部品

LibreOffice が書いた最小の `.pptx` を実測した(自作の 1 枚のスライド):

```
_rels/.rels                              583 B
[Content_Types].xml                    2,066 B
docProps/core.xml / app.xml
ppt/presentation.xml  + _rels          722 B
ppt/presProps.xml                        343 B
ppt/theme/theme1.xml                   2,257 B
ppt/slideMasters/slideMaster1.xml     10,088 B  + _rels
ppt/slideLayouts/slideLayout1.xml      3,076 B  + _rels
ppt/slides/slide1.xml                  1,882 B  + _rels
```

🔑 **master と layout は 1 枚ずつで足りる**(LO の出力がそうなっている)。
スライドが増えるのは `ppt/slides/slideN.xml` と、`presentation.xml` の `sldIdLst` だけ。
⚠ 画像は `ppt/media/` + そのスライドの `_rels`(docx と同じ形)。

⚠ **zip の書き手は既に在る**(`src/features/export/zip-writer.ts`)── docx が使っている。

## 7. 検証の型 ── docx で効いたものを踏襲し、**図は最初から**

| 何 | どう守るか |
|---|---|
| 🔴 **生成物を開いて中を見る** | `[Content_Types].xml` / `presentation.xml` の `sldIdLst` / 各 `_rels` を**名指しで読む**(「宣言されて・実在して・指されて」を 1 本で)── docx の #232 と同じ型 |
| 🔴 **切れ方** | 見出しと `+++` の組み合わせを**総当たり**で当て、スライドの枚数と題名を pin する |
| 🔴 **図の smoke**(最初から) | 図は unit では届かない ── 焼くのは `main.ts` が渡す産出器。**PKC2 が落とした当の穴** |
| 🔴 **速度とメモリ** | `tests/bench/` に 1 本。対照群は「同じノートを docx で書き出す」 |
| 変異試験 | 着地前に必ず。⚠ 切れ方の規則は**行を消す変異**が効く(枚数が変わる) |

## 8. 段取り(#187 に起票する)

| 段 | 中身 |
|---|---|
| ① | 骨格 14 部品 + 切れ方(見出しと `+++`)+ 題名と本文の文字だけ |
| ② | 箇条書き・表・強調(docx の写像を流用) |
| ③ | **画像と図**(添付・mermaid・グラフ)+ **図の smoke** |
| ④ | 枠の表と `<a:normAutofit/>`(見た目を整える) |
| ⑤ | 出す口(情報ペインに **PPT**)+ お知らせ + マニュアル |

⚠ ⑤ を最後に置く理由:**出口を先に作ると、中身が空でも「対応した」ことになる**。
docx は逆順で 1 度失敗しかけている。
