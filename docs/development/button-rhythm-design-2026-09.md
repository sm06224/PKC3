> 出どころ:user 指示 2026-09-21(こちらの解釈)。
> **「ボタンの横のサイズが一定ではない。つまり中身の名前にもリズムがない。視覚的にもでこぼこで統一感がなく、ストレス」**
> そして **「サブメニュー化は結構乱暴な解決策だとも理解している。良い案があるなら提案して欲しい」**。
>
> 裁定 2026-09-21:**推奨でよい。実装を進めてよい。**
> ⚠ ただし見え方が変わるので、**名前の全数表は入れる前にもう一度お見せする**(§4)。
>
> 台帳 #1029 / 続き先 #582(操作体系の再設計)・#1017(UI のトータルデザイン)。

## 1. 何が起きているか(実測 2026-09-21)

### 1.1 でこぼこの数

| 並び | ボタン | 名前の幅(全角換算) | 幅の種類 |
|---|---|---|---|
| 編集の帯(`BAR_FORMAT_OPS`) | 15 | **2 〜 14** | 9 |
| 右の列(ノートの操作) | 17 | **3 〜 28** | **17** |

⚠ 右の列は **17 個のボタンが 17 通りの幅**を持っている ── 同じ幅のものが 1 組も無い。

### 1.2 原因は CSS ではなく名前である

`src/styles/app.css` は **「語より細くしない」**(`min-width: max-content`)と決めている。つまり

> **ボタンの幅 = 名前の幅**

高さは `--row-h`(26px)で全部固定されているのに、**横だけが名前の長さの写し**になる。
だから名前の字数がバラバラだと、そのまま右端がガタつく。

🔑 **この規則は事故の後始末であり、戻してはいけない** ── 2026-08-27 に実機で
「**+ ノート**」が器 43px に対し名前 55px で **「+ ノ」に切れていた**(1024px では 28px)。
`min-width: max-content` を入れて切れは **8/8 → 0/8**、段数はどの幅でも増えなかった。
⚠ **固定幅に戻すと、この事故が戻る。**

### 1.3 名前に拍子が無い(同じ列に 4 つの作り方が混在)

| 作り方 | 実例 |
|---|---|
| 名詞 1 語 | 履歴 / 削除 / 添付 / 録音 |
| 動詞(辞書形) | 移す / 書き戻す / 並べ替える |
| 動詞(〜する) | ここから編集する / 時間を計る |
| 指示語つきの文 | **この**スタックを載せる / **この中に**新しいノートを作る |

表記も混在 ── 英語のまま(Word / PDF / PowerPoint)、括弧つき(バックアップ**(このノート)**)、三点リーダつき(移す**…**)。
⚠ **長さが意味と対応していない**(長い名前 = 重い操作でも、よく使う操作でもない)ので、長さを手がかりにできず毎回読む。

### 1.4 既に揃っている物(壊さない)

| | 状態 |
|---|---|
| 高さ | 🟢 **26px に統一済み**(触る端末は 34px)。例外は下の 2 件だけ |
| 字の大きさ | 🟢 **3 段に統一済み**(2026-09-05 #722。直す前は 5 種が混在していた) |
| 主の操作の目印 | 🟢 **1 つの面に 1 つだけ濃くする**機構が在る(`markPrimary`) |

### 1.5 いま壊れている物(見た目の選択ではなく、付け忘れと基準割れ)

| 何が起きているか | 実測 |
|---|---|
| 🔴 **「今日」に絵が付いていない** | 絵の名前を取り違えて呼んでおり、その名前は一覧に無い → 無地。検査も無い |
| 🔴 **「時間を計る」「構成をコピー」も無地** | 一覧に未登録。同じ並びの他のボタンには絵が在るので**混ざって見える** |
| 🔴 **画面下の「開く」「元に戻す」が 18px** | 他は 26px。指で押せる下限(24px)を**この 2 つだけ**下回る |
| 絵の被覆 | 登録 **46** に対し、押せる操作は約 **150** ── 3 個に 1 個しか絵が無い |

## 2. 直し方 ── 4 つの手を、効く順に

### 2.1 【手 1】見出しに動詞を持たせ、ボタンを名詞にする(いちばん効く)

いまボタンが長いのは、**1 個ずつが自分で全部を説明しようとしている**からである。
**塊の見出しが動詞を引き受ければ、ボタンは名詞 1 語で足りる。**
名詞は短く、字数が揃うので、**幅は放っておいても揃う**(§1.2 のとおり幅は名前の写しだから)。

**名前の規則(案)**

| # | 規則 | 理由 |
|---|---|---|
| 1 | **名前は全角 6 字(12 桁)以内**。超える説明は `title` へ逃がす | 12 桁は「バックアップ」が収まる長さ。これを上限にすると段が 2 つで済む |
| 2 | **1 つの塊の中では品詞を揃える**(名詞なら全部名詞) | 拍子は「長さ」だけでなく「形」でも出る |
| 3 | **指示語を書かない**(「この」「その」)── 対象は面が決めている | 右の列は「選んだノートに効く」ことが確定している |
| 4 | **括弧で対象を補わない**(バックアップ(このノート))── 塊の見出しが言う | 括弧は字数を食い、拍子を崩す |
| 5 | **「…」は「押すと次に選ぶ」の印としてだけ使う**(移す… / 目印を選ぶ…) | 意味のある記号にすれば拍子の一部になる |
| 6 | **製品名は英語のまま**(Word / PowerPoint / PDF / Markdown / HTML) | 既に決まっている(`STANDARD_TERMS`) |

### 2.2 【手 2】幅は「段」で受ける(固定幅にはしない)

名前を揃えても端数は出る。そこで **下限だけ**を 2 段で与える:

| 段 | 下限 | 収まる名前 |
|---|---|---|
| **短** | 全角 3 字ぶん | 履歴 / 削除 / 参照 / 添付 / 今日 |
| **長** | 全角 6 字ぶん | バックアップ / 別ウィンドウ / 名前を変える |

🔑 **下限だけを決め、名前が長ければ伸びる** ── だから §1.2 の事故(字が切れる)は起きない。
⚠ 段を 3 つ以上にしない(3 つ目を作ると、また「どれに入れるか」の判断が毎回生える)。

### 2.3 【手 3】塊は「線」ではなく「間」で切る

区切り線を引くと、**無彩色の地に線が増える**(思想③「地は無彩色、色は情報にだけ」)。
代わりに**間(すき間)の大きさを 2 段**にする ── 塊の中は詰め、塊の間だけ空ける。
部品も色も増やさずに拍子が出る。

⚠ いま左の列の下だけが区切り線を持っている(`collection-bar`)。**そこも間に揃える**か、
**線を正式な作法にする**かは、どちらかに倒す(混在をやめる)。→ 推薦は**間**。

### 2.4 【手 4】絵の混在をやめる

**1 つの並びの中では、全部に絵を付けるか、全部字だけにするか**のどちらかにする。
⚠ 全部に付けると幅が増えるので、**8 幅で測ってから**決める(過去にタブと左の列で
「絵を付けたら入り切らず段が増えた」実測がある ── 544px → 362px で段が 3 → 2 に戻った)。

## 3. サブメニューの使い所(user の案への回答)

**乱暴になるかどうかは中身で決まる。**

| ✅ 入れてよい | ❌ 入れてはいけない |
|---|---|
| **押した後にどのみちもう一段選ぶ物**(図の種類 / 日付 / 雛形 ── 既にこの形が在る) | **よく押す物**(バックアップ / + ノート) |
| **同じ動詞の変種の束**(「書き出す」の 5 形式 ── 動詞は 1 つで形式だけ違う) | **緊急のときに押す物**(録音・画面録画を**止める**) |
| | **初めての人が探す物**(システム / ヘルプ) |
| | **戻り道**(‹ › / やめる) |

🔑 推薦は「**書き出す形式だけを束ねる**」。⚠ ただし **バックアップは束から出して外に残す**(いちばん押すため)。
⚠ 制約:PKC3 は**折りたたみ部品を使わない**と決めており検査で固定されているので、
サブメニューは「押すと下に出る」形を自前で作る = **部品が 1 つ増える**。
増やすなら、それに見合う所(= 変種の束)だけに絞る。

| | いま | 案 |
|---|---|---|

下限を 2 段で与えれば、**画面に出る幅は 2 通り**になり、右端に縦の線が 2 本立つ。

⚠ 「参照」「名前」「構成」のように**短くしすぎると意味が落ちる**ものは、
**見出しと `title` が支えているか**を 1 件ずつ画面で確かめる(⑤-2 と同じ作法)。

## 5. 壊れうる所と、そこに置く門(検査)

⚠ 直したことを**次の PR が崩さない**ように、手ごとに機械の門を置く。

| 手 | 門 |
|---|---|
| 1 名前 | **名前の幅の上限**(全角 6 字)を全数で pin。超えたら落ちる。⚠ 製品名は除外リストで名指し |
| 2 幅の段 | **CSS に現れるボタンの幅の段が 2 つだけ**であることを走査して pin |
| 3 間 | **1 つの帯に区切り線と間が混在しない**ことを pin |
| 4 絵 | **同じ並びのボタンは、全部に絵が在るか、全部無いか**を pin(いまの「一部だけ」を落とす) |
| ── | **押し所は 24px 以上**を全数で pin(いまの 18px 2 件を落とす) |

⚠ 門は「**代替物で満たせない条件**」で書く(CLAUDE.md §1)── たとえば手 4 を
「絵の登録が N 件以上」で書くと、**並びが混在していても緑**になる。見るのは**並びごとの揃い**である。

## 7. これが分かったら覆る

- **「書き出す」系を毎日 2 つ以上押している** → §3 の束ね(段 E)は取り下げる
- **名前を短くしたら意味が取れなくなった**(user の実機) → 手 1 の字数上限を 8 字へ緩め、段を 3 つにする
- **絵を全部に付けたら 8 幅のどれかで段が増えた** → 手 4 は「全部字だけ」へ倒す
