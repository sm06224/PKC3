### 2.3 🔴 だから境目の規則を「px」ではなく「**本文の取り分**」で書く(推薦)

いまの境目は **A〜F の 6 分類・20 個以上の値**に散っており、軸も **窓の幅 / 器の幅**が
混ざっている(§2.1 の逆転)。⚠ これを 1 つずつ調律しても、**次に面が 1 つ増えた日に
また崩れる** ── 崩れ方が「残り物が本文」だからである。

🔑 **提案:境目は「本文が確保できる面積」で決める。**

| いまの規則 | 提案 |
|---|---|
| 脇の面が `30vh` / `220px` を**取る** | 脇の面は**残りを分ける**(本文が先に取る) |

1. **#588** ── 本文が 55px にならないので、重なりが**起きる余地ごと消える**
   (issue の A/B/C は**どれも要らなくなる**)

## 4. 🔴 推薦(1 つ)

### 型:**「操作表は 1 つ。面はその射影であって、面は操作を所有しない」**

操作 1 件を 1 行で宣言する:

| 列 | 中身 |
|---|---|
| `id` | `data-pkc-action` と**同綴り**(= 実行の受け手と等値で pin できる) |
| `label` | **字の正本**(面ごとに別の字を書かない) |
| `scope` | **何に効くか** ── `app` / `collection` / `view` / `entry` / `selection` / `block` |
| `when` | いつ出るか(**閉じた union**。`folder` / `linked` のような既存の形) |
| `keys?` | 鍵 |

**落ちてくる規則(この型を選べば、以下は発明ではなく導出である)**:

1. 🔴 **置き場は `scope` が決める。頻度は決めない。**
   頻度が決めてよいのは**面の中の順位だけ**。
   ⚠ いま `commands.ts` は「押す頻度」で左帯と設定を分けており(#239)、**これは軸違い**である
   ── 同じ `collection` の物が 2 つの面に分かれている
2. 🔴 **パレットは既定 ON、他の面は opt-in**(VS Code)。
   「すべての操作は名前で呼べる」が**規律ではなくフィールドの初期値**になる
3. 🔴 **畳めるペインが唯一の入口になってはならない**
   ── 🔴 **訂正(2026-08-30)。「規則 2 を入れると自動的に満たされる」は成り立たない。**
   ⚠ **パレットを開くボタンは、畳める左ペインの中に在る**
   (`shell.ts:514` を `collectionBar` に足し、`:549` が `sidebar` に append。
   `app.css:164` が畳んだ `sidebar` を `display: none` にする)。
   実測(2026-08-30、main `8a1b5b2` を焼いて実ブラウザ。ノートを 1 件開いた状態):

   | 窓 | 一覧を戻す口 | **パレットを開く** | 掴む帯 |
   |---|---|---|---|
   | 480×844 畳まず | 0 | 🟢 1 | 1(追記欄) |
   | 🔴 480×844 一覧を畳んだ | 🔴 **0** | 🔴 **0** | 1(追記欄のみ) |
   | 1280×900 畳まず | 🟢 1 | 🟢 1 | 3 |
   | 1280×900 一覧を畳んだ | 🟢 1 | 🔴 **0** | 3 |

   ⚠ **初稿の「押せるボタンが 22 → 0 個」は範囲が広すぎた**(画面全体が 0 になると読める)。
   実際は 480px で畳んでも**編集の帯など 28 個は残る** ── 0 になるのは
   **一覧を戻す口とパレット**である。🔑 `22 → 0` が指していたのは
   **左ペインの中のボタン 29 個のうち押せた 22 個**(#609 の表)であって、画面全体ではない。
   ⚠ **計器の名前を、計器が見ている範囲より広く書かない**(CLAUDE.md §4)。
   🔑 計器は `scripts/pane-escape-probe.mjs`(対照群 = 畳む前を先に測る。
   ⚠ ノートを 1 件も作らずに測ると追記欄の帯が出ないので、probe が先に 1 件作る)。

   🔴 **そして 1280px でもパレットは 0 になる** ── この誤りは狭い窓に限らない。
   広い窓では戻す口(掴む帯)が残るので**行き止まりにはならない**が、
   **「名前で呼ぶ」道は全幅で 1 つの面の持ち物**である。
   ⚠ user 指示「**マウスだけで完結し、キーボードは近道**」に正面から当たる
   ── 戻す手は `Alt+[` だけで、**畳んだ状態は保存されるので読み込み直しても戻らない**。
   🔑 Apple も同じことを戒めている(R6):
   「**Avoid using the menu bar as a catch-all location for functionality that
   doesn't fit in elsewhere.**」── **床は catch-all ではない。**
   ⚠ だから規則 3 は**規則 2 の系ではなく、独立した要件**である
   (パレットの口を畳めない所へ出すこと ── **画面が変わるので #604 へ設問を出した**)。
   🔑 **「畳んだら操作はどこへ行くのか」の答えは「どこへも行かない。最初からパレットに在った」**
4. **文脈は行を足すだけ。既存の順位を動かさず、現在地も移さない**(Office)
5. 🔴 **`scope` を持つ面は空にならない。次に大きい `scope` へ落ちる**(Figma)──
   情報ペインは選択が無いとき `collection` を出す(件数 / タグ / 取り込む / バックアップ / 最近)。
   ⚠ いまは「左の一覧から選ぶと、ここに情報が出ます。」という**死んだ 1 文**が常設の幅を占めている
6. **ボタンは自分の名前と鍵を名乗る**(Emacs のエコー)── 機構は `shortcut-hint.ts` に既に在る。被覆 **7/30**

### 4.1 ⚠ 「パレット中心」は user 指示と衝突しないか

user 指示 2026-08-03「**マウスだけで完結し、キーボードは近道**」──

**衝突しない。ただし明記が要る**:
🔑 **パレットは「保証」であって「主動線」ではない。**
主動線は**空間的なまま**(ペイン・帯・右クリック)で、パレットは
**①どの操作にも必ず 1 つは入口がある ②畳んでも消えない**を保証する**床**である。
⚠ PKC3 のパレットは既に**マウスで開ける**(`shell.ts:514` に「操作を探す」ボタンが在る)ので、
キーボード必須にはならない。

### 4.2 🔴 「動的と静的の導線をどう置くか」への答え(user の問い)

> user 指示 2026-08-29:「**いまの設計を度外視して動的と静的の導線をどうおくのか**」

⚠ いまの PKC3 には**この区別が 1 つも無い** ── 操作は「どの面に書いたか」で決まっており、
**動的(いまの状況で変わる)か静的(いつでも同じ)か**は誰も宣言していない。

🔑 **§4 の表に既に答えが在る** ── `scope` と `when` の**組**がそれである:

| | 静的な導線 | 動的な導線 |
|---|---|---|
| 定義 | `when` を持たない(= 常に出る) | `when` を持つ(= 状況で出入りする) |
| 例 | 取り込む / 設定 / ヘルプ / パレット | 「フォルダを開く」(`folder`)/「関係を外す」(`linked`) |
| 置き場 | 🔑 **場所が動かない**(同じ物は常に同じ場所) | 🔑 **行を足すだけ**(既存の順位を動かさない) |
| 畳めるか | 🔴 **畳める面を唯一の入口にしない**(規則 3) | 畳んでよい(状況が消えれば操作も消える) |

🔴 **ここが「意識の固定」の実体である**(user の言葉):

> 「**ユーザーの意識の固定とペインのハイドをした場合の復帰方法や操作体系の一貫性が必要だ**」

🔑 **意識が固定されるのは「静的な導線が動かない」ときだけである。**
⚠ いまは静的な物(パレット・取り込む・設定)が**畳める面の中**に在るので、
**畳んだ瞬間に「いつもの場所」が消える** ── 意識の固定が原理的に成立しない。

⚠ **逆も要る**:動的な導線を**静的な場所に据え置く**と、押せない物が常設される
(この repo の作法「押せない物を黙って出さない」に反する)。
🔑 だから **`when` を持つものは面から出入りしてよく、持たないものは動いてはいけない**。

### 4.3 🔴 「畳んだときの復帰方法」への答え

> 「**ペインのハイドをした場合の復帰方法**」

いまの実測(#609):畳める 3 面のうち **追記欄だけ**が鍵もパレットも持っていなかった
(2026-08-30 に埋めた)。⚠ しかし**より深い穴**が残っている ──
**畳んだ面の中にしか入口が無い操作が 58 種**あり、両側を畳むと**ノートへの操作が全部消える**。

🔑 §4 の型からは、復帰方法も**導出される**:

1. **静的な導線は畳めない場所に 1 つ持つ**(規則 3)── これが「戻る道」の床である
2. **畳んだことは言う**(段組み / 横並べ枠の既存の前例)
   ── ⚠ ただし**知らせは次の操作で上書きされる**ので(#584 で実測)、
   **知らせに操作を載せるなら、知らせ自身が留まる必要がある**
3. **畳む操作は必ず対で持つ**(user 指示 2026-08-23「片道の操作を作らない」)
   ── 掴む帯 / 鍵 / パレットの **3 つ揃い**が既定

⚠ 3 の「3 つ揃い」は**いま揃っていない面がある**(追記欄は 2026-08-30 に揃えた)。
🔑 **揃っているかは機械的に検められる** ── §6 の R7 に pin の形を書いた。

### 4.4 ⚠ この推薦が**やらない**こと

- **ボタンを減らさない。** user 指示 2026-08-07「記法を減らすことは、user の動線を減らすこと」の同型
  ── 減らすのは**登記簿の数**であって、押せる場所ではない
- **配置を今すぐ変えない。** 登記簿を作り、いまの配置を**そこから配る**のが先
  (見え方が変わらないので、裁定を待たずに進められる部分がある ── §5 の段①)
