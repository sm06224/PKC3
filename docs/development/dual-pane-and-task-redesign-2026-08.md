### 2-1. 2 ペインファイラ ── 4 つの古典に共通する不変の形

1. **縦の積層順が固定**:道具は一覧の**上**、情報は一覧の**下**、操作キー行は**最下段**
2. **左右は対等・交換可能**。`Tab` で焦点が移り、コピー / 移動の相手は**常に反対側**
3. **名前列だけが可変幅で残りを食い、他は固定幅**(DC の実数:名前 250 / 拡張子 50 /
   サイズ 70(**右寄せ**)/ 日付 140(**右寄せ**)/ 属性 100)
4. 🔴 **「カーソル(1 行)」と「印(複数選択)」は別概念**。色は
   **通常 / 印 / カーソル / 印+カーソル** の **4 状態**要る(TC の見本ラベル・FAR のパレット・
   DC の描画分岐が完全に一致)
5. **印は文字色で出す**。背景の塗り替えは既定ではない(FAR = 青地に黄文字 /
   DC の `UseInvertedSelection` は既定 false)
6. 🔴 **焦点はペイン上端の見出し帯(パス)の色**で示す。枠線でも全体の明暗でもない
7. **ペインごとに情報行**を持ち「**選択 N / 全 M 件**」と「選択サイズ / 全サイズ」を対で出す。
   ⚠ 印が 0 件なら**カーソル下のものの詳細**に切り替える(DC / FAR)
8. 🔴 **操作は最下段の全幅・等分割 1 行**。**F5 コピー / F6 移動 / F7 作成 / F8 削除**
   (+ F3 表示 / F4 編集)は 3 実装で**完全一致**
9. **ラベルは「キー + 語」を連結**して作る(Krusader は実際の割当から生成 ── **バー自体が
   チートシート**であり、user が鍵を変えると表示も追従する)
10. **すべての帯は個別に隠せる。隠せないのは一覧本体だけ**

### 2-2. 近代系が意図的に変えた点(2026 年に真似るべきか判断するための材料)

- F キー行を捨て、操作を**右クリック**へ寄せた(Dolphin / Nemo の既定ツールバーに
  コピー・移動・削除・新規のボタンは**1 つも無い**)
- 2 ペインを**既定 OFF のトグル**へ降ろした(3 つとも)
- 🔴 **Nautilus は機能ごと削除**(commit `b8d5b4a`)。理由は「OS に左右並べがある」
  「タブとの組合せが過剰」「ファイル選択ダイアログと不整合」「**タッチで使えない**」
- 非焦点ペインは**カーソルを消す**のではなく**面ごと沈める**
  (Dolphin = 背景 alpha 150 / Files = アクティブ側を Z=32 持ち上げて影)
- **日時が相対表記へ倒れた**(Dolphin 既定 relative / Files は **7 日を超えたら絶対**)
- **行が高くなった**(muCommander ≈ 18px に対し **Files 既定 36px**)。
  ⚠ ただし Files は **5 段階(28/36/40/44/48)で選ばせる**

### 2-4. ノートの中にタスクを書く系 ── 決定的な事実

🔑 **つまり PKC3 の現状(frontmatter `date:` = ノートの日付 / 本文 `- [ ]` = 札)は主流と一致
している。ずれているのは「札に日付を書く手段が無い」ことだけ。**

⚠ そして**失敗談も揃って同じ方向を指している**:
- Obsidian Tasks の docs は **118 ページ / 745KB**。「Quick Reference」1 枚が 46KB
  ── **覚える量そのものが失敗**

- org 公式マニュアルが SCHEDULED と DEADLINE の使い分けを「**頻繁な誤解**」と明記
- 絵文字記法は **NBSP と異体字セレクタで黙って読まれなくなる**(2 件とも公式 docs の
  Limitations に載っている ── 「見た目は正しいのに読まれない」)
- Logseq はクエリを書かせるのをやめ、**Query Builder(GUI)**を後付けした

## 3. 設計 ── 2 ペインファイラを作り直す

> 同じ作法**にする(§1-4)。⚠ **近代系の「F キー行を捨てて右クリックへ」は採らない** ──
> PKC3 に**右クリックメニューは 1 つも無い**(`grep contextmenu src/` = 0 件)ので、

### 3-2. 採らないもの(理由つき)

- ❌ **右クリックメニュー**:PKC3 に 1 つも無い機構を、この作り直しで新設しない
  (足すなら別件。⚠ 近代系が F キー行を捨てられたのは**右クリックが在るから**である)
- ❌ **2 ペインを既定 OFF のトグルへ降ろす**:PKC3 は**既にタイルから開く**形なので、
  常時 2 ペインではない(近代系の変更は済んでいる)
- ❌ **Nautilus 型の「機能ごと削除」**:user 指示が「作り直せ」なので対象外。
  ⚠ ただし削除理由の 1 つ「**タッチで使えない**」は**残る弱点**として台帳に置く
- ❌ **相対日付**(「3 日前」):⚠ 左の一覧が `MM/DD` の絶対表記なので、**面ごとに
  日付の読み方が変わる**ほうが害が大きい。⚠ Files も **7 日を超えたら絶対**へ戻している
- ❌ **行の高さを増やす**:近代系は 36px へ倒れたが、user 指示は「**業務画面**・高密度」。
  いまの **26px を保つ**(⚠ Files が 5 段階で選ばせている形は、将来の設定として台帳へ)

### 3-3. キー(市井に合わせる)

| キー | すること | いま |
|---|---|---|
| `Tab` | 反対のペインへ | ✅ 在る(⚠ 行の上でだけ効く → **面のどこでも効く**へ) |
| `↑` `↓` | カーソルを送る | ✅ 在る(⚠ いまは印も一緒に動く → **カーソルだけ**動かす) |
| `Space` / `Insert` | **印をトグルして 1 行下へ** | 🔴 **無い**(FAR / DOpus が同型) |
| `Shift+↑↓` | 印を伸ばす | ✅ 在る |
| `Enter` | フォルダへ入る / ノートを開く | ✅ 在る |
| `Backspace` | 親へ | ✅ 在る |
| `F2` | 名前を変える | ✅ 在る |
| `F3` | 開く(読む) | 🔴 **無い** |
| `F5` | 写す(反対側へ) | 🔴 **無い** |
| `F6` | 移す(反対側へ) | 🔴 **無い** |
| `F7` | フォルダを作る | 🔴 **無い** |
| `F8` | ゴミ箱へ | ⚠ `Delete` は在る ── **F8 も足す**(表示と一致させる) |

🔑 **表示と割当は同じ表から作る**(Krusader 方式)── user が鍵を変えたら
操作行のラベルも追従する。⚠ **2 か所に書かない**(§7)。

## 4. 設計 ── カレンダーと「やること」の導線

> 🔑 指針:**記法は 1 つだけ増やす。集める面は既定で用意し、クエリ言語は作らない。
> 日付は必ずピッカー / 補完から入る。**

### 4-1. まず直す(見た目の破れ。§1-2 の K〜O)

- 曜日の列を**等幅**にする(`table-layout: fixed`)/ 月表示を**面いっぱい**に配る
- **今日に印**を付ける / 日付の数字を**リンクの青から降ろす**(地は無彩色)
- 予定は**押せる形**で出す

### 4-2. 🔴 「日付を付ける」を 0〜2 回に縮める

いまは**カレンダーの日を押す 1 経路だけ**で、しかも**その面からノートを選べない**
(= 実質できない)。市井は**作りながら 0 回**が既定 ── そこへ寄せる:

1. **本文に日付を書く口**(記法 1 つ):`@` を打つとその場に日付ピッカーが出て、
   選ぶと **`@2026-08-19`** が入る ── Obsidian Kanban の `date-trigger` と同型。
   🔑 **絵文字記法は採らない** ── 入力手段が無いと打てず、**NBSP と異体字セレクタで
   黙って読まれなくなる**実績が公式 docs に 2 件載っている
2. **読みは寛容に、書きは 1 つに**:`@2026-08-19` / `📅 2026-08-19` /
   `[due:: 2026-08-19]` を**全部読んで**、書き戻しは常に `@`。
   🔑 これは不可侵裁定「**記法を減らすことは user の動線を減らすこと**」と同じ向き
   (受け口を増やすのは動線を増やす)。⚠ そして Obsidian Tasks の #1891
   (形式を切り替えると片方を一切読まなくなる → **移行手段が無い**)を踏まない唯一の道
3. **ピッカーは相対の近道が先頭**:`今日 / 明日 / 今週末 / 来週` → その下に格子
4. **カレンダーの面にノートを選ぶ手段を置く**(いまの「先に選んでおけ」を捨てる)

### 4-3. 🔴 時間軸の面を持つ(市井の 6 つが全部持っている)

**やることの板**に列を足すのではなく、**束ね方**として持つ:
- **今日**(期限が今日 + **期限切れも合流**。Apple の Today と同じ定義)
- **この先**(日付があるもの)
- **日付なし**

⚠ **クエリ言語は作らない**(Obsidian Tasks の 118 ページ / 46KB の Quick Reference が
その失敗)。⚠ Logseq に倣い**既定は折りたたみ**にして、邪魔にならない形で置く。

### 4-4. 🔴 完了の行き先を変える

いまの板は**完了列に打ち消し線で残り続ける** ── 調べた 6 つに**この形は 1 つも無い**。
**下へ落として畳む**(既定は非表示、1 操作で戻す)へ寄せる。

### 4-5. ⚠ これが分かったら覆る

1. ✅ **確かめた(2026-08-19)** ── **`@` は既に使われている**。
   `markdown-render.ts:1546` が携帯参照の札を **`@card` / `@card:<variant>`** として
   出しており、マニュアル §(`docs/manual.md:318`)にも載っている。
   🔑 **`@` の直後が数字なら日付、英字なら既存の札**、と読み分ければ共存はできる
   (`@2026-08-19` と `@card` は 1 文字目で割れる)が、⚠ **同じ記号に 2 つの意味**を
   持たせる判断になるので、実装 issue で**次の 3 案から選ぶ**:
   - (a) `@` を数字で読み分ける(打鍵が最短。⚠ 意味が 2 つ)
   - (b) **`/日付` のスラッシュコマンド**(Logseq 型。⚠ 打鍵は 1 つ増えるが記号は増えない)
   - (c) 既存の frontmatter だけに留め、**行の日付は入れない**
     (⚠ その場合 §2-4 の「タスクの日付は行に書く」という市井の全会一致に反する)
2. **user が「いつやるか」と「いつまでか」の両方を書きたいと言ったら** 4-2 は 2 本立てになる
   ── ⚠ その場合 org 公式が認めた「**頻繁な誤解**」を **UI の言葉で吸収**する必要がある
   (Logseq が repeater でやったように、**記号ではなく名前で選ばせる**)
3. **板の札が「やること行」ではなくノートを載せる方向へ動いたら** 4-3 の束ね方は変わる

## 5. 変えない約束(作り直しても壊さないもの)

- **データの意味論**:居場所は relations、日付は frontmatter の `date`、
  やることは本文の `- [ ]` の行 ── **記法は 1 つも増やさない / 減らさない**
  (不可侵:記法を減らすことは user の動線を減らすこと)
- **中央は常にいま開いているノート**(探し方を変えても中央は動かない)
- **印(複数選択)は面ごとに持つ**(左の一覧と 2 ペインは別勘定)
- **組み込みタイルから開く**(帯に切替を戻さない ── #241 の訂正で確立した形)
