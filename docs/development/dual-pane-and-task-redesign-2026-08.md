### 1-4. 🔴 いちばん重い発見 ── **同じアプリの中で作法が割れている**

左の列の「フォルダ」タブ(`filer.ts`)と、2 ペイン(`dual-filer.ts`)は
**同じ仕事(場所を辿って整理する)をする 2 つの面**である。ところが:

| | 左の「フォルダ」タブ | 2 ペイン |
|---|---|---|
| 列見出し | **在る**(`名前` / `更新日`。`filer.ts:407-419` の `<thead>`) | **無い**(`dual-filer.ts` に `thead` が 1 つも無い) |
| 種別の出し方 | **行頭の図案**(P9 段③ で列をやめた) | **文字の列**(「フォルダ」「ノート」「ログ」) |
| 操作の置き場 | **面の下端に横並び**(上へ / 下へ / ゴミ箱) | **左右ペインの間に縦積み** |
| 現在行 | 薄い帯で示す | 示さない |

🔑 **つまり「独りよがり」の正体は、市井から外れていることに加えて、
自分のアプリの中でも外れていること**である。⚠ P9 段③ で
「種別の列はやめて行頭の図案にする」と**一度決めた**のに、2 ペインだけが
古い形のまま残っている(CLAUDE.md「片側を直したら、対称の反対側を必ず疑う」)。

⚠ だから作り直しの指針は 2 本になる:
1. **市井の 2 ペインファイラの当たり前**へ寄せる(調査中)
2. **左の「フォルダ」タブと同じ作法**にする(列見出し・行頭の図案・下端の操作)

## 3. 変えない約束(作り直しても壊さないもの)

- **データの意味論**:居場所は relations、日付は frontmatter の `date`、
  やることは本文の `- [ ]` の行 ── **記法は 1 つも増やさない / 減らさない**
  (不可侵:記法を減らすことは user の動線を減らすこと)
- **中央は常にいま開いているノート**(探し方を変えても中央は動かない)
- **印(複数選択)は面ごとに持つ**(左の一覧と 2 ペインは別勘定)
- **組み込みタイルから開く**(帯に切替を戻さない ── #241 の訂正で確立した形)
