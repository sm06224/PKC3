## 1. user の言葉

> **ローカルでホストする仕組みと一緒にインストーラーをPKC3自身で配布できるように
> 組み込みアプリに動線を追加しましょう**

## 2. 調べて分かったこと(2026-08-29、main `c5e4104`)── **見当が 2 つ外れていた**

### 🔴 ①「分離ヘッダを出せるサーバが要る」は**誤り**

PKC3 の `crossOriginIsolated` は **Service Worker 自身が COOP/COEP を被せる**作りである
(GitHub Pages がヘッダを設定できないため):

> `src/adapter/platform/sw/sw-source.ts` /  `coi-headers.ts` / `coi-reload.ts`

`http://localhost` は secure context なので **SW が登録でき、分離もそこから生まれる**。
🔑 要るのは**ただの静的ファイルサーバ**である。

⚠ ただし **初回は 1 回読み直す**(`coi-reload.ts`)── SW は自分を登録した文書を
制御していないため。これは Pages と同じ挙動なので、新しく作る物は無い。

### 🔴 ②「配る中身を組み立てる必要がある」も**誤り**

`sw.js` は生成物の**根**に在り、登録も相対(`main.ts:2896` の `./sw.js`)。
つまり **`dist/` を document root に置くだけ**でよい。

### 🔴 ③ 起動スクリプトの前提が **2 OS で外れていた**

| OS | #532 本文の見当 | 実際 |
|---|---|---|
| Windows | PowerShell(標準) | ✅ 合っている |
| macOS | `python3`(CLT が入っていれば) | 🔴 **既定では入っていない** |
| Linux | `python3` / `bash` はほぼ在る | 🟡 最小構成には無いことがある |

🔴 **いちばん厄介なのは「在るように見えて走らない」こと**:

- **macOS**: `/usr/bin/python3` は **CLT を入れさせるための殻**。走らせると導入ダイアログ
- **Windows 11**: `python3` は **Microsoft Store へ誘導する App Execution Alias の殻**。
  走らせると案内を出して**非ゼロで終わる**

⚠ つまり **`command -v python3` は両方で成功する。**
🔑 **有無は「在るか」ではなく `python3 -c ''` を実際に走らせた終了コードで判定する。**
⚠ ここを間違えると「起動しました」と出て**何も起きない**(いちばん見分けにくい壊れ方)。

## 3. 🔴 いちばん重い設計点 ── **origin を固定する**

`http://localhost:8080` と `http://127.0.0.1:8080` は**別 origin**。
OPFS も IndexedDB も origin に紐づくので、**綴りやポートが変わると
user のノートは消えたように見える**。

🔑 **だから「空いているポートを自動で探す」を実装してはいけない。**
埋まっていたら**止めて理由を出す**(「8080 が使われています。
先に使っている物を止めるか、`--port` で決め打ちしてください」)。

⚠ そして **user に origin を見せる**:起動時に
「**この住所でだけ、あなたのノートが見えます: http://localhost:8080**」と出す。

## 4. 段の切り方

### 段 A: 「入れる」動線(サーバ 0 本。**いますぐ効く**)

PKC3 は既に PWA(`manifest.webmanifest` + SW)なので、ブラウザの「インストール」で
**独立した窓**になり、**オフラインでも開く**。
⚠ 置き場は変わらないので「自分のパソコンでホストする」ではない ──
**段 B の前に、これが在ることを user に伝える**(#491 の教訓:
在る物を伝えないと、user は使えないまま)。

### 段 B: 一式を落とす(`dist/` + 起動スクリプト)

組み込みアプリに「**自分のパソコンで動かす**」を置き、押すと **zip 1 個**が落ちる:

```
pkc3-selfhost/
  site/            ← dist/ そのまま
  start-mac-linux.sh
  start-windows.cmd
  はじめに.txt      ← origin の注意を含む
```

- `start-windows.cmd` … `powershell -ExecutionPolicy Bypass -File start.ps1`
  (⚠ 実行ポリシーの壁を `.cmd` 側で回避する ── user に設定を触らせない)
  `start.ps1` は `System.Net.HttpListener` で静的配信
- `start-mac-linux.sh` … **実際に走らせて**使える物を選ぶ
  (`python3 -c ''` → `python -c ''` → `node -e ''`)。
  ⚠ **1 つも無ければ、何を入れればよいかを画面に出して止まる**

### 段 C: 更新の当て方(⚠ まだ設計していない)

落とした一式は**古くなる**。SW は自分の origin のキャッシュしか見ないので、
Pages 版のような自動更新は効かない ── 段 B の zip に**版**を書き、
アプリ内から「新しい一式を落とす」を出すのが素直だが、未検討。

  secure context ではないので **SW も OPFS も動かない**)
