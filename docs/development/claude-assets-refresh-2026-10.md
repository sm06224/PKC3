⚠ **消す物は無い。** 全文は `git log` に残るが、それは「読める」ではない ── 教訓は
`reference/` と `rules/` に**日付と issue 番号つきで**残す。縮むのは**毎回読む量**だけである。

## 6. 書き方の指針(C・D で書き直すときの作法。新しく書く物にも)

1. **型 → 1 行の見分け方 → 1 行の直し方 → 参照**。物語(何が起きたか)は参照 file へ
2. **禁止は目的で書く**(CLAUDE.md「戒めには何のための禁止かを書く」)── 対象で書くと際限なく広がる
3. **🔴 は「外すと壊れる」だけ**。⚠ は 1 節に 2 つまで。🔑 は要点 1 つ
4. **数字は pin が在る物だけ**(CLAUDE.md 2026-09-21)。日付と issue 番号は残す(検算の足場)
5. **「分からない」と書ける形にする**:判定不能 / 未検証 / 未測定 を結論と区別する欄を持つ
6. **本番運用を主語にする**:読む相手は配布先の user である ── 「test が緑」ではなく「user に何が届くか」で閉じる
7. **思考を縛らない**:手順を固定するのは**壊れやすい順序**(変異の戻し / merge 直後の branch / 焼きの順)だけ。他は「何を確かめれば足りるか」を書いて、やり方は委ねる

## 7. 覆る条件

- user 印の節を**動かす**判断が要る場面が出たら、止めて聞く(ここに書いた線を越える)
- rules の `paths:` が**読まれない**(`claude --debug` で載らない)なら、rules をやめて skill の `reference/` に寄せる
- C の後に、こちらの教訓を参照する test(`tests/repo-hygiene.test.ts` などが CLAUDE.md の §番号を docstring で指す)が**行き止まり**になる ── §番号は表に残すので壊れないはずだが、`grep -rn 'CLAUDE.md §' tests src` を C の検算に入れる
